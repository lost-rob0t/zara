* 1. Vision

Calm Console is one column, one input, one stream. The window is a reading
surface first: a centered ~760px measure, generous vertical rhythm, and a
history that disappears into a summoned overlay instead of a permanent
sidebar. The Prolog ADE is the hidden depth: a right-anchored inspector
drawer that slides in over/next to the stream when asked (Ctrl+I or the
inspector button) and carries three quiet sections — a live query console
against the daemon's real engine with generation-fenced results, a KB facts
browser, and the current intent/task state. Nothing about Prolog is visible
until summoned; once summoned, everything is real. The feel is Linear/Things:
restraint as the feature, the engine one keystroke away.

Structural claims, verified in this worktree:

* 3. UI structure

** 3.1 Hierarchy

One window (=CopilotWindow=, objectName =zaraCopilot=) with exactly three
layers:

1. *Header* (quiet): conversation title (left), 8px status lamp + one status
   word (center-right, detail only in tooltip or on error), three text
   buttons (History, Inspector, Settings). No brand block, no provider label
   in the header row — provider/model stays in the status tooltip
   ([[file:zara/desktop/windows/quick.py][quick.py:471-479]] precedent).
2. *Stream*: one centered column, maximum reading measure **760px**, message
   spacing raised 6→12px. Chat bubbles keep =MessageWidget= and all gated
   objectNames (=zaraMessageBubble=, =messageRole=, =messageKind=), but the
   *activity* kind renders as a hairline row: 2px primary left tick, tool
   name + status word in =text_muted= mono — no bubble chrome. Assistant
   bubbles lose their left accent corner radius (16px uniform) so the column
   reads as a document, not a messenger transcript.
3. *Composer*: unchanged =ChatComposer= + =ComposerActionButton= inside
   =zaraComposerShell= (growth behavior is test-gated,
   [[file:t/test_adaptive_copilot.py][test_adaptive_copilot.py:207-220]]). Placeholder: "Ask Zara…".

meaningful; [[file:zara/desktop/theme.py][theme.py:641-645]]), anchored top-center over the stream, width

** 3.3 Inspector drawer (the ADE)

A right-anchored panel, width **400px**, toggled by =Inspector= / Ctrl+I.
Docked side-by-side in EXPANDED (chat column shrinks, composer stays full
width of the chat column); overlay above the stream in COMPACT (the quick
surface stays one column; the drawer is a summoned instrument, the window
does not reflow). Drawer state persists per presentation in QSettings,
exactly mirroring the existing per-presentation geometry keys
([[file:zara/desktop/windows/copilot.py][copilot.py:33-36]]). Toggling must not rebuild message widgets — the same
invariant =set_presentation= already honors
([[file:t/test_adaptive_copilot.py][test_adaptive_copilot.py:58-103]]).

Three stacked sections, hairline-separated, each collapsible, no tab bar:

Sections:

1. *Console* — one =QPlainTextEdit=-style goal input (mono, =?- = prefix in
   placeholder), result list beneath, one status word ("Ready", "Running…",
   "2 solutions", "Cancelled · late results will be discarded" — the exact
   honest-cancel copy already gated in
   [[file:t/test_desktop_settings_window.py][test_desktop_settings_window.py:247]]). History of the last 20 goals
   (KB limit [[file:.prolog/kb/desktop_prolog_ide.pl][desktop_prolog_ide.pl:23]]) via a quiet dropdown, as today

2. *KB facts* — two sub-lists. "Saved" lists =ManagedFactStore.list()= from

   =modules/desktop_ade.pl= (see §4.3). Never free-form browsing.

   read-only: pretty-printed =prolog_context_term=, active intent frame

   discourse entities. Sourced from =ConversationService= state +

** 3.4 Tokens, type, spacing

Zero new color tokens: drawer ground =panel_deep=, cards =panel=, borders
=line=, active query state =active=, errors =danger= on =danger_deep=, mono
text =text= ([[file:zara/desktop/theme.py][theme.py:142-160]]). Type: body stays Adwaita Sans 14px; goals,
results, fact terms and frame terms stay Hack Nerd Font Mono 12–13px
(existing families, [[file:zara/desktop/theme.py][theme.py:939-943]]). Spacing rhythm: 4/8/12/16/24 only.
Section headers are 11px mono uppercase =text_muted= (reuses the
=zaraMessageRole= vocabulary, [[file:zara/desktop/theme.py][theme.py:763-770]]).

Why it reads simple + modern: one axis of hierarchy (the stream), a single
accent color doing all state work (the lamp), no permanent panels, and the
ADE living behind a summonable surface rather than beside the chat.

* 4. Prolog ADE architecture

** 4.1 Process and thread model

- The desktop process *never imports pyswip*. All engine contact rides the
  existing seam: =CopilotWindow(bridge, conversations, prolog_query=callable)=
  where =callable = lambda goal, n: client.submit(RunPrologQuery(goal=goal,
  max_solutions=n))= — built once in =DesktopController= and handed to both
  the Copilot and the Settings factory, replacing the lambda duplicated at
  [[file:zara/desktop/controller.py][controller.py:55-62]]. With =prolog_query=None= (all current UI tests,
  fixtures) the drawer renders the honest "Runtime query unavailable" state,
  same as Settings ([[file:zara/desktop/windows/settings.py][settings.py:749-752]]).
- Submission happens on the Qt thread but performs no engine work; the future
  completes on a worker and re-enters the UI through a Qt signal — the exact
  =prolog_query_finished = Signal(int, object)= pattern Settings uses
  ([[file:zara/desktop/windows/settings.py][settings.py:257]], [[file:zara/desktop/windows/settings.py][settings.py:285]]), which satisfies =no_qt_thread_prolog=
  by construction and by gate test
  ([[file:t/test_desktop_settings_window.py][test_desktop_settings_window.py:204-231]]).
- One engine truth: queries execute on the daemon's engine behind
  =PrologEngine._runtime_lock= ([[file:zara/prolog_engine.py][prolog_engine.py:335-336]]). The UI holds no
  mirror of KB facts beyond rendered strings; every engine number on screen
  is the result of a query that just returned, or is labeled as saved-file
  state.

** 4.2 Query lifecycle (submit / fence / cancel / render)

Mirrors and generalizes the Settings console into a reusable
=QueryConsoleController= in the new =zara/desktop/inspector.py= (Settings
migrates onto it in phase 3; behavior-identical):

1. *Submit*: non-empty goal; client-side pre-validation replicating
   =RunPrologQuery.__post_init__= (≤4096 bytes, no NUL,
   =max_solutions=50= — the KB's =ui_requested_solutions=
   [[file:.prolog/kb/desktop_prolog_ide.pl][desktop_prolog_ide.pl:22]], within the wire cap
   [[file:zara/runtime/commands.py][commands.py:128-129]]); generation token =+1=; Run disabled, Cancel
   enabled, status "Running…" ([[file:zara/desktop/windows/settings.py][settings.py:896-925]] semantics).
2. *Fence*: the future's done callback emits =(generation, outcome)= over
   Qt; =_finish= drops anything with =generation != current= — stale and
   cancelled results can never render ([[file:zara/desktop/windows/settings.py][settings.py:935-937]]). The wire layer
   independently fences by =reply_to= request id
   ([[file:zara/zmq_transport.py][zmq_transport.py:2188-2202]]), so a receipt from a previous request can
   never be misattributed even across drawer/settings consoles.
3. *Cancel*: bumps the generation and flips the status copy; no engine-side
   interrupt exists in the protocol, and the UI does not pretend otherwise
   ([[file:zara/desktop/windows/settings.py][settings.py:927-933]]).
4. *Render*: =N solutions= / =false=; per-line 2,000 chars, cumulative
   64,000 chars with explicit truncation marker ([[file:zara/desktop/windows/settings.py][settings.py:950-962]] =
   KB =rendered_output_chars=). History deque capped at 20.
5. *Restart/teardown fence*: on =set_status= transitioning to
   =DISCONNECTED=/=ERROR=, or on the receipt of the =RestartRuntime=
   acknowledgment the controller already tracks ([[file:zara/desktop/controller.py][controller.py:246-260]]), the
   drawer bumps its generation and shows "Runtime restarting — results
   discarded".

** 4.3 Fact→UI projection

Prolog logic stays in Prolog. A new =modules/desktop_ade.pl= exposes
bounded, pure projection predicates; Python issues only these fixed goals:

#+BEGIN_EXAMPLE
desktop_ade:kb_module_summary(Module, Count)         % per loaded kb/ module
desktop_ade:fact_sample(Module, Term, Limit)         % bounded sample rows
desktop_ade:intent_catalog(Phrase, Intent, Arity)    % verb_intent/3 grouped
desktop_ade:wake_words(Words)                        % kb_config:wake_word/1
#+END_EXAMPLE

Each is called with =max_solutions=50= through =RunPrologQuery=. No
=consult=, no =assertz=, no =retract= ever originates from the drawer —
writes stay in the Settings pipeline with its allowlist + fresh-process
=swipl= validation ([[file:zara/desktop/prolog_studio.py][prolog_studio.py:270-353]]). Managed ("Saved") facts render
from =ManagedFactStore= file reads only.

** 4.4 Intents / tasks surfaces

- *Intents*: the Live state section reads the canonical projection
  (=dialogue_state.prolog_context_term=, =unresolved_questions=,
  =discourse_entities=) with no runtime traffic; frames decode via the
  existing typed mirror path if a frame view is needed
  ([[file:zara/prolog_engine.py][prolog_engine.py:486-538]] — server side, not desktop). The catalog query
  of §4.3 gives the static intent inventory.
- *Tasks*: long-horizon tasks are =RuntimeHost=-owned and
  =[tasks].enabled=-gated (wiki contract); there is no desktop command for
  them today. The design shows the conversation-level truth the desktop
  already owns (active turn, pending approval, clarifications) and adds a
  phase-2 =tasks.list= ZARA/1 message, admin-gated identically to
  =prolog.query=, before any task row is rendered. No mock rows.

* 6. Failure & recovery

- *Engine crash / daemon loss*: =RuntimeError= events reduce to
  =DISCONNECTED=/=ERROR= status ([[file:zara/desktop/controller.py][controller.py:287-301]]); the drawer's lamp section
  mirrors the header status, bumps its generation (§4.2.5), and the console
  shows the honest unavailable state. Recovery = RestartRuntime from tray or
  header ([[file:zara/desktop/controller.py][controller.py:246-260]]); the first new query after =IDLE= succeeds
  normally.
- *Stale/late results*: fenced at UI generation, wire =reply_to=, and
  projection generation — three independent fences, tested at
  [[file:t/test_desktop_settings_window.py][test_desktop_settings_window.py:234-249]] and re-tested for the drawer.
- *Barge-in during generation*: chat cancel (=CancelTurn=,
  [[file:zara/desktop/windows/quick.py][quick.py:308-323]]) and drawer queries are independent channels, but both
  serialize on the one engine; a long user goal can delay a turn (the lock is
  held until solutions drain, [[file:zara/prolog_engine.py][prolog_engine.py:329-333]]). The drawer therefore
  defaults to 50-solution goals and displays "Running…" so the user knows
  the engine is occupied; server-side inflight/backpressure limits bound the
  queue ([[file:zara/zmq_transport.py][zmq_transport.py:1316-1327]]).
- *Long queries*: cancel is fence-based; the goal byte cap (4096) and
  solution cap (50 requested / 100 hard) bound worst-case lock occupancy.
- *Restart*: receipts from before the restart carry stale generations and are
  discarded; history (20 goals) survives as pure UI text in QSettings scope
  of the session, not as engine state.
- *Drawer opened with no runtime* (=prolog_query=None= in tests/fixtures):
  "Runtime query unavailable", no buttons that pretend ([[file:zara/desktop/windows/settings.py][settings.py:749-752]]).

* 10. Rejected alternatives

1. *A separate ADE window* (dockable IDE-style second window). Loses on both
   lenses: it duplicates surfaces the way pre-#324 desktop had two copilots,
   which this repo deliberately collapsed into one renderer
   ([[file:zara/desktop/windows/copilot.py][copilot.py:39-40]] "One chat renderer"; [[file:zara/desktop/controller.py][controller.py:70-72]] "not a second
   renderer"); and it makes Prolog a destination instead of an instrument —
   context-switching away from the conversation the query explains.
2. *Tabbed inspector (Console | Facts | State).* A tab bar is chrome, needs
   persistent selected-tab state, and hides two of three surfaces on every
   glance. Stacked collapsible sections show the whole ADE in one column at
   400px with no state to remember.
3. *Full source-editing inside the drawer.* Editing is already solved with
   an allowlisted repository, atomic writes, fresh-process =swipl=
   validation, and diagnostics ([[file:zara/desktop/prolog_studio.py][prolog_studio.py:270-353]]) — duplicating an editor
   in the drawer forks the risk surface and invites unvalidated writes near
   the query path. The drawer is query/read-only by design; editing stays in
   Settings.

* 11. Risks

1. *Engine lock contention from curious users running heavy goals.* The lazy
   query holds the process-wide lock until drained ([[file:zara/prolog_engine.py][prolog_engine.py:329-333]]);
   a pathological goal stalls turns. *Mitigation:* 50-solution cap, 4096-byte
   goal cap, honest "Running…" + cancel (fence), server inflight backpressure
   ([[file:zara/zmq_transport.py][zmq_transport.py:1316-1327]]); phase-2 option: a server-side solution deadline
   behind the existing admin gate.
2. *Fixture/theme gate churn.* The screenshot matrix is exact-set and the
   stylesheet vocabulary is pinned by string asserts; a drawer mistake fails
   three suites at once. *Mitigation:* additive-only fixture states, keep
   objectNames/styles for gated selectors byte-identical, bump manifest
   schema deliberately, extend =test_desktop_theme= selector assertions in
   the same commit.
3. *History-palette migration regressing conversation flows.* Rename/bind/new
   flows are exercised through the palette today and are central to the
   copilot. *Mitigation:* palette reuses the same =history_list=, signals,
   and =ConversationService= calls — only geometry changes; the migrated
   overlay test asserts composer visibility and activation rebinding; the
   five untouched adaptive-copilot tests catch drift.
