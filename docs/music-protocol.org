#+title: Zara Music Wire Protocol
#+property: header-args :comments no

* Purpose

Zara Music reuses =ZARA/1= for authenticated control and event traffic. It does
*not* turn ZARA/1 into an audio transport. Navidrome/OpenSubsonic HTTP remains
the media plane for audio, artwork, downloads, and range requests.

The control plane is deliberately bounded for libraries that can contain
millions of files:

- clients submit selectors rather than path lists;
- results are snapshot-pinned and cursor-paged;
- page size is capped at 500 items;
- long operations are durable jobs with progress sequence numbers;
- filesystem mutations are always =plan -> apply=;
- =expected_generation= fences stale plans;
- idempotency keys make retries explicit;
- Android and desktop consume the same message contract.

The human-readable Org document is canonical for the generated Prolog facts and
machine schema below. Run:

#+begin_src sh
python scripts/tangle-music-protocol.py
python scripts/tangle-music-protocol.py --check
#+end_src

Only the two explicit targets in this document are accepted by the tangler.

* Control versus media plane

#+begin_example
Android / desktop / Zara plugin
              |
        ZARA/1 + CURVE
              |
       Zara Music service
        /            \
   Prolog policy     durable jobs
        |                 |
   explanations      filesystem workers
              \
         Navidrome plugin
              |
      Navidrome/OpenSubsonic
              |
        HTTP media stream
#+end_example

A client never receives authority merely because it knows a path, job id,
snapshot id, or plan id. Principal identity comes from the existing ZARA/1
authenticated session.

* Query contract

=music.library.query= carries:

- =library_id=
- =selector=
- =page_size= in =1..500=
- optional opaque =cursor=

A selector can pin =snapshot_id=, contain one bounded =where= tree, and contain
up to four sort keys. The predicate tree has a maximum depth of 8 and maximum
64 clauses. The wire representation is JSON data, never executable Prolog
source. The server translates the validated AST into its internal Prolog/query
representation.

=music.library.page= returns a stable =snapshot_id= and numeric =generation=.
A later page uses the opaque cursor. The server may expire a cursor; it must
never reinterpret a cursor against a different snapshot.

* Job contract

=music.job.submit= supports these operations:

| Operation | Meaning | Mutates media filesystem directly? |
|-----------+---------+------------------------------------|
| scan | inventory/change discovery | no |
| hash | content hashing | no |
| fingerprint | acoustic fingerprint generation | no |
| metadata | metadata/knowledge candidate acquisition | no |
| dedupe | duplicate candidate analysis | no |
| tag | proposed tag edits | only after plan/apply |
| move | proposed path moves | only after plan/apply |
| quarantine | proposed recoverable quarantine | only after plan/apply |

=tag=, =move=, and =quarantine= may only be submitted with =mode= set to
=plan=. A successful planner emits =music.plan.ready=. Applying that plan
requires =music.plan.apply= with the exact expected library generation.
Generation mismatch fails closed instead of applying stale path decisions.

Jobs are resumable server objects. Progress events carry monotonically
increasing =seq=/=last_seq= values so reconnecting clients can obtain current
status without replaying an unbounded event history.

* Failure and safety invariants

- No music-domain message accepts binary payload frames.
- No music-domain command accepts conversation/turn/audio-stream correlation.
- The selector AST is finite and allowlisted.
- Error codes and public error strings are bounded and sanitized.
- LLM output never bypasses plan/apply, generation fences, or Prolog policy.
- Destructive file deletion is not a protocol primitive. Quarantine/undo is
  implemented by the server-side filesystem engine.
- Paths are result data, not capabilities.
- OpenSubsonic credentials/media URLs do not become Prolog facts or ZARA logs.
