* Zara

Zara is the Linux assistant I keep turning into a real program instead of a pile of demos.

It listens, transcribes speech, routes deterministic commands through SWI-Prolog, falls back to a LangGraph agent for open-ended work, calls native and MCP tools, remembers things, manages todos, speaks replies, and exposes the same runtime through a native Qt desktop application. It also has desktop pets, because apparently a normal status indicator was not enough.

The unusual split is intentional. I do not want an LLM deciding every little thing just because it can produce convincing text. If Zara can resolve an action symbolically, Prolog gets the first shot. If the request is genuinely conversational or needs tools and model reasoning, the agent handles it.

#+begin_quote
This is still a learning project. A lot of Zara was bootstrapped with LLMs, and part of the point is going back through that code, understanding it, cutting out nonsense, and replacing weak language plumbing with things I can explain.

So: useful software, active experiment, bad choice of reference implementation for your bank.
#+end_quote

Linux and Nix are the real target. Other platforms occasionally work because Qt and Python are portable, not because I am pretending they receive equal testing.

** What works now

Zara is several interfaces over one growing runtime, not seven unrelated assistants wearing the same name.

*** Voice

- Long-running wake mode with =zara=, =hey zara= and related wake spellings.
- Silero VAD for speech boundaries, pre-roll, trailing silence, no-speech timeouts, and bounded utterances.
- Immediate acknowledgement audio before slower work starts.
- Speech-to-text backends including faster-whisper, whisper.cpp, OpenAI Whisper, sherpa-onnx families, OpenAI transcription, and Groq transcription.
- Dictation mode with ordered commits, parallel transcription, and configurable stop phrases.
- TTS through local Piper/espeak, ElevenLabs, Edge TTS, or Qwen3 TTS.
- Barge-in and cancellation so new speech can stop active playback.
- Speaker-echo protection so post-TTS capture does not immediately feed Zara its own voice.
- Structured latency traces that deliberately exclude transcript text, prompts, credentials, and audio.

Read [[file:docs/voice.org][the voice overview]] and [[file:docs/STT.md][the STT backend guide]].

*** Prolog command path

SWI-Prolog handles the deterministic side of Zara: intent resolution, command routing, application mappings, search, dictation control, timer parsing, state-aware control, and related symbolic rules.

The Python boundary is deliberately thin. =zara/prolog_engine.py= serializes access to the process-wide SWI runtime and keeps user-derived terms behind constrained serializers. The command loop emits structured acknowledgement/result events instead of pretending every handler succeeded.

Not every recognized verb has a completed side effect. For example, alarms are explicitly unsupported today, and several old media/device verbs are still recognition/stub territory. [[file:docs/commands.org][commands.org]] is the exact truth table instead of making the README perform interpretive dance around =kb/intents.pl=.

Timer parsing knows seconds, minutes, and hours. That is timer normalization, not a general unit-conversion feature.

The built-in knowledge base lives under =kb/= and executable Prolog logic under =modules/=. User overrides are separate from Python TOML configuration; see [[file:docs/config/prolog.org][the literate Prolog config]] and [[file:docs/features.org][the feature map]].

Plain Prolog is part of Zara. Prolog-RLM is not a Zara runtime backend.

*** Agent, tools, memory, and todos

Open-ended conversation runs through the LangGraph backend. The currently supported LLM providers are OpenAI, Anthropic, and Ollama.

The built-in tool set includes:

- calculator and current time;
- controlled Prolog queries;
- memory =remember=, =recall=, =memory_list=, and =forget=;
- todo capture, listing, editing, completion, reopening, search, scheduling, and export;
- optional sandboxed-by-root file reads/writes;
- NOAA weather when configured;
- dynamically discovered MCP tools.

Memory can persist through ChromaDB with ONNX, Ollama, or sentence-transformer embeddings. If persistent memory cannot initialize, Zara reports that state and falls back to process-local memory rather than quietly dying.

Todos use Zara's SQLite storage and support statuses, priorities, tags, schedules, durations, recurrence rules, conflict checking, and Org/Markdown export. More detail lives in [[file:docs/features.org][the feature map]] and [[file:docs/configuration.org][configuration guide]].

*** Native desktop

=zara-desktop= and =zara --desktop= launch the PySide6 desktop shell.

The shipped desktop path has:

- one process-owned =QApplication= and desktop controller;
- a tray when the platform provides one, with a reachable full window when it does not;
- Quick Copilot and Full Chat backed by the same durable conversation state;
- direct Quick Copilot → Full Chat handoff without copying or resubmitting the conversation;
- SQLite conversation/message persistence;
- runtime status propagation through a Qt-safe bridge;
- native message/code rendering;
- runtime restart, shutdown, cancellation, and status surfaces.

The historical research document [[file:docs/desktop-copilot-design.md][desktop-copilot-design.md]] contains both decisions that landed and ideas that did not. For current behavior, prefer [[file:docs/features.org][features.org]] and [[file:docs/architecture.org][architecture.org]].

*** MCP

Zara has a native Model Context Protocol client built on the official MCP Python SDK v2.

Each configured server has its own async actor/session. Zara supports local =stdio= servers and Streamable HTTP, discovers tools/resources/prompts, namespaces remote tools, isolates server failures, reconnects for future work, and never automatically replays a failed effectful tool call.

The management CLI can add, remove, enable, disable, inspect, and list server capabilities:

#+begin_src sh
zara mcp list
zara mcp status
zara mcp inspect SERVER
zara mcp tools SERVER
zara mcp resources SERVER
zara mcp prompts SERVER
#+end_src

Read [[file:wiki/mcp.org][the MCP guide]] and the [[file:docs/config/mcp.org][literate MCP config]].

*** User plugins

Zara supports both the older tool-plugin shape and a versioned service-plugin lifecycle for long-running integrations.

Service plugins get a deliberately narrow runtime facade: status, their own configuration table, bounded runtime-event subscriptions, canonical command dispatch, and bounded managed workers. They do not get Qt widgets, microphone internals, Prolog objects, or a secret back door into the agent.

Read [[file:wiki/plugins.org][the plugin guide]].

*** Pets

Zarathushtra Pets are optional PySide6 desktop overlays driven by provider-neutral runtime events. They can show =idle=, =running=, =ready=, =blocked=, and =needs-input= states, remember position/scale, respect reduced-motion preferences, and import Zara-native or compatible ChatGPT/Codex sprite packages.

Run them directly with:

#+begin_src sh
zara --pets
zara --pets-settings
#+end_src

Wake mode can launch them as a companion with =zara --wake --pets=. See [[file:docs/pets.md][the full Pets documentation]] and [[file:wiki/pets.org][the short operational notes]].

** Quick start

Nix is the supported install, development, and packaging path.

#+begin_src sh
git clone https://github.com/lost-rob0t/zara.git
cd zara
nix develop
#+end_src

Launch the desktop:

#+begin_src sh
zara --desktop
# or
nix run .#zara-desktop
#+end_src

Launch wake mode:

#+begin_src sh
zara --wake
#+end_src

Talk directly to the agent:

#+begin_src sh
zara --agent
#+end_src

Run a deterministic text command:

#+begin_src sh
zara 'open firefox'
#+end_src

For installation details, package entry points, GPU/STT notes, and the best-effort Python packaging path, use [[file:wiki/install.org][wiki/install.org]]. For what a text command can *actually* execute today, use [[file:docs/commands.org][commands.org]].

** Configuration without archaeology

Zara currently has three user-facing configuration layers:

| Layer | Default location | Use it for |
|-------+------------------+------------|
| Main TOML | =$XDG_CONFIG_HOME/zarathushtra/config.toml= | voice, STT, TTS, LLM, tools, memory, plugins, pets, database, todos |
| Prolog overrides | =~/.config/zarathushtra/config.pl= / loader-supported user path | application mappings, search/dictation commands, sounds, todo formatting, symbolic overrides |
| MCP overlay | =~/.config/zarathushtra/mcp.toml= | changes made by =zara mcp add/enable/disable/remove= |

Use [[file:docs/configuration.org][configuration.org]] for precedence and behavior. The annotated examples are intentionally readable on their own:

- [[file:docs/config/main.org][main TOML literate config]]
- [[file:docs/config/prolog.org][Prolog literate config]]
- [[file:docs/config/mcp.org][MCP literate config]]

Canonical defaults still live in code. The literate files explain them; they do not secretly become a second configuration implementation.

** Development and verification

Enter the Nix shell and run the complete regression gate:

#+begin_src sh
nix develop -c bash scripts/test-all.sh
#+end_src

The flake checks the same core surfaces as Nix derivations:

#+begin_src sh
nix flake check
#+end_src

The repository deliberately treats documentation changes like code changes for CI purposes. If a docs edit breaks packaging, links embedded in generated metadata, or some other apparently unrelated thing, congratulations: computers have found another way to make prose fail a build.

See [[file:wiki/install.org][Install & Configuration]] for the test phases and [[file:AGENTS.md][AGENTS.md]] for contributor rules.

** What Zara is not pretending to be

- It is not production-hardened assistant infrastructure.
- It is not security-audited.
- It is not equally supported on Linux, macOS, and Windows.
- It does not have a working =--voice= one-shot mode just because the flag exists.
- A recognized Prolog intent is not automatically a completed side effect.
- It does not have a general unit-conversion command just because timer parsing understands hours and minutes.
- Draft architecture in a design document is not a promise that the code already does it.
- The LLM is not the authority for deterministic commands when Prolog can resolve them.

There is plenty left to replace. That is the point. The interesting version of this project is the one where I can explain why each layer exists instead of pointing at a generated abstraction and hoping nobody asks questions.
