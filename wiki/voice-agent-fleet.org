#+title: Zara Voice Agent fleet

* Enable

The fleet is the existing RuntimeHost-owned TaskRunner, not a second agent
runtime. Finalized voice transcripts and typed turns use the same
LangGraphRuntimeBackend entry point. Conversation turns do not wait for task
completion. Existing providers, tool approvals and capability execution remain
in place.

Restart the runtime after changing configuration. Tasks remain disabled by
default. This does not change the selected provider or model and does not
install an APK or update another machine's configuration.

* Talk while the fleet works

Prolog classifies the finalized utterance; Python executes only the returned
closed action vocabulary. New explicit requests such as “research this topic”,
“also review this project”, “start a task to ...” or “have an agent ...” admit
another durable task. Excess work enters a bounded FIFO queue. Ordinary chatter,
negation, quoted stop words and questions about commands do not start or stop a
task. Ambiguous language stays on the existing conversation path, where the
configured conversational model can use the normal task tools.

Goals retain the original case and punctuation. A missing, invalid, busy or
failed symbolic router does not silently delegate a control command to a model.
“Fleet status” and “what are my agents doing?” provide bounded task summaries.

* Stop scopes

| Utterance | Result |
|-----------+--------|
| Stop talking | Interrupt output only; agents keep working |
| Stop / pause | Reversibly pause the principal's task fleet |
| Pause this task | Pause the unique current conversation task and descendants; ask for an ID when ambiguous |
| Pause task task-ID | Pause that task tree |
| Resume task task-ID | Resume that retained tree through the queue |
| Resume all work | Resume interrupted roots and their interrupted descendants |
| Cancel task task-ID | Cancel that tree permanently |
| Stop all agents / stop all work | Cancel running, queued and interrupted work for this principal |

Task cancellation does not undo an already-committed external effect. The
runtime revokes active turn capabilities and requests backend cancellation;
external providers and subprocesses still need to acknowledge cancellation.
Cancelled tasks cannot resume. A later explicit new request is a new task.

* Subagents and stop conditions

Calling task_create inside an active task automatically delegates a child; a
worker cannot escape its ancestry by requesting a new root. Parents release
their concurrency slot while joining children, including with a one-worker
fleet, and receive bounded child results before continuing. Child failure stops
the parent; parent pause/cancel/shutdown propagates to descendants. Task agents
cannot issue fleet-wide controls or control unrelated task trees.

The root and descendants share a persisted attempt budget and original
wall-clock deadline. Pausing, resuming, retries and delegation do not refresh
those limits. The deadline includes queued and paused time. Per-root descendant
count and depth limits bound fan-out. Three identical consecutive nonterminal
step summaries stop a task as no_progress; this is a conservative repetition
check, not a semantic proof of progress. Existing approval rejection/timeouts,
backend errors and runtime shutdown remain stop conditions. A standalone
TASK_COMPLETE or TASK_COMPLETE: marker ends a step loop only after children have
completed; arbitrary prefixes do not count as completion evidence.

* Barge-in

The managed event consumer never waits for synthesis or playback. A separate
managed speech worker consumes a bounded eight-item queue. Confirmed user speech
increments a speech generation, flushes queued output, cancels active synthesis
and terminates playback. Generation checks suppress audio that arrives after
interruption. None of those output operations cancels durable fleet tasks.
Existing playback-aware VAD thresholds and continuous microphone/STT ownership
are retained. Threshold-based gating is not acoustic echo cancellation.
