#+title: Zara Android navigation

* Three left menus

Issue [[https://github.com/lost-rob0t/zara/issues/934][#934]] reorganizes the existing Android shell. This is a navigation change, not a new runtime or a claim that every planned feature is implemented.

| Left menu | Tabs |
|-----------+------|
| Chat | Chat, Voice |
| Workspace | Code, Logic, Projects, Scheduled |
| Settings | Runtime, Connection, Permissions, Appearance, Plugins, Updates, Diagnostics, About |

On a compact window, open the menu button at the upper left. The drawer has exactly three primary entries; conversation-history placeholders and local/remote status remain below them. At an available window width of at least 600dp, the same three entries appear in a persistent left rail. The menu button still opens the history drawer. There is no bottom navigation bar competing with the composer.

Tabs scroll horizontally. Selecting a menu restores that menu's last tab. Code is Workspace's first tab; Logic stays directly beside it rather than being hidden in advanced settings.

* Settings organization

Runtime contains the existing local-server status, Auto/Local/Remote routing selection, and on-device embedding toggle. It does not change provider or model selection implicitly.

Connection contains client identity creation, public-key enrollment guidance, trusted-server pinning/replacement, endpoint entry, and Connect in one place. Previously these controls were split between Settings and Remote. Existing trust validation, connection lifecycle gates, and explicit user actions are unchanged.

Permissions contains Android Assistant-role onboarding, collapsed Samsung setup help, and microphone permission status/request. Opening Permissions does not request permission or start listening.

Appearance uses the existing shared semantic theme previews. Plugins preserves its current explicit implementation gate. Updates contains the existing verified APK download/install flow. Diagnostics and About reuse their existing bounded surfaces.

* State and Back

=AppNavigation= stores the selected primary menu and one last-selected route per menu. Save keys are stable names, not enum ordinals. Unknown or cross-menu restored values fall back to the relevant menu's first tab.

The shell's route-keyed =SaveableStateHolder= preserves existing =rememberSaveable= form values, chat drafts, and scroll state while routes are off-screen. This is Android UI saved state, not a new durable conversation database, a promise to retain unbounded documents, or a change to the Prolog editor's persistence contract. Recreation and large-draft behavior still require Android interaction evidence.

Back closes an open drawer before changing routes. Otherwise it returns from a secondary tab to that menu's first tab (Code for Workspace), then from Workspace/Settings to Chat. Back at the Chat root is handled by Android. Tab changes do not restart or replace the runtime.

* Feature truth

At the implementation base =e8e8382ddea3a48b1b67de9146e5e8ae6d17645f=, Projects, Scheduled, and Plugins are explicitly gated by #653, #654, and #655. Their tabs remain available to explain that state; this change does not add their backends. Pinned/recent history remains its existing unavailable placeholder state. Other workers can wire these surfaces through the existing callbacks/contracts without adding primary-menu entries.

* Verification and release gate

The dependency-free navigation contracts execute the actual =AppNavigation.kt= source: all route transitions, exhaustive saved-state combinations, invalid restoration, invalid construction, menu memory, Back convergence, and the 600dp breakpoint. The existing JUnit gate invokes those same contracts.

Additional source-wiring contracts check the saved-state holder, menu/rail inventory, scrollable tab wiring, separated Settings sections, insets, and menu accessibility label. These checks do not render Compose.

Before merge/release, exact-head repository and Android/Wear/native/APK CI must pass. Capture and inspect actual Android screenshots and interactions for:

- three-item drawer and all three menu/tab bars;
- every Settings tab, including scroll to About;
- 320dp compact width, 600dp rail threshold, landscape, and split-window resizing;
- Outrun and Light, normal and increased font scale, labeled focus/TalkBack targets;
- chat draft and connection form switching, rotation/recreation, Back, and IME-visible composer;
- disconnected local-capable mode, missing permissions, corrupt enrollment, and updater busy state;
- Code/Logic tab switching without loss of editor or Logic draft state.

No visual or hardware pass is implied by the pure Kotlin tests, source checks, or syntax parsing. The reference's visual language and all runtime/security gates remain authoritative; only its flat drawer inventory is superseded by #934.
