#+title: Android app

The native Android Zara client (issues #152, #170–#179, Samsung epic #194).

## Layout

- =android/= — Gradle project, single =app= module, application id =ai.zara.app=.
- =android/gradle/libs.versions.toml= — version catalog; pins live here.
- =android/app/src/main/java/ai/zara/app/runtime/= — the single typed runtime state + pure reducer (server connection, assistant role). The assistant surface (#196) and the Compose shell (#197) must extend this state, never fork it.
- =android/app/src/main/assets/prolog/= — reserved for the shared Prolog semantic fixtures (#172).

## Build / test

```sh
nix develop .#android -c bash scripts/test-android.sh
```

Runs JVM unit tests, =assembleDebug=, and an APK secret-marker inspection. The debug APK lands at =android/app/build/outputs/apk/debug/app-debug.apk= and is uploaded by the CI =android= job as an artifact.

See =rage/170-android-bakeoff.org= (Prolog runtime: Trealla via NDK + thin JNI; transport: jeromq pure-Java ZMTP/3.0 CURVE against the pyzmq CURVE/ZAP server) and =rage/171-android-skeleton.org= (skeleton, gates, toolchain as-built evidence).
