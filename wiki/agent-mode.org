#+title: Zara core agent mode

* Purpose

=agent-mode= is a first-party service plugin shipped inside Zara. It is disabled
by default and turns the normal conversational runtime into a more persistent,
autonomous assistant without creating a second AgentManager, event bus, or tool
runtime.

When enabled it can:

- persist and execute recurring background tasks;
- create proactive turns that periodically ask the user a question;
- speak arbitrary text through Zara's configured TTS provider;
- optionally speak proactive questions or recurring-task results;
- keep all work inside RuntimeHost so ordinary tools, approvals, memory, Discord,
  and other surfaces still see the same turn lifecycle.

* Enable

Add this to =~/.config/zarathushtra/config.toml= and restart the Zara runtime:

#+begin_src toml
[plugins.agent-mode]
enabled = true
random_questions = true
question_min_minutes = 60
question_max_minutes = 240
speak_questions = true
speak_task_results = false
poll_seconds = 1.0
#+end_src

The plugin is intentionally off when =[plugins.agent-mode].enabled= is absent or
false. First-party disabled plugins are not registered into the model tool set.

Recurring task state is stored at:

#+begin_example
$XDG_STATE_HOME/zarathushtra/agent-mode/state.json
#+end_example

or =~/.local/state/zarathushtra/agent-mode/state.json= when =XDG_STATE_HOME= is
unset. The directory is mode =0700= and the state file is mode =0600=. Set
=state_path= in the plugin table to override it.

* Tools

When agent mode is enabled, Zara gains:

- =schedule_recurring_task(name, prompt, every_minutes, start_delay_minutes=0)=
- =list_recurring_tasks()=
- =cancel_recurring_task(task_id)=
- =set_random_questions(enabled)=
- =agent_mode_status()=
- =speak(text)=

A recurring task is not a separate agent. When it becomes due the plugin submits
an ordinary =SubmitTurn= with an =agent-mode:task:<id>= conversation id. The
existing runtime executes that turn with the normal agent, tools, memory, and
approval rules.

* Proactive questions

When random questions are enabled, the scheduler chooses a random delay between
=question_min_minutes= and =question_max_minutes=. At the deadline it submits a
normal background turn asking Zara to produce one concise question that can
learn a preference, clarify active work, discover useful memory, or help with a
current goal.

The default interval is intentionally broad (60--240 minutes) rather than a
constant ping loop. =set_random_questions(false)= persists the disabled state.

Set =question_prompt= to replace the built-in generation prompt.

* TTS and wake capture

The =speak= tool uses the existing =TTSEngine= and =mpv= playback. Playback is
serialized so two tool calls cannot talk over each other.

The tool deliberately does not open, close, pause, or take ownership of any
microphone input device. Wake capture therefore remains active while tool-driven
TTS plays. Zara's existing barge-in path already supports microphone VAD during
playback; this plugin does not replace that path or create another capture loop.

The configured =[tts]= provider and voice are reused. Nix Zara wrappers already
place =mpv= on =PATH=. A non-Nix installation must provide =mpv= separately for
playback.

* Task result speech

=speak_task_results=false= is the default because autonomous tasks may produce
long output. Set it to true if recurring task responses should be spoken.
Proactive questions default to speech when =speak_questions=true=.
