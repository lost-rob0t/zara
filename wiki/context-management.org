Tracking: [[https://github.com/lost-rob0t/zara/issues/51][#51]]. This recovery retains
the existing ContextManager/skills implementation at =b9d3d5d3=, the existing
=d1e42d0= recovery contracts, and #260 advice controls from =fea09898=. Its old
research/design logs are retained for provenance; the current reconciliation

* Ownership and normal turns

ContextManager owns active inference history, complete turn groups, one canonical
base prompt, one optional summary, per-turn memory/runtime/MCP context, selected
skills, budget checks and mutation audits. ConversationManager retains mode and
timeout state and exposes a history projection backed by the context owner.
Clearing/replacing that compatibility projection routes through ContextManager;
callers cannot append directly to its owned history.

Raw durable conversations and derived long-term memory retain their existing
storage owners. The base prompt and transient context are regenerated per turn,
and never committed as raw conversation history. Selected provider memory is
still bound by RuntimeHost before turns; this code neither installs nor creates
another memory engine. Backend memory persistence remains the existing owner.

#+begin_src toml
[context]
strategy = "truncate" # or "compress"
max_tokens = 32000
preserve_recent_turns = 8
summary_max_tokens = 2000
skill_max_tokens = 6000

[skills]
enabled = true
search_paths = []
#+end_src

Values are validated without coercing strings or booleans into numeric limits.
Protected context that cannot fit reports unavailable instead of silently
discarding a recent turn or calling a provider with an oversized request.

The default counter is a conservative, local serialized UTF-8 payload estimate
including tool arguments and message overhead. It is not a measured provider
tokenizer count. =ContextManager(token_counter=...)= accepts an explicit local
provider counter; no tokenizer download, dependency, model or remote endpoint is
selected implicitly. Audit =token_count= and configured =max_tokens= use that
counter's budget units. Check the provider's actual window separately when
configuring a provider-specific counter.

Every canonical graph model step checks its current messages, including newly
returned tool data, before invoking the provider. Context ownership travels in
task-local scope, outside graph/checkpoint state. Owner/lease objects are not
serialized. An overlarge current tool turn fails closed rather than splitting
its calls/results. A completed output cannot expand active history beyond twice
the configured input budget; the next input assembles within the input budget.

* Retention and explicit Compact

=truncate= removes only complete oldest groups, retaining the configured recent
tail. =compress= replaces an eligible prefix and any previous summary with one
bounded summary. Destructive changes are staged: failed later summaries,
impossible budgets, cancellation and stale leases leave the live source history
unchanged. Automatic assembly commits retained context only with the accepted
turn result. A failed model call cannot commit the staged prefix.

=await ContextManager.compact(lease, reason="manual")= is an explicit typed API,
not a chat prompt. It works before budget pressure and returns changed/no-op,
affected group IDs, before/after counts, reason and summary revision. It preserves
the recent tail exactly and replaces an existing summary. Async summarization
has a caller deadline (60 seconds by default) covering callback invocation and
completion. Synchronous callbacks run off-loop; asynchronous providers retain
their original loop. Timed-out/cancelled work cannot commit. One supervised slot
stays =draining= until actual completion, refusing replacement work instead of
queuing more callbacks. The slot is shared across interactive/ephemeral contexts
and retained by RuntimeHost across restart generations. A queued synchronous
callback that expires before invocation is never called.
Shutdown cancellation shields the queued executor job until its cleanup runs;
cancellation before submission releases the unused slot immediately. The job
uses the existing default executor and preserves the caller's context variables.

RuntimeHost also bounds final pending-task draining by its existing shutdown
timeout and logs only survivor counts. This does not kill arbitrary Python code:
an uncooperative thread can remain alive and may delay OS-process exit. Providers
must honor their own cancellation/I/O limits; restarting a runtime does not
erase or replace occupied work. =summary_work_state= exposes idle/running/draining
metadata without callback bodies, transcripts or results.

=await AgentManager.compact_context(conversation_id)= selects only the active
context and rejects a busy interactive turn. Explicit cancellation invalidates
the active context lease before a late result can commit. Switching conversation
identity clears active inference context, avoiding cross-chat carryover; this is
not a replacement for rehydrating durable conversation history through the
existing conversation owner.

Task turns with supplied history or task system context use a fresh ephemeral
context owner. Success/failure cannot replace interactive history, persist a
task system message, or reuse interactive inference context. Stable scheduled
display-thread identity remains scheduler work; it is separate from inference
context lifetime.

* Advice and skills

Memory recall and context assembly are Core-owned before registrations on the
existing AgentLoopAdviceRegistry. They run when user customization is disabled.
Per-registration enable state is visible in metadata-only diagnostics; disabling
assembly makes turns unavailable. Global user-hook and around/override policy
remains effective. There is no second hook engine.

SkillRegistry loads bounded-budget YAML-frontmatter SKILL.md declarations from
the bundled source/installed tree, XDG user skills and explicit search paths.
Only relevant selected skills and their dependencies enter transient context.
Duplicate names, bad schema/metadata, dependency cycles, conflicts and budget
overflow fail explicitly. Shipped RAGE instruction text is preserved with added
standard metadata. Nix, wheel and source distributions retain the skill tree.

=browser_entries()= exposes stable metadata, source, domain/language, selectors,
priority, budgets, dependencies/conflicts, always-on state and declared tool
references. It excludes instruction bodies. Skill selection/tool references do
not register tools, grant permissions, approve actions or execute code.

* Remaining #51 integration

** Typed local acquisition

Local RuntimeHost clients can use =AcquireTextContext(text=..., conversation_id=...)=
to acquire an already-authorized pasted text snapshot, then pass the returned
=ContextAcquiredReceipt.context_id= to =SubmitTurn.context_ids=. This operation
does not invoke a model or execute text. The store is created lazily on the
backend's canonical principal; clients need no direct store injection. Defaults
remain the preceding bounded text-owner contract. An explicit reference is
required for each model turn; acquiring alone never changes active context.

=RevokeTextContext(context_id=..., conversation_id=...)= returns a metadata-only
=ContextRevokedReceipt.revoked= boolean. Wrong/missing/expired/revoked references
return false, and conversation revocation cannot remove a TURN snapshot. Stop
and restart clear the existing owner; stale IDs fail closed. These bounded local
mutations run on the canonical Host loop with existing lifecycle admission.

Commands validate UTF-8 text and canonical identifiers, max64KiB text, bounded display
name and typed sensitivity before dispatch. Command repr hides text/private
display name, receipts contain no supplied content, and acquisition/revocation
failure events and future errors use generic messages rather than backend error
payloads. Secret text remains withheld from the model. Validation errors do not
echo the supplied value. This privacy contract includes the Qt bridge's generic
future/receipt path; no new UI signal or approval channel is created.

Trusted local default factories now construct AgentManager with the canonical
=PrincipalContext.local_owner()=, matching the existing memory fallback identity.
Caller-supplied factories still require an explicit canonical principal for
acquisition; missing remote/plugin identity is never upgraded to local owner.
The server's authenticated per-principal manager factory remains authoritative.

The local typed API and explicit ZARA/1 commands below share this owner.
Graphical composer, Compact and skill-browser integration remains with the
existing UI issues #1045/#961/#1478; no parallel graphical stack is introduced.

#+begin_src python
reference = host.submit(AcquireTextContext(
    text="Pasted reference data", conversation_id="my-chat",
)).result()
host.submit(SubmitTurn(text="Summarize the reference", conversation_id="my-chat",
                     context_ids=(reference.context_id,))).result()
host.submit(RevokeTextContext(context_id=reference.context_id,
                             conversation_id="my-chat")).result()
#+end_src

Cancelling/timing out a future cannot retract a mutation that already completed.
An unacknowledged acquisition remains bounded by the same retention/TTL or stop
cleanup. A UI must not infer rollback from a cancelled future.

** Explicit text attachment owner

=zara.context.ContextAttachmentStore(principal=PrincipalContext(...))= is an
opt-in, in-memory owner for already-authorized text snapshots. The typed
kind/scope/sensitivity contract is recovered from the original #51 attachment
branch without its global store or implicit path reads. =acquire_text= accepts
data; a path or URL string is never opened. A trusted local caller must perform
any acquisition and authorization before supplying text. There is no implicit filesystem capability, binary decoder or persistent scope.
Explicit local and CLI pasted-text acquisition use this same store.

Inject the store with =LangGraphRuntimeBackend(..., attachment_store=store)=.
Its canonical principal must match the manager's full PrincipalContext on start
and before every turn. A store binds exclusively to one backend until stop;
another backend cannot reuse it or clear its snapshots. Existing =SubmitTurn.context_ids= references resolve
before routing/provider work. A missing/unconfigured store still fails closed.
Conversation scope requires the same explicit conversation ID. Turn scope also
requires the actual turn ID; direct backend callers know that ID. RuntimeHost
allocates turn IDs after SubmitTurn, so existing pre-submit clients can use
conversation-scoped snapshots; a future typed acquisition command must resolve
that timing before exposing turn scope in a composer. No client-provided ID is
silently rebound to a different turn.

Defaults: 32 retained items, 64KiB UTF-8 text per item, 256KiB aggregate text,
12,000 render characters, and 15-minute monotonic TTL (maximum one hour).
Expired references fail closed; entries are reclaimed on the next operation
or stop. Metadata is bounded, diagnostics contain counts/bytes only, and secret
text is withheld from the model. A render that exceeds its bound fails without
silently clipping data. The complete rendered transient still passes through
ContextManager's provider budget check. This local Python API is not a sandbox
against arbitrary code running inside the process.

The backend takes a bounded store-issued turn lease before any await. Duplicate
active identities and new TURN acquisitions during that lease are refused.
Finally cleanup removes only the captured turn snapshots under that exact lease;
clear/stop invalidates old leases, so late old completion cannot revoke new
generation data. Success, failure, cancellation and deterministic routes all
release their turn lease. Conversation snapshots remain until expiry/revoke or
backend stop, and must be explicitly referenced again to reenter the model.
Revocation prevents future lookup; it cannot retract text already sent to a
provider. RuntimeHost remains responsible for turn cancellation/result fencing.

Attachments enter labelled transient context as untrusted input data, never
approval or action authorization. They do not select a route, register tools,
change permissions, or enable task mode. Existing tool policy and the single
backend memory persistence owner remain unchanged. Raw persisted history excludes
attachment text; an assistant's derived response can still mention supplied
facts. Isolated task context remains isolated and skips ordinary session writes.

This slice leaves #51 open. Graphical acquisition and binary/file adapters
must use this scoped text owner rather than introducing global acquisition.
Post-turn memory advice must reconcile existing backend persistence
without duplicate writes. The typed RuntimeHost/UI command projection for Compact
and skill metadata belongs with #961/#1478 and existing #1045 surfaces; no new
Compose browser or competing registry is added here.

Finish these existing #51 prerequisites before extending #654's retained
#1058/#1150 scheduler. No Android Python packaging, installed UI, watch capture,
hardware battery or live-model acceptance follows from deterministic host tests.

* CLI pasted context through ZARA/1

#+begin_src sh
printf '%s' 'Synthetic reference [00:01]: verify the draft' | \
  zara --conversation-id my-chat --context-stdin 'Summarize this reference'
#+end_src

This connected CLI path uses the existing owner-local daemon by default; it does
not require a remote server. =--connect= remains an explicit endpoint choice.
The flag reads at most8193 bytes, accepts at most8192 UTF-8 bytes, and requires an
explicit conversation ID and text command. Invalid, blank or oversized input
fails before connecting. Text is absent from argv; this never opens a path or URL.
The local typed API retains its64KiB limit; the narrower wire bound keeps even
escaped text under the existing64KiB JSON envelope cap.

The CLI acquires PRIVATE conversation context, sends the opaque reference with
=SubmitTurn=, and revokes it in =finally= after success/error/timeout. Acquisition,
submission acknowledgment and cleanup each have a5-second wait; turn output uses
the existing30-second deadline. Missing or malformed cleanup acknowledgment
returns failure and reports the store's retention fallback. A lost acquisition
reply cannot supply a reference for cleanup: retention/stop limits still apply.
A timeout does not retract completed daemon work or cancel an already accepted
turn. Context is not ordinary transcript input, but model replies can quote it.

The closed message types are =context.text.acquire= / =context.text.acquired=
and =context.text.revoke= / =context.text.revoked=. Every envelope requires session
and explicit conversation correlation; no turn, stream, content-type, flags or
binary payload is accepted. Acquisition body is exactly text/display_name/
sensitivity; revoke exactly context_id. Replies contain only context_id and,
for revoke, a boolean revoked. The client checks operation, session, conversation
and revoke reference. The gateway binds identity from the existing trusted-local
or authenticated principal and uses the existing bounded pending/replay queues.
Both mutations require =context.write= on authenticated connections. Pairing's
default capability grants remain unchanged: existing remote pairings fail closed
without an explicit grant, and older peers report unsupported operations.

Retries with the same principal/request-ID and equal payload replay the original
receipt without reacquiring; differing payloads conflict. The bounded replay
cache keeps a keyed digest of acquired content/metadata rather than plaintext.
A replayed acknowledgment is not proof that a TTL-expired/revoked reference is
live. Use a new request-ID for intentional new acquisition after expiry/restart;
store and runtime-generation checks still decide usability. Revocation on a
wrong conversation, missing, expired or previously revoked reference returns
false and cannot delete another scope or principal's snapshot.
