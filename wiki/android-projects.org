#+title: Zara Android Projects

* Status

The Android Projects surface is implemented incrementally by issue #653.
The first slice is intentionally metadata- and conversation-scoped. It does not grant filesystem authority or recursively index a directory.

* User model

A project is a persistent app-private work context with:

- a stable project id,
- a bounded display name,
- an explicit source scope,
- an optional remote conversation id.

One project may be selected at a time. Selection survives process recreation. Selecting no project returns Chat to its ordinary conversation scope.

* Conversation isolation

Project chat and ordinary chat are separate scopes.

- A new remote project begins with no conversation id.
- The server-returned conversation id is bound only to that project.
- Switching project A -> B -> A restores each project's own conversation binding.
- A project response does not replace Android's ordinary selected conversation.
- Local project turns use an in-process identity of =local-project:<project-id>=; that local identity is never persisted as a remote conversation binding.
- Last-turn UI projection is isolated by project id, so switching projects does not display another project's latest turn.

* Source authority

The initial model exposes only =ProjectSourceScope.AppPrivate=.
There is deliberately no path, URI, directory, recursive-crawl flag, or ambient filesystem permission in =ProjectContext=.

A string that looks like a path is still only a project name. Source attachment is explicit and separately permissioned; selecting a project never implies access to nearby files.

The Chat composer now owns a bounded explicit-context layer. Its =+= menu may import user-selected UTF-8 text/code/data files through Android SAF or add pasted text. Zara snapshots that content into app-private storage for the current ordinary-chat or project scope; it does not retain a broad filesystem grant, crawl a directory, or read sibling files. Binary/PDF/image extraction is deliberately rejected until a typed extractor owns those formats.

Explicit context remains visible as removable chips before a turn is sent. The current Android slice materializes those bounded snapshots into the submitted turn with clear attachment boundaries and an untrusted-reference warning. It does not claim that the canonical #51 =context_ids=/ContextManager pipeline is complete.

* Persistence and degradation

=ProjectContextStore= uses a versioned bounded binary file in Android app-private storage.
Writes use a temporary file and atomic replacement where supported.

Limits are intentionally small:

- 64 projects,
- 80 characters per project name,
- 128 characters per project id,
- 256 characters per remote conversation id,
- 64 KiB maximum metadata file.

Malformed, unsupported, oversized, or inconsistent metadata enters an explicit degraded state. Zara does not invent replacement projects or silently overwrite the damaged file; project mutations remain blocked so recovery remains possible.

* UI

Projects are first-class from both the main Chat surface and =Workspace -> Projects=.

The main Chat surface provides:

- an always-visible =Projects= shortcut,
- the active-project indicator and =Chat / <project>= breadcrumb,
- a ChatGPT-style =+= menu for file context, pasted context, =Add chat to project=, and =Open Projects=,
- removable explicit-context chips.

=Workspace -> Projects= provides:

- active context summary,
- registered-project list,
- project creation,
- explicit project selection,
- explicit return to unscoped Chat.

When a project is active, Chat renders a compact =Chat / <project>= breadcrumb.

* Verification

Focused tests cover:

- create/select/list persistence across a new store instance,
- A/B conversation isolation and switching,
- missing project rejection,
- bounded names and control-character rejection,
- corrupt-state degradation,
- clearing selection without deleting projects,
- explicit scoped controller routing,
- project -> ordinary-chat contamination regression,
- Projects route/UI/host wiring contracts,
- absence of filesystem authority in the project model,
- bounded context-store persistence/degradation,
- explicit context materialization with prompt-injection labeling,
- main Chat Projects shortcut and =+= menu wiring,
- add-current-chat-to-project conversation/context handoff.

Real Android screenshot evidence remains a merge gate for the Projects list, selected-project details, active project breadcrumb, and degraded/empty presentation.

* Stack

The initial implementation is stacked on PR #939 because that PR establishes the canonical three-menu Android navigation and places Projects under =Workspace=. The Projects PR should be retargeted/reconciled after #939 lands, then rerun exact-head Android and repository gates before merge.
