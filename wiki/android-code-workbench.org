#+title: Zara Android Code Workbench and Prolog IPC

* Product contract

Zara has one Android Code Workbench UI implementation.

- =:code-workbench= owns the reusable Compose editor surface, SAF workspace browser,
  revision-fenced buffer integration, adaptive file rail, buffer inspector, find state,
  and voice-edit presentation.
- =:app= embeds that exact surface as =Workspace -> Code=.
- =:code-editor= remains a separately installable =ai.zara.code.editor= APK, but is a
  thin host over the same =CodeWorkbenchSurface=.
- =:editor-core= remains the revision/edit authority. The workbench does not invent a
  second mutable buffer model.
- Prolog-specific query, expert, KB, graph and learning tools remain in =Workspace ->
  Logic=. Code recognizes Prolog files but does not fork the Prolog IDE/runtime.

The default visual language follows the canonical Zara semantic theme tokens. No
screen-local Outrun palette is allowed in the reusable workbench.

* Cross-app Prolog contract

=:prolog-ipc= publishes =ZARA-PROLOG/1= for trusted Zara sibling APKs. The host is
=ai.zara.app.prolog.ipc.PrologIpcService= in the main Zara APK.

The service is exported only behind:

#+begin_example
ai.zara.permission.PROLOG
protectionLevel = signature
#+end_example

This is deliberately a trusted first-party channel. A random third-party app cannot
bind merely because it knows the action name.

The service forwards requests into =ZaraApplication.appSession.queryLocalProlog=.
It never creates =LocalZaraServer= or =NativeTreallaBridge=, so Android continues to
have one canonical serialized Trealla actor.

** Client setup

A sibling APK built by the Zara signer adds:

#+begin_src xml
<uses-permission android:name="ai.zara.permission.PROLOG" />
#+end_src

and depends on =:prolog-ipc=. Then:

#+begin_src kotlin
val prolog = PrologClient(context)
val call = prolog.query("member(Result,[alpha,beta])")
call.result.whenComplete { reply, error ->
    if (error == null) {
        reply.terms.forEach(::println)
    }
}
#+end_src

=PrologCall.cancel()= fences late delivery for that exact request id.

** Bounds

Version 1 enforces:

- request id: closed ASCII token, at most 96 characters;
- goal: non-empty, at most 8192 characters;
- deadline: caller-provided, at most 15 seconds;
- output: at most 64 terms, 4096 characters per term, and a bounded aggregate;
- error text: bounded before Binder delivery;
- duplicate active request ids: rejected;
- deadline/cancel: stale native results are dropped.

The existing =PrologQueryPolicy= remains the runtime query authority. The IPC layer
adds transport/lifecycle bounds; it does not grant new Prolog effects or Android
capabilities.
