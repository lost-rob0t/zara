#+OPTIONS: toc:nil

* Overview

Zarathushtra Pets are optional animated desktop companions that reflect live Zara runtime activity. They are native PySide6/Qt6 overlays, not Electron apps and not executable plugin packages.

For the full package/import/manifest/platform documentation, read [[file:../docs/pets.md][docs/pets.md]]. For where Pets sit in the runtime, see [[file:../docs/architecture.org][architecture.org]]. Static settings are annotated in [[file:../docs/config/main.org][the literate main config]].

* Enabling

Open settings/import UI:

#+begin_src sh
zara --pets-settings
#+end_src

Launch the overlay directly:

#+begin_src sh
zara --pets
#+end_src

Or launch it alongside wake mode:

#+begin_src sh
zara --wake --pets
#+end_src

* Linux display backend

On a Wayland Linux session with XWayland available (=DISPLAY= is set), the Pet process automatically uses Qt's =xcb= backend. This keeps Zara's main runtime on Wayland while preserving the Pet overlay's always-on-top and client-side drag behavior.

An explicitly configured =QT_QPA_PLATFORM= is respected. Set =ZARA_PETS_QPA_PLATFORM= to override the backend for the Pet process only. If XWayland is unavailable, the Pet keeps Qt's native platform selection.

Linux is the tested platform. “Qt can probably open a window elsewhere” is not the same sentence as “we support that platform.”

* States

| State        | Priority | Meaning                                  |
|--------------+----------+------------------------------------------|
| needs-input  |        4 | Waiting for approval/confirmation/input  |
| blocked      |        3 | Fatal failure / provider unavailable     |
| ready        |        2 | Finished with unseen output              |
| running      |        1 | Model/tool/agent/indexing/search active  |
| idle         |        0 | No active operation                      |

When activities overlap, the highest-priority current state wins. The Pet visualizes runtime state; it does not decide whether work succeeded.

* Import

- *Import Pet...* imports a Zarathushtra-native =pet.json= package.
- *Import ChatGPT Pet...* imports a compatible ChatGPT V1 (1536×1872) or V2 (1536×2288 plus =pet.json=) sprite package.
- *Import from ChatGPT...* discovers compatible Pets in known local ChatGPT/Codex application-data locations, read-only.

Pet packages are data: manifest plus sprite assets. They cannot contain executable scripts/hooks/network references.

* Storage

- managed Pets: =$XDG_DATA_HOME/zarathushtra/pets/<pet-id>/=
- runtime Pet state: =$XDG_CONFIG_HOME/zarathushtra/pet-state.json=
- static defaults: =[pets]= in Zara's main =config.toml=

Removing an imported Pet removes Zara's managed copy, not the original source asset.
