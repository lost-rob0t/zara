#+title: Android embedded local AI

* Scope

Zara Android can keep its Prolog-first standalone mode while optionally adding local conversational models and local speech synthesis. Model output does not become action authority. Android device effects continue through the typed Zara capability/policy boundary.

The owning issue is #904 under #622.

* Provider contracts

Zara treats local language models and local speech engines as two independent provider families.

** Language-model providers

The built-in language-model provider has provider id =embedded= and display name =Embedded Local=.

Android's =LocalAiServiceClient= implements =LocalAiProvider=. Callers depend on that provider contract rather than on LiteRT-LM directly. The contract exposes provider capabilities, provider state, installed-model catalog, active model, model installation and selection, streaming generation, cancellation and unload.

A provider model is selected by model id + version. The model catalog keeps metadata for every verified local install instead of replacing one global model record, so many compatible model families can coexist and be switched without changing Zara's chat routing code.

The shared model descriptor is format-neutral and can represent =litert-lm=, =gguf=, =onnx= and =tflite= containers plus explicit quantization metadata. The built-in =embedded= provider currently advertises and accepts only =litert-lm= because that is the runtime it actually executes today. Future GGUF/llama.cpp, ONNX Runtime, TFLite or WebAssembly/WebGPU engines implement/register the same provider interface and advertise only the formats they actually execute. Unsupported formats are never guessed or silently routed to the wrong engine.

The quantization vocabulary includes LiteRT-style dynamic INT4/INT4/INT8/FP8/BF16/FP16/FP32 and common GGUF quantizations such as Q8_0, Q6_K, Q5_K_M, Q4_K_M, Q4_0, Q3_K_M and Q2_K. Unknown quantization is rejected rather than inferred from a filename.

** Speech providers

Speech is separate from the language-model provider. =LocalTtsProvider= and =LocalTtsProviderRegistry= let Zara discover and select speech engines independently.

The first provider is =android-offline=. It uses Android =TextToSpeech= only with a voice whose =Voice.isNetworkConnectionRequired= value is false. It is deliberately marked as not Zara-model-backed because the voice model is owned by the installed Android TTS engine.

A future =sherpa-onnx= provider can own downloaded Piper/VITS/Kokoro-family models, and other local speech engines can register beside it. This separation means changing the LLM does not force a TTS change, and changing TTS does not change the LLM provider.

The portable =local-ai-v1= operation vocabulary includes provider discovery, model listing, active-model inspection, verified install, selection, load, generate, cancel, unload, TTS-provider discovery/selection, speak and stop-speech.

* Android service boundary

The phone hosts model and TTS lifetime in the signature-protected =LocalAiService= running in Zara's =:voice= process.

#+begin_example
Compose / VoiceInteractionService / AndroidAppSession
                    |
                    | provider contracts
                    v
             LocalAiService
          /                     \
 LocalAiProviderRegistry   LocalTtsProviderRegistry
          |                     |
 embedded LiteRT-LM       android-offline TTS
 model catalog            future neural TTS providers
          \                     /
              typed results
                    |
          Prolog / capability policy
#+end_example

The service is not a second Zara authority, memory store, plugin system, scheduler, or remote server. It owns only expensive local inference resources and speech synthesis lifetime.

* LiteRT-LM

Android uses the native Kotlin LiteRT-LM package pinned by the repository. Do not use =latest.release=. Model loading and inference stay off the Android main thread. CPU, GPU and NPU are explicit backends. GPU use declares the optional OpenCL/vendor libraries required by LiteRT-LM.

Model files are not bundled into the base APK. They are installed into app-private storage and require explicit metadata:

- model id and version;
- model container format;
- exact quantization;
- SHA-256;
- context limit;
- requested backend.

Unknown format or quantization is rejected. Zara never guesses either from a filename. The model file is SHA-256 checked before activation and again before service load.

Every install gets a catalog sidecar in app-private storage. The active manifest is only the current selection pointer; switching models does not delete the other verified model files or metadata.

The initial practical real-device lane is a small explicitly quantized =.litertlm= model, such as the Gemma 3 1B IT dynamic-int4 class where its model license is accepted. CI uses fake backends and does not download a large model.

* Routing

Local text remains symbolic-first:

#+begin_example
utterance
  -> portable Prolog / expert router
     -> deterministic result: return it
     -> no deterministic match: selected LocalAiProvider model
        -> no installed/ready model: bounded model-unavailable result
#+end_example

Model text is conversational output only. It cannot call Android capabilities or provider-native tools as action authority.

* Local TTS

** Small on-device neural voice: Kitten Nano

The supported integration path is a sherpa-onnx *Android TTS engine* APK,
consumed by Zara's existing =android-offline= provider. This is an installed
on-device model, not an HTTP endpoint or a Zara server dependency. It is not
bundled into Zara's APK. Use an engine APK, not the standalone demo APK.

Verified download on 2026-11-13:

- Runtime/package: sherpa-onnx 1.12.22, Android =arm64-v8a=.
- Model: =kitten-nano-en-v0_2-fp16=, English, eight voices.
- Model ONNX bytes inside APK: 23,804,897 (22.70 MiB).
- Complete APK: 44,169,844 bytes (42.12 MiB); extracted contents are larger.
- SHA-256: =09dd1ea58ae08804ef58ecd2bfbfedd6d23b81792b5ad64e1582131f4cd3d8ef=.
- Official engine catalog: https://k2-fsa.github.io/sherpa/onnx/tts/apk-engine.html
- Download: https://huggingface.co/csukuangfj/sherpa-onnx-apk/resolve/main/tts-engine-new/1.12.22/sherpa-onnx-1.12.22-arm64-v8a-en-tts-engine-kitten-nano-en-v0_2-fp16.apk

Install the matching architecture APK through Android's package installer,
open its setup once, and select it as the preferred engine in Android speech
settings. In Zara, open Settings -> Runtime & local AI -> Offline speech,
press Refresh voices, then Test offline speech. Repeat the test with network
disabled. Stop speech must cancel playback. No language model needs loading.
The ARM64 package above does not run on an x86_64 emulator; use the matching
architecture from the official catalog for emulator evidence.

Refresh now stops old speech and recreates the engine even when it was already
ready. Ordinary initialization remains cached. Late callbacks from the retired
engine cannot replace the new engine or complete a new utterance.

Other small CPU options are Kitten Micro/Mini and Piper low/x-low voices via
the same sherpa Android engine catalog. Their package sizes, supported languages
and model licenses vary; do not treat their weights as interchangeable with the
pinned Nano package. Kitten's lightweight ONNX family is documented at
https://github.com/KittenML/KittenTTS/blob/main/docs/onnx-models.md .

The exact Nano weights extracted from the APK produced 4.05 seconds of 24 kHz
audio in 1.12 seconds on this session's Linux x86_64 CPU with two threads
(sherpa-onnx Python 1.12.26; initialization 1.32 seconds). This is a CPU smoke
test, not an Android latency, audible-playback or phone acceptance claim.
Python 2.0.1 rejected this older package's phonemizer configuration; keep the
packaged engine/model pair together rather than upgrading a runtime blindly.

** Provider behavior

The first local speech provider is Android =TextToSpeech= with an explicitly selected voice whose =Voice.isNetworkConnectionRequired= value is false. If the device has no installed offline voice, Zara reports TTS unavailable. It does not silently switch to network speech.

Speech uses unique utterance ids and =UtteranceProgressListener=. Zara can stop the engine immediately for barge-in/cancellation.

A later fully Zara-managed neural voice provider may use sherpa-onnx with a downloaded, versioned and checksummed Piper/VITS/Kokoro-family model. Model files remain app-private and checksum/versioned; the Android system provider remains the lightweight fallback.

* WebAssembly / Web

The local-AI provider boundary has the stable =local-ai-v1= ABI vocabulary so the same product contract can be implemented by a WebAssembly/Web backend.

For browsers, LiteRT-LM's JavaScript path uses WebGPU and LiteRT.js loads its WebAssembly runtime. That is the Web implementation path.

Android itself deliberately uses native Kotlin LiteRT-LM rather than embedding the browser/WebAssembly runtime in a WebView. Native Android LiteRT-LM exposes the supported CPU/GPU/NPU acceleration path directly. The WebAssembly boundary is portability at the provider contract, not a reason to throw away Android acceleration.

* Security and lifecycle

- =LocalAiService= is non-exported.
- Models and catalog metadata live in app-private storage.
- Unknown formats and quantizations are rejected.
- Provider capabilities are explicit; Zara does not claim an engine can execute a format it cannot.
- No network fallback occurs merely because local inference fails.
- One actor owns model load/generate/unload ordering.
- Provider selection never grants model output device-action authority.
- A cancelled LiteRT-LM conversation is discarded rather than reused.
- Activity recreation does not create another model owner.
- Local model output remains untrusted text until normal Zara semantic/policy handling.
- Offline TTS selects only a non-network-required voice.

* Android setup and recovery

Install the Zara phone APK first. It owns the model catalog, inference, and
speech service in the =:voice= process. Both the main app and LLM Serve use
the same Messenger IPC facade; a local Binder cast cannot cross that process
boundary. The service's exported facade requires Zara's signature permission.

Open Settings -> Runtime & local AI. Select Local for symbolic-first on-device
chat, or Symbolic to forbid all model calls. Import a compatible =.litertlm=
file with its explicit quantization, context limit, and CPU/GPU/NPU backend.
A file extension or a successful import is not proof of inference: complete a
semantic-miss chat turn and verify the actual selected model response.

The Offline Speech card is independent of model installation and accounts.
Use Android speech settings to enable an engine and install an offline voice.
Return to Zara, select Refresh voices, then Test offline speech. Stop speech
cancels queued and active speech. Network-required and not-installed voices
are excluded. Missing engines/voices show setup instructions. Speech is stopped
when the activity leaves the foreground; assistant replies share the canonical
speech owner and surface synthesis failures.

For a direct remote model, save the HTTPS API base URL, exact model id, and API
key under Runtime & local AI, enable the profile, and use Check saved connection
/ load models. This check calls =GET /models=; it does not generate a reply.
Select a returned model (or enter an exact id when catalog discovery is not
supported), save it, and choose Remote. A connected authenticated Zara server
still takes precedence in Remote. Direct provider replies stream into a
transient chat draft; Stop reply cancels the provider and fences later chunks.
Only completed successful turns enter future model context. Keys are wrapped
by Android Keystore and are not saved in Compose restoration state.

Local and Symbolic startup do not restore a remote connection merely because
an old server profile exists. An unavailable local model never enables a
remote provider implicitly.

* Debug acceptance downloads

CI publishes =android-test-unverified-<source SHA>= after a successful APK build,
even if later installed acceptance fails. This bundle contains the Zara and LLM
Serve debug APKs, SHA-256 checksums, installation notes, and the acceptance outcome.
It is explicitly not a validated release. Release-candidate uploads still require
the green gate. Offline audio and real inference are not certified by the bundle.

External Android TTS engines run behind a worker so a slow engine cannot hold
Zara's main IPC thread. Initialization reports an unavailable engine after 15
seconds; state/stop remain responsive. If the engine itself is stuck, check Android
speech settings and its offline voice data before refreshing. This does not make
a missing voice available or substitute network speech.

The opt-in installed real-model test accepts pinned =qwen2-0.5b= or
=smollm2-135m= fixtures via =realModelFixture=. =reuseInstalledModel=true= verifies
an existing catalog model before the same generation, streaming, unload/reload
assertions; it does not claim a fresh import. Ordinary CI skips real-model tests
unless their external fixture is explicitly supplied.

* Update channels and versions

Settings -> Updates has independent Master (fastest green) and Versioned release
channel controls. Refresh versions loads the published catalogs. The selected
channel and version persist across refresh and process restart; a missing channel
never silently switches to the other one.

Master resolves =android-latest/zara-latest.manifest.txt= and downloads the exact
=zara-latest.apk= whose checksum it records. Its displayed product version and
Android version code come from that manifest, not from the mutable tag's target.
Versioned entries use =zara-android-<version>.manifest.txt= and the exact phone APK;
Code Editor, Wear, LLM Serve and Org APKs are never selected for the phone updater.
The user can inspect older releases, but an already installed or older version
has no download/install action. A master APK with a lower Android version code
is also rejected. Android's package installer retains signer verification and
user confirmation. Selecting a channel or version never installs automatically.
