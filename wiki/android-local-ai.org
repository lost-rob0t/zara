#+title: Android embedded local AI

* Scope

Zara Android can keep its Prolog-first standalone mode while optionally adding a local conversational model and local speech synthesis. The model does not become action authority. Android device effects continue through the typed Zara capability/policy boundary.

The owning issue is #904 under #622.

* Provider contract

The embedded engine is a first-class Zara model provider with provider id =embedded= and display name =Embedded Local=.

Android's =LocalAiServiceClient= implements =LocalAiProvider=. Callers depend on that provider contract rather than on LiteRT-LM directly. The contract exposes provider capabilities, provider state, installed-model catalog, active model, model installation and selection, streaming generation, cancellation/unload, and local speech.

A provider model is selected by model id + version. The model catalog keeps metadata for every verified local install instead of replacing one global model record, so Gemma, Qwen, or any other model that is packaged for a supported embedded backend can coexist and be switched without changing Zara's chat routing code.

The built-in embedded provider currently advertises =.litertlm= containers and CPU/GPU/NPU acceleration. That is a capability statement, not a hard-coded model family: Zara does not assume a particular architecture or model id. Future GGUF/llama.cpp, ONNX, or WebAssembly/WebGPU engines should implement/register the same provider interface and advertise only formats they actually execute. Unsupported formats must not be claimed or guessed.

The portable =local-ai-v1= operation vocabulary includes model listing, active-model inspection, verified install, selection, load, generate, cancel, unload, speak and stop-speech.

* Android service boundary

The phone hosts model and TTS lifetime in the non-exported =LocalAiService= running in Zara's =:voice= process.

#+begin_example
Compose / VoiceInteractionService / AndroidAppSession
                    |
                    | LocalAiProvider (embedded)
                    v
             LocalAiService
                actor lane
             /             \
      LiteRT-LM engine    offline TTS
      model catalog       Android voice
             \             /
              typed results
                    |
          Prolog / capability policy
#+end_example

The service is not a second Zara authority, memory store, plugin system, scheduler, or remote server. It owns only expensive local inference resources and speech synthesis lifetime.

* LiteRT-LM

Android uses the native Kotlin LiteRT-LM package pinned by the repository. Do not use =latest.release=. Model loading and inference stay off the Android main thread. CPU, GPU and NPU are explicit backends. GPU use declares the optional OpenCL/vendor libraries required by LiteRT-LM.

Model files are not bundled into the base APK. They are installed into app-private storage and require explicit metadata:

- model id and version;
- exact quantization;
- SHA-256;
- context limit;
- requested backend.

Unknown quantization is rejected. Zara never guesses quantization from a filename. The model file is SHA-256 checked before activation and again before service load.

Every install gets a catalog sidecar in app-private storage. The active manifest is only the current selection pointer; switching providers/models does not delete the other verified model files or metadata.

The initial practical real-device lane is a small explicitly quantized =.litertlm= model, such as the Gemma 3 1B IT dynamic-int4 class where its model license is accepted. CI uses fake backends and does not download a large model.

* Routing

Local text remains symbolic-first:

#+begin_example
utterance
  -> portable Prolog / expert router
     -> deterministic result: return it
     -> no deterministic match: selected LocalAiProvider model
        -> no installed/ready model: bounded model-unavailable result
#+end_example

Model text is conversational output only. It cannot call Android capabilities or LiteRT-LM tools as action authority.

* Local TTS

The first local speech backend is Android =TextToSpeech= with an explicitly selected voice whose =Voice.isNetworkConnectionRequired= value is false. If the device has no installed offline voice, Zara reports TTS unavailable. It does not silently switch to network speech.

Speech uses unique utterance ids and =UtteranceProgressListener=. Zara can stop the engine immediately for barge-in/cancellation.

A later fully Zara-managed neural voice backend may use sherpa-onnx with a downloaded, versioned and checksummed Piper/VITS/Kokoro-family model. That remains behind the same provider/speech boundary.

* WebAssembly / Web

The local-AI provider boundary has the stable =local-ai-v1= ABI vocabulary so the same product contract can be implemented by a WebAssembly/Web backend.

For browsers, LiteRT-LM's JavaScript path uses WebGPU and LiteRT.js loads its WebAssembly runtime. That is the Web implementation path.

Android itself deliberately uses native Kotlin LiteRT-LM rather than embedding the browser/WebAssembly runtime in a WebView. Native Android LiteRT-LM exposes the supported CPU/GPU/NPU acceleration path directly. The WebAssembly boundary is portability at the provider contract, not a reason to throw away Android acceleration.

* Security and lifecycle

- =LocalAiService= is non-exported.
- Models and catalog metadata live in app-private storage.
- No unknown quantization is accepted.
- No network fallback occurs merely because local inference fails.
- One actor owns model load/generate/unload ordering.
- Provider selection never grants model output device-action authority.
- A cancelled LiteRT-LM conversation is discarded rather than reused.
- Activity recreation does not create another model owner.
- Local model output remains untrusted text until normal Zara semantic/policy handling.
- Offline TTS selects only a non-network-required voice.
