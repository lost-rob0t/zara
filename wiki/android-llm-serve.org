#+title: Android LLM Serve APK

* What it is

=llm-serve= is a separate Android APK that exposes Zara's existing on-device
LiteRT-LM runtime through a small Ollama-compatible loopback HTTP surface.

It is compatibility, not a bundled copy of upstream Ollama. The server binds
only =127.0.0.1:11434= and implements the subset Zara needs:

- =GET /api/version=
- =GET /api/tags=
- =GET /api/ps=
- =POST /api/chat=
- =POST /api/generate=

Both buffered JSON and NDJSON streaming are supported for generation.

* Runtime ownership

The APK reuses Zara Android's canonical =LocalModelStore=,
=LocalAiRuntime=, and =LiteRtLocalLlmBackend=. The runtime remains
single-thread actor-owned. There is no second model scheduler, model catalog,
or inference policy implementation.

Model installation is app-private and SHA-256 verified. The user supplies model
id, version, backend, context size, and an explicit declared quantization.
Unknown or omitted quantization is not guessed.

* Zara configuration

A Zara process on the same Android device can use the service as an Ollama
provider:

#+begin_src toml
[client_profiles.phone-local.llm]
provider = "ollama"
endpoint = "http://127.0.0.1:11434/api/chat"
model = "zara-local"
#+end_src

Select that profile locally with =ZARA_CLIENT_PROFILE=phone-local=, or bind a
known client id through =[client_pins]=.

A different profile can pin the mobile client to OpenRouter while desktop or
another local process remains on this loopback service.

* Security boundary

- no wildcard/LAN bind;
- service component is not exported;
- request body/header/message sizes are bounded;
- model bytes stay in app-private storage;
- model output has no device-action authority;
- API credentials are not stored in client profile tables.

* Launch and reboot

After importing a compatible verified model, choose =Start server= once.
The foreground notification shows the local endpoint and active model.
Zara LLM Serve remembers that choice and resumes after =BOOT_COMPLETED=
(user unlock) and when its Activity is opened again. It does not start
on a fresh install before the user has started or successfully imported a
model. =Stop server= disables boot and sticky-process resumption. Android
force-stop and OEM battery restrictions can still require reopening the app.

The loopback listener can run with an empty model catalog, but the status
then reads =waiting_for_model=. A model-load failure remains an explicit
failure; it is never hidden behind a ready notification.

In Zara Android's Runtime settings, select local Ollama and the exact
model name from =/api/tags= (for example =zara-local:1=). The server's
quantization metadata is exposed there, so the client does not require
upstream Ollama's =/api/show= endpoint.
