** Research / selected architecture
- Zara's existing =create_tools_node= already owns tool availability checks, approval composition, =ToolStarted=, canonical =ToolCancelled(reason="turn cancelled")=, failure, completion, and the single call into LangGraph ToolNode.
- Bind one invocation-scoped Core cancellation ContextVar immediately around =tool_node.ainvoke=. LangGraph's synchronous executor receives the call context while async tools execute directly in it.
- The scope owns a private =threading.Event=. Plugins receive only a read-only =ToolCancellation= view through =current_tool_cancellation()=. The model cannot supply, suppress, replace, or retarget it.
- On =CancelledError=, =create_tools_node= signals the scope before publishing the existing terminal cancellation and re-raising. No second terminal authority is introduced.
- The contract is generic at Zara's canonical tool boundary rather than plugin-specific execution machinery; service plugins consume it through the public plugin API.

** Invariants
- one cancellation signal per exact tool invocation;
- concurrent calls cannot cancel one another;
- cancellation never bypasses =ToolApprovalController= or availability checks because scope begins only at execution;
- sync and async tools observe the same Core signal;
- terminal outcome remains owned by =create_tools_node=;
- plugin unload/registration identity remains untouched;
- no new model-visible arguments or reusable IDs.

** Gate
- deterministic sync cancellation before side effects;
- concurrent invocation isolation;
- async cancellation sees signal before =CancelledError= handling;
- approval rejection must not expose a running cancellation scope;
- full =scripts/test-all.sh=, =nix flake check=, packaged Zara, Android compatibility, Arch/Ubuntu shared-mic, exact-head reviews/threads.
