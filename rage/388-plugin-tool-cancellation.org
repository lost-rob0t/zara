** Contract
- Service-plugin tools remain ordinary =BaseTool= registrations in the canonical =ToolRegistry -> ToolNode= path.
- =PluginManager= wraps each service tool exactly once and preserves its name/schema/metadata, including approval metadata.
- Every invocation receives one Core-owned =ToolCancellation= view via =current_tool_cancellation()=; the token is not a model/tool argument and cannot be retargeted.
- Canonical task cancellation signals the token before child-task teardown. =create_tools_node= remains terminal-event authority and emits =ToolCancelled(reason="turn cancelled")=.
- Concurrent invocations have isolated tokens. Async tools still receive =CancelledError=.

** Recovery design
- Synchronous wrapped tools now run through one explicit =asyncio.to_thread= worker owned by the cancellation adapter; Python propagates the invocation ContextVar into that worker.
- Async-only tools keep direct =ainvoke= execution under the same bound ContextVar.
- Cancellation first sets the shared =threading.Event= and then cancels the child asyncio task. A synchronous worker may continue only long enough to observe that token and release owned work; it cannot report a successful canonical terminal after parent cancellation.
- No global cancellation flag, process-id registry, user-visible cancel token, or secondary execution path exists.

** Deterministic acceptance
- running synchronous service tool observes canonical cancellation before side effects;
- concurrent cancellation tokens remain isolated;
- async-only service tool sees the same invocation-scoped token and receives =CancelledError= after the token is signalled;
- Android compatibility and both shared-mic lanes remain unchanged.
