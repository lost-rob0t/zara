** Research (pre-implementation)
- Live incident: =zara hello= → =ZARA/1 handshake timed out=; daemon journal showed
  =domain_error(zarathushtra_user_config_fact, direct_app(torbrowser-launcher))= raised from
  =main.pl:14= initialization, so the principal Prolog engine never loaded.
- Mechanism: SWI-Prolog parses unquoted =torbrowser-launcher= as =-(torbrowser, launcher)=
  (infix =-=). =validate_user_fact(direct_app(Name), ...)= requires =atom(Name)=, validation
  fails, =read_user_terms/3= throws.
- Fail-closed on invalid facts is intentional: =rage/309-prolog-config-recovery-design.org=
  requires =domain_error(zarathushtra_user_config_fact,...)= and
  =t/prolog_config_recovery.pl= enforces it. The defect is diagnostic quality only.
- Operator fix applied on the live system: quote the atom in
  =~/.config/zarathushtra/config.pl= and the Home-Manager source; engine load verified restored
  (=Loaded Prolog program= in journal after =systemctl --user restart=).

** Design
- Keep fail-closed semantics. Change only the error context message.
- When the rejected term contains a compound argument shaped =atom-atom=, replace the generic
  message with one that states the operator trap and shows the quoted form
  (e.g. =direct_app('torbrowser-launcher')=).
- Rejected: accepting hyphenated compounds as atoms (silent coercion creates false authority
  and changes stored facts); weakening fail-closed to skip invalid facts (contradicts #309).
- Scope: =modules/config_loader.pl= user-config path only; server-config reader unchanged
  (different fact vocabulary, no reported incident).

** Acceptance-to-test map

- Existing fail-closed recovery behavior unchanged :: =t/prolog_config_recovery.pl= suite.
