** Current architecture findings
- =DatabaseManager= is Zara's shared SQLite boundary with locked transactions and registered migrations.
- =ConversationStore= already proves the repository pattern for binding a store instance to one =PrincipalContext= and adding =principal_id= to every read/write predicate.
- User-authored commands must not be stored as executable Prolog/Python/shell. Persistence stores a closed declarative schema only; compilation/execution belongs to later #163+.

** Design
- Add a core =zara.user_commands= persistence module, independent of desktop UI and Android.
- Store one JSON document per command only after structural validation into explicit typed Python dataclasses. JSON is data, not executable authority.
- Every store instance is permanently bound to a =PrincipalContext=; owner is injected from the store, never accepted from command payloads.
- Stable command IDs are caller-supplied or generated; lookups, list, update and delete include =principal_id= in SQL predicates.
- Optimistic concurrency uses an integer =revision=. Updates require the observed revision and atomically advance it, preventing silent concurrent overwrite.
- Use =BEGIN IMMEDIATE= for create/update/delete mutations so uniqueness/conflict decisions and writes are one SQLite transaction.
- Version 1 accepts only trigger/aliases, typed semantic action references, enabled state, ownership, timestamps and revision in this slice. No shell/import/provider-class/Prolog-goal fields exist.
- Guest/ephemeral principals fail closed for durable mutations; local-owner/authenticated/synthetic test principals may persist unless later principal policy narrows that contract.

** Threat / failure review
- Cross-principal known-ID attack: SQL owner predicate makes get/update/delete indistinguishable from absence.
- Payload owner spoofing: owner is not part of the persisted input API.
- Code-smuggling: model has no free-form executable field; dangerous execution capabilities fail validation.
- Partial write/crash: each mutation is one SQLite transaction.
- Lost update: revision compare-and-swap.
- Trigger collision: trigger/alias collision detection is scoped to the principal and normalized deterministically.
- Migration: =schema_version= is explicit; unsupported versions fail closed before activation.
