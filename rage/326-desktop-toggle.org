* Iteration 2 — bounded local owner and CLI
** Contract
- Exactly one desktop process owns one local AF_UNIX control endpoint per canonical Zara runtime directory.
- Closed commands are =toggle=, =show= and =hide= only. No arbitrary shell/eval, ZARA/1 visibility verb, second daemon, or remote listener.
- The owner reserves the endpoint before starting its daemon-backed desktop client. A duplicate startup relays =show= to the winner and exits without creating another runtime/client.
- Socket-server threads never mutate Qt widgets directly: validated commands cross onto the controller through a Qt signal.
- =zara --toggle-desktop= toggles an existing owner and starts one visible canonical desktop if absent. =--show-desktop= is idempotent summon/start; =--hide-desktop= fails honestly if no owner exists.
- Endpoint directory and socket remain current-UID owned and private. Stale same-user sockets may be reclaimed; a live owner is never unlinked by a losing process.

** Adversarial fixes
- Duplicate-owner review found a TOCTOU cleanup bug where a losing server could unlink a winning owner's endpoint. Ownership is now explicit and unlink occurs only after this server successfully bound the endpoint.
- CI #1417 / run 33972495977 at head =75bba4088e9aba98a6e0a7f0c7fbb4a59438d34b= proved Android and both shared-mic lanes green and ran 1976 Core tests; exactly five new desktop-control tests failed with =OSError: AF_UNIX path too long= under the intentionally long isolated CI runtime path. 1971 tests passed. Flake/package remained correctly gated after the Core failure.
- The direct endpoint is now used only when its encoded path fits the Linux =sockaddr_un= budget. Longer canonical runtime paths deterministically map via BLAKE2s to a short =/tmp/zara-desktop-control-UID/<digest>.sock= endpoint.
- The fallback directory is created/validated as current-UID =0700= and the socket is =0600=. Client and server both validate private endpoint-parent ownership before use; the mapping contains no secret and exposes no broader command surface.
- Dedicated regression covers long-path determinism, owner-private fallback permissions, stale socket recovery, malformed/oversized input and live-owner preservation.
