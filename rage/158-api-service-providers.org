** Inference
- The server danger is structural, not current-runtime: the server does not
  run Prolog command execution today (prolog_engine=None), but shared
  config makes Linux shell mappings look like valid server behavior the
  moment any Prolog boot lands server-side (#160 routing). The split must
  make device mappings un-consultable by a server boot and make server
  reachability explicit (environment =providers= list from a host-owned
  registry).
- Desktop behavior must be preserved exactly: user config.pl overrides
  (module-less facts) keep working via the loader, now routed to a device
  module.

** Unknowns resolved by design below
- Where the environment/providers builder lives (RuntimeHost-owned
  registry), what server providers do concretely (adapters), and the
  compatibility story for old user config.pl (server scope refuses device
  facts loudly; desktop routes them to the device module).

* Design (Auto-RAGE; recorded decision below)

** D1. Three-way Prolog configuration split
- =kb/config.pl= (shared semantic, server-safe; module =kb_config= keeps
  name) retains =todo_*=, =search_engine= (URL template — data, not a
  command), =wake_word=, =llm_*=, =prolog_rlm_*=. The
  =initialization(load_user_config)= hook MOVES to =main.pl= (desktop boot)
  so consulting =kb/config.pl= alone never loads user config.
- =kb/device_providers.pl= (NEW, module =kb_device_providers=): =app_mapping=,
  =direct_app=, =dictation_command=, =timer_sound=, =alarm_sound= with
  =:- dynamic= declarations. Consulted only by =main.pl=. Consumer
  re-pointing: commands.pl, sound.pl, dictate.pl, main.pl show_config,
  PrologEngine.get_app_mapping, builtin_tools query_prolog description,
  tests + scripts/test-replies.sh.
- =kb/server_providers.pl= (NEW, module =kb_server_providers=): the versioned
  =api_service= registry facts, flat portable subset (no lists — pyswip
  nesting gotcha):
  =api_service_registry_version(1).= and
  =api_service_provider(Id, Kind, TimeoutSeconds)= for =search_server=,
  =timer_server=, =admin_restart= (builtin). This file is server provider
  CONFIGURATION (what the host registers), distinct from =kb/capabilities.pl=
  (the capability authority: provider properties/bindings stay there).
- =server_main.pl= (NEW, repo root, beside =main.pl=): server-safe Prolog
  boot consulting kb/config, kb/server_providers, kb/capabilities,
  modules/capability_plans, modules/config_loader, then
  =initialization(config_loader:load_server_config)=. It NEVER consults
  =kb/device_providers.pl=.
- =main.pl= gains explicit =config_loader:load_user_config= initialization.

** D2. Loader scopes (compatibility + fail-safe)
- =modules/config_loader.pl=: device-fact =validate_user_fact= clauses
  re-target =kb_device_providers= (desktop behavior preserved; old user
  config.pl files keep working unchanged). New =load_server_config/0 +
  validate_server_user_fact=: server allowlist = semantic + intent facts
  only; any device fact (app_mapping/direct_app/dictation_command/
  timer_sound/alarm_sound) or unsupported fact throws
  =domain_error(zarathushtra_server_config_fact, Term)= — failing the
  server boot loudly (PrologStartupError) instead of silently accepting
  shell mappings. Documented compatibility behavior: a shared desktop+server
  machine keeps device overrides in user config only if the server is not
  enabled there.

** D3. Versioned api_service registry + adapters (Python)
- =zara/runtime/api_service.py= (NEW):
  - =API_SERVICE_REGISTRY_VERSION = 1=; =ProviderSpec= (frozen:
    provider_id, kind, timeout_seconds bounded [0.1, 60]).
  - =ServiceProviderRegistry=: thread-safe =register(spec, adapter)= /
    =unregister(provider_id)= / =provider_ids()= / =resolve_adapter(id)= /
    =timeout_for(id)=; duplicate id or unknown unregister raise; adapter
    resolution is live so unregistration takes effect for in-flight plans;
    race-safe (tested with threads).
  - =TimerService=: injectable monotonic clock (virtual clock in tests, no
    sleeps), bounded table (64), =set(duration_s, label, request_id)=,
    =cancel(id)=, =due(now)=; duration validated in (0, 86400]. Policy
    pinned: server timers are recorded service work with due tracking;
    firing delivery (callbacks/events) is a later slice (events design is
    #173's).
  - Builtin adapters: =search_server= resolves =config_loader:search_url/2=
    on the server engine and returns the URL as data (no shell, no browser);
    =timer_server= records into TimerService; =admin_restart= invokes an
    injected restart hook (host =RestartRuntime= submission; typed refusal
    when no hook). Memory adapters wait for memory intent frames (none
    shipped); tool/MCP stay available through the existing ToolRegistry /
    MCPManager where they are the chosen provider (LLM path) — no parallel
    registry, no dynamic capability facts this slice.
  - =build_api_service(config, restart_hook)=: creates =PrologEngine=
    (server_main.pl, located like main.pl), reads + validates registry
    facts (version match, known kinds, timeout bounds, duplicate ids ->
    typed errors), applies =disabled_providers=, registers builtin
    adapters.
  - =PlanExecutionService.execute(frame, *, principal, auths, request_id)=:
    builds =PlanEnvironment(principal, auths=auths, devices=(),
    providers=registry ids, aliases=(), policies=())= — server policy owns
    reachability; device advertisements are a client-advertisement concern
    (later slice); aliases ride future server alias config (no builtin
    provider carries ref(app_alias) arguments). Selection via
    =engine.plan_for_frame= in a worker thread; not-ready/None selections
    become typed REFUSED outcomes (=plan_not_ready= with status:reason in
    response; =selection_failed= when Prolog returns nothing); ready plans
    execute through =PlanExecutor= under =asyncio.wait_for(spec timeout)=:
    timeout -> =executor.track(request_id)= + REFUSED =adapter_timeout=
    (side effect may have landed; retry returns replayed — at-most-once
    preserved), cancellation -> track + re-raise =CancelledError=.

** D4. PlanExecutor dynamic resolution

** Adversarial review
- Attack 1 (device leak via user config): server scope asserts semantic
  facts only; device facts throw. Residual: server Prolog state holds
  =kb_config= semantic facts — all data, none executable; acceptable.
- Attack 2 (open_desktop registered on headless server): registry contains
  ONLY kb/server_providers.pl facts (search/timer/admin). open_desktop/
  screen_server/pause_server stay declared-but-unregistered: selection
  marks them unavailable; no adapter exists; double refusal layer.
- Attack 3 (timeout duplicates side effect): adapter keeps running after
  wait_for timeout; we track the request id on timeout so a retry replays
  instead of re-executing. adapter_failed still re-executes on retry —
  documented contract (adapters validate before acting); pinned by test.
- Attack 4 (registry race between snapshot and execute): executor resolves
  adapters live; an unregistered provider mid-flight yields typed
  =unknown_provider=, never a crash or stale adapter call.
- Attack 5 (restart during execution): admin hook submits RestartRuntime
  through host.submit (thread-safe); restart clears the service; in-flight
  executor work completes in its worker thread; replay window dies with
  the executor — accepted (bounded, documented; persistence is the envelope
  store's concern per #157).
- Attack 6 (kb/config.pl hook move breaks hermetic tests): tests that
  consulted kb/config.pl for user-config behavior already drive
  reload_user_config explicitly (t/prolog_config.pl); main.pl consults
  keep the desktop flow. Grep-verified consumers during implementation.
- Attack 7 (pyswip nested compounds): registry facts are flat arity-3 with
  scalars only; no lists, no dicts (Trealla-compatible for #172).
- Attack 8 (user config with ONLY device facts enables server):
  load_server_config throws on first device fact — loud, typed, and the
  host degrades plan service but stays healthy.

** Decision (recorded — Auto-RAGE)
Proceed as designed: three-way config split with loader scopes; versioned
host-owned api_service registry with builtin search/timer/admin adapters;
typed timeout/track semantics on the executor; config-gated RuntimeHost
wiring; server_main.pl boot; phase-2c gate. Rejected alternatives: dynamic
capability facts for tool providers (no consumer capability yet — YAGNI,
revisit when a capability warrants a tool-backed provider), server timer
firing events (#173 owns event design), gateway-facing plan command (#160
owns routing cutover).
