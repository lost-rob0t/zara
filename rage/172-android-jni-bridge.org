* Research
- #170 selected Trealla as the Android embedded runtime because upstream provides a small C99 embeddable runtime and Android support; Zara owns only a thin JNI boundary.
- The selected architecture explicitly rejects an Android-side second assistant/runtime authority. The JNI layer therefore exposes only init/evaluate/shutdown for the portable semantic core.
- Native library availability is a packaging fact, not something Kotlin may silently recover from. Missing/failed native loading must be surfaced as a typed failure to the existing runtime lifecycle.

* Design / adversarial review
- Introduce =NativeTreallaBridge= as the concrete implementation of the already-landed =TreallaBridge= contract.
- Isolate =System.loadLibrary= behind =NativeLibraryLoader= so JVM tests deterministically cover load ordering and failure without requiring an Android device.
- Isolate JNI externals behind =TreallaNativeApi=; production =JniTreallaNativeApi= owns the native symbols while tests use a fake API.
- Pin the library name to =zara_trealla= by default; reject blank overrides.
- Do not allow evaluation before successful native initialization; do not mark initialized when library loading or native init fails.
- Preserve native returned semantic terms byte-for-byte for the existing normalized comparator; the bridge must not introduce a second parser/normalizer.
- Shutdown is idempotent and clears readiness even when native shutdown throws.
