** Design

Smallest coherent fix — make the existing state machine tell the truth:

1. =ZaraWireException= gains =val code: String? = null=.
2. =ZaraTextClientActor= threads the server's protocol =code= into the
   exception at the hello and turn protocol-error sites.
3. =AndroidTextSessionController.submitTextInternal= treats a failed turn
   whose root cause is =ZaraWireException(code in {"handshake_required",
   "stale_session"})= exactly like a timeout: when =requestIsCurrent()=,
   call =connectionLost("server requires re-handshake (<code>)")=. The
   existing bounded reconnect (attempt backoff, generation fencing) then
   performs a fresh hello + capability negotiation.
4. The failed turn itself still surfaces its error to the caller once (no
   automatic turn replay; the server idempotency keys differ across
   sessions, so replay would not be a resume).

Invariants: only current-generation requests may invalidate the session;
non-session protocol errors (=invalid_message= etc.) stay per-turn errors;
reconnect stays bounded.

** Adversarial review

- Race: superseded-generation completions cannot clobber a newer session —
  guarded by =requestIsCurrent()= (same pattern as the timeout path).
- Retry storm: =handshake_required= is =retryable=True=; reconnect budget
  is the existing bounded scheduler; a hard-down server ends in
  =OfflineDegraded= as before.
- Echo/reject loops: re-hello happens at most once per =connectionLost=;
  =RuntimeEvent.ConnectionLost= dedupe already collapses duplicates.
- Non-goals: desktop client twin (#1353), full telemetry vocabulary
  (#1301), error-card UI truth (#1303).
