** Research
Complete. See =rage/260-hooks-prolog-config-research.org=.

The existing =modules/zara_hooks.pl= surface had no registry: =run_hook/2= dynamically constructed one predicate name, swallowed errors/failure, and the catch-all =before_reply/1= / =after_reply/1= clauses made ownership, ordering, removal, and inspection impossible. The existing =config_loader= already owns mutable XDG Prolog configuration, so this slice reuses that path instead of adding another config authority.

** Design
Complete for the bounded Prolog seam. See =rage/260-hooks-prolog-config-design.org=.

The typed interface is an owner-aware ordered registry:
- =register_hook(+Stage,+Owner,+Priority,+Goal,-RegistrationId)=
- =unregister_hook(+RegistrationId)=
- =clear_hook_owner(+Owner)=
- =list_hooks(-Hooks)=
- =run_hook(+Stage,+Event)=

Registration rejects unknown stages, malformed owners/priorities, and non-callable goals. Dispatch is priority-then-sequence ordered, snapshots registry state before invoking handlers, and isolates failure/exception per handler so later hooks still execute.

** Adversarial review finding
The first implementation shape auto-loads local =hooks.pl= during Prolog startup. Issue #260 also requires explicit =[hooks].enabled= and =[hooks].allow_override= policy gates. Even trusted mutable local code should not gain an un-gated startup execution path merely because the registry itself is correct.

Therefore the branch remained non-mergeable until canonical Zara config gated this loader (and later override/advice surfaces) without introducing a second config owner. This is a design/safety completion requirement, not a test waiver.

** Design update
The design now makes =config.toml= the sole policy source while keeping mutable =hooks.pl= / =config.pl= in the existing XDG user directory. The Prolog projection is intentionally limited to the =[hooks]= table's two booleans. Missing, malformed, or duplicate policy fails closed; unrelated TOML and secrets are never reflected into Prolog or logs. =allow_override=true= cannot by itself enable hook execution.

** Implementation
- =modules/hooks_loader.pl= now holds explicit fail-closed policy state and clears owner=user registrations when disabled.
- startup/reload derives =config.toml= beside canonical =config.pl=, reads only =[hooks].enabled= and =[hooks].allow_override=, and applies policy before any =hooks.pl= consult.
- =hooks.pl= remains mutable user-owned state: core does not create or overwrite it.
- no Python agent loop, second Prolog engine, Android code, shell privilege path, or plugin repository was added.
