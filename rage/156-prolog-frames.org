* Design (decisions)
- D1 :: New portable module =modules/intent_frames.pl= defining =resolve_frames(+Text, +State, +Context, -Frames)= as the only new public entry point. Pure: no assert/retract, no I/O, no dynamic goals from user strings. Reuses =normalizer= normalization + =kb_intents= verb tables (single verb authority, D6 of #154 design).
- D2 :: =frame_intent/3= projection: legacy =(Intent, Args)= -> =frame(intent(ns(NS),name(N)), Slots, Status)=. ns mapping: timer/alarm/lock etc -> device; open/launch -> app; text/message -> message; search/find -> web; hello/stop/ask-style -> conversation; python(Skill) -> skill; dictation -> dictation; play/pause etc -> media. Unknown verbs keep =resolve/4= behavior (no frame).
- D3 :: Slot schemas in Prolog =frame_slot_spec(Intent, SlotName, Type, Required)= for the shipped built-ins (timer.set: duration required, label optional; open: target ref(app_alias) required; text: contact ref(contact) + message text required; search: query text; schedule_todo: task text). Bare verb with unfilled required slots -> =missing([Names])= and prefilled slots keep values with origin(utterance) - bare "set a timer" becomes a typed missing-duration frame.
- D4 :: Context handling: =Context=[]= -> resolve from scratch. =partial_frame(Frame0, Missing)= -> the follow-up text is parsed for the FIRST missing slot's type only (duration/text/ref/number); unambiguous parse -> frame completes with origin(follow_up); invalid -> =invalid(SlotName, reason)=; ambiguity -> =ambiguous(Alternatives)=. Correction markers ("actually ...") -> origin(correction) on replaced slot.
- D5 :: Cancellation: stop/cancel phrases in context resolve to =frame(intent(ns(conversation),name(cancel)), [], complete)= and the open frame becomes superseded at the HOST layer (#155 already owns that; resolver only emits the cancel frame).
- D6 :: Compatibility boundary: =zara/prolog_engine.py= gains =resolve_frames()= returning a typed Python mirror (same shapes as zara/runtime/frames.py) and =adapt_frame_result=; =wake.py= pending branch migrates to frames when the resolver returns them, keeping the #155 templates as the dialogue schema. Legacy =resolve_intent= path stays for non-frame callers (console/command_loop) - isolated, not authoritative.
- D7 :: Corpus: =kb/corpus.pl= (or =planning/corpus.pl=) one case/6 table: =corpus_case(Id, Utterance, State, Context, ExpectedFrames, Tags)= covering the issue's minimum set (timer complete/pending/correction/cancel; open complete/pending; text complete/pending; search; memory; screenshot/device; unavailable; quoted/literal; question/conversation non-hijack; misspellings only via #122). Python driver =t/test_semantic_corpus.py= runs every case through PrologEngine on SWI and asserts normalized frame equality (evidence excluded per contract comparator rules).
- D8 :: Evidence: bounded =evidence(resolver, Steps)= derived from deterministic rule names only (verb_head, unit_normalization, slot_fill, correction_marker). No LLM internals.
- D9 :: Keep #122 upstream: rewritten text is input; resolver never accepts slot/provider names from rewrite metadata.

* Threat / failure analysis
- Dynamic goal injection :: resolver builds no goals from user strings; corpus case asserts =no dynamic goal= by construction (pure pattern matching only).
- Unbounded slot text :: literal slot content bounded (<= 512 chars at the compat boundary; corpus case pins it).
- Unicode regression :: corpus includes punctuation-heavy and non-ASCII cases with documented current-normalizer behavior (ASCII deletion remains the recorded defect; portable Unicode normalizer is #172/#122 follow-up, but corpus must not silently encode ASCII-deleted expectations as "correct").
- Determinism :: repeated corpus runs byte-identical (test asserts run-twice equality).
- Legacy fixtures :: existing intent fixtures keep passing through the compat boundary (documented mapping, no behavior fork).
- Precedence conflicts :: state_control phrases outrank verb frames (stop/end before anything); corpus pins precedence.

* Adversarial review
- "open firefox" with an app named "stop" -> state_control(passive,[stop|_]) only fires on verb-head stop; "open stop" keeps open frame. Corpus pins it.
- "set a timer for zero seconds" -> duration(0) is valid (non-negative); huge (> 7 days) -> invalid(value(duration), out_of_range). Corpus pins both.
- Empty/whitespace -> no frames (no crash).
- "text stop" -> contact ref "stop" - slot text containing command words must not hijack: frame slot is inert text/ref; corpus pins.
- Ambiguous verbs ("run" maps in kb to open and also schedule?) -> resolver picks deterministic first-match by verb_intent clause order; corpus pins.
- #122 rewrite upstream -> corpus includes a rewritten-input case where the rewrite only changes tokens, not slot authority.
