** Research
- =ZaraVoiceInteractionService.onShutdown()= only cancels when the shared manual voice state is already =Capturing=.
- =startAssistantVoice()= may reconnect asynchronously before calling =pressToTalk(true)=.
- Therefore service/role shutdown during an in-flight assistant start can occur before the shared state becomes =Capturing=; the late completion can then start capture after shutdown.
- =AssistantInvocationGate= already fences late UI-session starts after =onHide=, but the service shutdown lifecycle has no equivalent generation fence shared with the async start operation.

** Architecture / design
- Add one small Android assistant lifecycle fence with monotonically increasing generation.
- A start captures the current generation before asynchronous reconnect/start work.
- Service shutdown invalidates the generation before cancellation/role reassessment.
- A late start continuation must fail closed if its captured generation is stale, and if capture crossed the boundary concurrently it must issue the canonical existing cancel rather than leaving a recorder alive.
- Keep =AndroidAppSession= and =PushToTalkController= as the only voice/capture owners; this fence only authorizes whether an assistant-originated start may proceed.
- No second state machine, socket, recorder, daemon, or assistant runtime.

** Adversarial review
- A session-local fence is insufficient because =VoiceInteractionService.onShutdown()= must invalidate the same generation observed by an in-flight session start.
- A second reducer/AppSession lifecycle state machine would duplicate ownership, so the fence contains generation only and never owns recorder/socket/runtime state.
- The pre-capture token check alone has a race if shutdown occurs immediately after it. The post-start check closes that race and issues canonical cancel if capture crossed the boundary.
- Cleanup failure is not hidden: stale invalidation plus failed voice cancellation completes exceptionally with the cancellation root cause attached.
