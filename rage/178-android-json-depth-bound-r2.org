** Research
The Android text decoder already caps each text envelope at 64 KiB and rejects malformed UTF-8, duplicate keys, unknown fields/types, and oversized text. The private strict JSON parser is recursively implemented with no explicit container-nesting budget, so byte-bounded hostile JSON can still consume stack depth independently of envelope size.

** Design
Keep the existing strict parser. Add a maximum of 64 nested JSON containers, counted before descending into each object/array. Reject the 65th container with =ZaraWireException= at the parser boundary. Do not add another parser, relax schemas, or change valid canonical envelopes.
