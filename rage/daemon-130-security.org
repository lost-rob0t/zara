** Slice C boundary refinement

The red API assumption was deliberately challenged before production implementation. Remote authenticated service ownership is clearer as a distinct =SecureZaraZmqGateway= boundary rather than optional security parameters on the local-owner =ZaraZmqGateway=.

Reasons:
- local IPC remains an explicit local-owner policy and should not acquire ambiguous optional authentication knobs;
- TCP service construction becomes fail-closed by type/constructor: the secure gateway requires registry, server CURVE config, and security limits;
- CURVE/ZAP authenticator lifecycle is owned by the secure gateway's one ROUTER owner loop;
- #131 event-isolation work remains separate: the secure gateway does not subscribe a single static principal to runtime events;
- the underlying ZARA/1 framing/backpressure implementation remains reused rather than forked.

TDD consequence: update only the Slice C tests to target =SecureZaraZmqGateway=; prove the new boundary is red before creating that production class.
