This slice establishes the plaintext-free Core reference ABI, trusted-runtime
lease metadata contract, and outbound text redaction boundary. Persistent vault
backends, actual plaintext materialization, Prolog lifecycle operations, =#968=
bindings, Android/desktop storage, and provider migration remain later slices.

* ANALYZE
Zara already has environment/config provider keys, Android credential wrapping,
SmartThings token storage, MCP environment redaction, and provider-specific key
fields. They do not share one cross-platform reference/use vocabulary or one
streaming-safe outbound scrubber.

The first dependency for later vault adapters is therefore a small plaintext-free
identity/use contract plus deterministic leak prevention before known material
can leave a trusted boundary.

* DESIGN
** Public reference
#+begin_example
SecretRef
  id
  name
  scope
  owner
  kind
  revision
  generation
  configured
#+end_example

Printable aliases use =§§secret(NAME)=. Names are canonical uppercase ASCII
identifiers. Public projections contain metadata only.

** Runtime use context and lease
#+begin_example
SecretUseContext
  principal
  runtime_generation
  consumer
  purpose
  sink
  request_id?
#+end_example

Initial sink vocabulary: =http_header=, =request_body=, =environment=, =stdin=,
=file_descriptor=, =credential_callback=.

=SecretLease= is runtime-issued, closeable, non-pickleable/non-serializable and
contains only reference/revision/generation/use/expiry metadata. It contains no
plaintext/value/material field. Lease TTL is hard-bounded to five minutes.

=_issue= is an internal implementation seam, not a claim of same-process
cryptographic unforgeability. Concrete stores must revalidate current
scope/revision/generation/revocation/usage policy before future materialization.

The public =SecretStore= protocol contains no =get_secret_value= or =materialize=
method.

** Complete-value masking
Complete text is scanned once through the trie. Generated aliases are emitted to
output and never re-scanned as raw input. This avoids alias corruption when some
other secret material happens to match text inside =§§secret(...)=.

If multiple references map to identical raw material, output uses generic =***=
rather than guessing attribution.

Alias attribution is itself policy-sensitive. =SecretRedactor(...,
reveal_aliases=false)= replaces all known values with generic =***= so a context
can hide even the secret name/alias. Normal operator-facing contexts may keep
aliases enabled when attribution is safe.

Values shorter than the configured scan minimum are excluded from generic
substring scanning to avoid pathological over-redaction. Future typed secret
sinks must protect those structurally.

** Streaming matcher
A bounded trie performs leftmost-longest matching. Required semantics:

- incomplete candidate: hold from the first character;
- exact terminal with longer children: hold until disambiguated;
- exact terminal with no longer child: emit safe replacement;
- mismatch after a terminal: emit the longest terminal replacement, then
  classify the remainder;
- mismatch before any terminal: emit one proven-safe ordinary character;
- final unresolved non-terminal prefix: emit =***=;
- final prefix that already crossed a shorter terminal: emit the shorter safe
  alias plus =***= for the unresolved longer-secret suffix, never that suffix.

The final rule closes the =token-123-m= class when both =token-123= and
=token-123-more= are configured. The regression now exhausts every proper prefix
of the longer value, not only one representative truncation.

Resource inputs are bounded by =max_secret_count=, =max_secret_length=, and
=max_total_secret_chars=.

* ADVERSARIAL REVIEW
Pinned coverage includes:

- malformed alias/name rejection;
- plaintext-free public reference/use projections;
- bool-vs-int revision/generation confusion;
- control-character rejection in use metadata;
- runtime-only lease construction;
- finite five-minute-bounded lease TTL, expiry and close;
- lease pickle/serialization rejection and safe repr;
- no plaintext/material attribute on lease;
- no public store getter/materializer;
- contained/overlapping values;
- duplicate material ambiguity;
- generated alias not reprocessed;
- explicit generic redaction mode hiding alias names;
- every two-chunk split boundary;
- one-character chunking and prefix withholding;
- exact short secret that may extend to a longer secret;
- disproof of longer candidate;
- every EOF truncation during a longer candidate after a shorter terminal;
- unresolved prefix at EOF;
- bounded count/value/aggregate material;
- intentional short-value scan exclusion.

Rejected approaches:

- global alias expansion in arbitrary text;
- public plaintext getters;
- serializable leases;
- minimum-trigger streaming filters that leak early prefix bytes;
- eager short-secret replacement when a longer secret shares the prefix;
- sequential =str.replace= that reprocesses generated aliases;
- reclassifying an unresolved longer-secret suffix as ordinary text at EOF;
- always revealing aliases even in privacy-sensitive output;
- unbounded configured secret sets.

* DECISION
Keep #1027 focused on Core aliases/references/use context/leases/redaction. Do not
add persistent storage or plaintext materialization here.

Next #1026 slices are now tracked separately:
- #1030 Android Keystore/noBackup =SecretStore=;
- #1031 Linux Secret Service/headless =SecretStore=.

Runtime materialization remains a separate trusted sink boundary and is never
added to the public =SecretStore= protocol.

No merge/release claim is made by this note. Exact-head CI and current Zara
review/governance remain authoritative.
