This slice establishes the plaintext-free Core reference ABI, trusted-runtime
lease metadata contract, and outbound text redaction boundary. Persistent vault
backends, actual plaintext materialization, Prolog lifecycle operations, =#968=
bindings, Android/desktop storage, and provider migration remain later slices.

* ANALYZE
Zara currently has several credential mechanisms: environment/config provider
keys, Android credential wrapping, SmartThings token storage, MCP environment
redaction, and provider-specific API-key fields. They do not yet share one
cross-platform secret reference, one runtime use-context/lease vocabulary, or
one streaming-safe outbound scrubber.

The first dependency for every later secret-store adapter is therefore a tiny
language-neutral identity/presentation contract, a plaintext-free lease that can
bind one authorized use, and a deterministic way to prevent already-known
material from escaping through normal text and chunked output.

* DESIGN
** Public reference

#+begin_example
SecretRef
  id
  name
  scope
  owner
  kind
  revision
  generation
  configured
#+end_example

The printable representation is =§§secret(NAME)=. Names are canonical uppercase
ASCII identifiers. =SecretRef.to_public_dict()= contains metadata only.

** Runtime use context and lease

A request to use a secret is described without material:

#+begin_example
SecretUseContext
  principal
  runtime_generation
  consumer
  purpose
  sink
  request_id?
#+end_example

Initial reviewed sink vocabulary is =http_header=, =request_body=, =environment=,
=stdin=, =file_descriptor=, and =credential_callback=.

=SecretLease= is runtime-issued, short-lived, closeable, and explicitly
non-pickleable/non-serializable. It records only secret identity/revision/
generation plus use context and expiry. It has no plaintext/value/material
field. Its constructor rejects ordinary direct construction; =_issue= is an
internal implementation seam, not a claim of same-process cryptographic
unforgeability. Concrete stores must revalidate live revocation/generation state
before future materialization.

The public =SecretStore= protocol deliberately contains no =get_secret_value=
or =materialize= method.

** Complete-value masking
Complete-text masking uses the same trie matcher as streaming but keeps a final
ordinary suffix that merely resembles an incomplete secret prefix. Generated
aliases are emitted directly to output and are never re-scanned as raw input,
preventing alias corruption when another configured value happens to match text
inside =§§secret(...)=.

If two refs resolve to identical raw material, outbound text uses generic =***=
instead of guessing which alias to attribute.

Automatic free-text scanning excludes values shorter than the configured
minimum length. Those values must later be protected structurally by typed
secret objects/sinks rather than substring replacement.

** Streaming matcher
A simple "replace complete values, then retain a suffix" implementation is not
strong enough. Two adversarial cases matter:

1. a chunk can end after only one character of a secret; emitting that character
   leaks a raw prefix;
2. one secret may be a prefix of another. If =token-123= and
   =token-123-more= are both known, a chunk ending exactly after =token-123=
   cannot safely emit the short alias yet.

Decision: build a bounded trie of scannable raw values and keep the earliest
unresolved raw prefix in the streaming filter. The matcher is leftmost-longest
for candidates sharing a start position:

- incomplete prefix: hold;
- exact terminal with longer children: hold until disambiguated;
- exact terminal with no longer child: emit safe replacement;
- mismatch after a terminal: emit the longest terminal replacement then
  re-evaluate the remainder;
- mismatch before any terminal: emit one proven-safe ordinary character;
- final unresolved non-terminal stream prefix: emit =***=, never raw text.

Lookup/memory inputs are bounded by:

- =max_secret_count=;
- =max_secret_length=;
- =max_total_secret_chars=.

* ADVERSARIAL REVIEW
Pinned tests cover:

- malformed alias/name rejection;
- no plaintext field in public SecretRef projection;
- bool-vs-int revision/generation confusion;
- bounded/control-character-free use-context metadata;
- runtime-only lease construction;
- lease expiry/close fail-closed behavior;
- lease pickle/serialization rejection and safe repr;
- =SecretStore= has no plaintext getter/materializer;
- contained/overlapping value ordering;
- generated alias output is never reprocessed as raw material;
- complete-text incomplete-prefix handling;
- identical material mapped to multiple refs;
- secret split across arbitrary two-chunk boundaries;
- one-character chunking;
- one-character prefix withholding;
- unresolved prefix at end-of-stream;
- exact short secret that can extend to a longer configured secret;
- disproof of the longer candidate;
- bounded secret count/value/aggregate material;
- redactor repr leakage;
- intentional short-value free-text exclusion.

Rejected approaches:

- global alias expansion in arbitrary text: aliases from model/chat content must
  remain inert;
- public plaintext getter on =SecretStore=: makes the safe ABI itself an
  exfiltration primitive;
- serializable leases: risks accidental transit through events/history/IPC;
- eager exact-match replacement in streams: fails prefix-of-longer case;
- minimum-prefix withholding for long secrets: leaks 1..N-1 raw characters at
  unlucky chunk boundaries;
- sequential =str.replace= over generated aliases: can corrupt alias identity;
- unbounded list scanning: creates avoidable resource-pressure attack surface.
