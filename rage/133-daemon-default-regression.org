** Regression
- Issue #133 was completed historically, but exact current master still routes ordinary =zara <command>= through =ZaraConsole()= unless =--connect= is explicit.
- This violates the daemon-capable default contract and can make one-shot timers process-owned rather than daemon-owned.
- Stale PR #223 contains prior art for this behavior but is non-mergeable and 27 files wide; it will not be replayed wholesale.

** Research / ownership
- =zara/__main__.py= already has a bounded =_run_connected_text/= path using =ZmqZaraClient= and keeps =--standalone= as an explicit compatibility path.
- The smallest recovery should reuse that client boundary, preserve explicit =--connect= and =--standalone= behavior, and never silently fall back to a private runtime when the daemon is unavailable.
- Timer ownership remains daemon/runtime-owned; this slice changes client routing, not timer storage or the todo subsystem.
- Android production is out of scope.

** TDD plan
1. Add a deterministic regression proving an ordinary timer command selects the daemon client path and never constructs =ZaraConsole=.
2. Prove RED on the exact test-only head in GitHub Actions.
3. Only after RED, implement the minimum endpoint/default routing change required by the test.
4. Preserve explicit standalone behavior and bounded daemon failure behavior.
5. Run focused client migration tests, =scripts/test-all.sh=, =nix flake check=, package/build gates, then exact-head Actions before merge.

** Invariants
- One daemon/runtime brain for the default supported command path.
- =--standalone= remains explicit and never becomes an implicit failure fallback.
- No second timer store or todo store.
- No Android production changes.
- No merge from stale/pending/failing/inconclusive CI.
