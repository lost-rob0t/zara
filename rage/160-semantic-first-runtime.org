- Trigger :: live operator regression on 2026-09-06:
  =zara set a timer for 2 hours= printed an unrelated AMD STT routing notice, then reached the LLM, which refused because timer capability was not wired into that model session.

* Research / observed root causes
1. =zara/__main__.py= resolves STT provider/device/model immediately after argparse for every mode. A text-only CLI turn therefore emits the AMD/Vulkan STT notice even though no microphone/STT path is entered.
2. =RuntimeSupervisor= supplies =PrologFirstRouter= to =AgentRuntimeBackend= when Prolog starts successfully, but =LangGraphRuntimeBackend.submit_turn= has no fail-closed policy for command-shaped input when the router is absent.
3. =PrologFirstRouter= is intentionally allowed to return =delegate= for unresolved/error paths. The backend previously interpreted every delegate as permission to run =AgentManager.process_async=, including text that the command gate had already identified as deterministic command input.
4. Timer parsing/execution itself already exists and is tested:
   - =modules/intent_resolver.pl= parses =set a timer for 2 hours= to =timer [7200,'']=.
   - =modules/commands.pl= dispatches timer to =alarm:start_timer/2=.
   - =modules/alarm.pl= owns the SWI alarm scheduler and completion notification.
   - =t/timers.pl= proves scheduling/completion through fakes.
   Duplicating another timer scheduler here would be the wrong fix.
5. #158's =TimerService= is not an immediate replacement for the legacy firing path: its documented scope records/due-tracks timers while firing delivery was explicitly deferred. The current regression must preserve the working alarm notification implementation until the typed service owns delivery.

* Decisions
- D1 :: Deterministic-first is enforced by runtime code, not by the LLM prompt.
- D2 :: A missing semantic router or deterministic delegate/failure is *not* implicit permission to call the model for command-shaped input.
- D3 :: Ordinary conversational text still delegates to the model.
- D4 :: Do not add a second timer parser/scheduler. Complete timer commands continue through the existing Prolog resolver/executor/alarm implementation.
- D5 :: STT initialization is lazy by mode. Only =--dictate= and =--wake= resolve STT provider/device/model; typed CLI commands, desktop, console, pets, and explicit agent mode do not emit STT routing notices merely because STT is configured.
- D6 :: Preserve task-turn behavior (explicit =conversation_history= / =system_context=) because those calls are intentionally agent/task execution, not the ordinary user command ingress owned by this regression.

* Implementation
- Runtime backend now gates command-shaped turns before model invocation:
  - no router -> deterministic-unavailable response;
  - router delegate/failure for command-shaped text -> deterministic-failed response;
  - non-command conversational input remains model fallback.
- CLI STT provider/device/model resolution moved behind the actual =--dictate= and =--wake= branches.
