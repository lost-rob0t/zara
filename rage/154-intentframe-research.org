** Verified structural findings
1. Dead sixth: kb/config.kb declares kb_user_intents but nothing loads or queries it (its double-quoted surface "bro" would also fail config_loader's atom(Surface) validation, and "bro" is a filler token anyway).
2. pending/1 is a return shape, not state :: missing_slots/3 (intent_resolver.pl:66-73) recomputes per utterance; nobody asserts/retracts pending state; no slot-fill loop exists. Clarification prompt generated in Python (wake.py:971-976 "Please provide: {required}."); the next utterance is re-resolved from scratch, so a bare slot answer ("firefox") can never complete the intent.

** External primary-source research
- Alexa IntentRequest + slots (developer.amazon.com, Dialog Interface Reference + Define the Dialog, accessed 2026-08-30) :: intent object = {name, confirmationStatus NONE|CONFIRMED|DENIED, slots map {name -> {value, confirmationStatus}}}; dialog directives = Dialog.Delegate / ElicitSlot(slotToElicit, updatedIntent) / ConfirmSlot / ConfirmIntent; the service owns the dialog model (delegationStrategy SKILL_RESPONSE vs ALWAYS); updatedIntent is how a follow-up replaces the in-progress intent. This validates: typed slot maps + explicit dialogue statuses + host-owned clarification with frame replacement (supersedes) as the composition mechanism, and that the *slot map*, not positional args, is the durable representation.
- Dialogflow session parameters (conceptual comparison; primary docs not fetched this pass) :: session-scoped parameter map owned by the session, not by the NLU call - corroborates "pending-dialogue state lives with the conversation owner, not the resolver".
- Rasa/assistant literature (general) :: slot events + active-loop state owned by the tracker, not the NLU - same ownership conclusion.
- Trealla dicts :: SWI dict docs describe dicts as SWI-native; Trealla 2.106.1 empirically rejects the dict syntax (nix shell trealla, catch((X = a{b:1}), _, fail) -> syntax error). Contract therefore uses plain compounds + lists only. SWI reads the same terms unchanged.

** Research questions -> answers (each grounded above)
1. Minimum typed semantic representation working in Prolog/Python/wire/Android Prolog :: frame/3 compounds + tagged typed slot values (contract section 2-3); no dicts; one serializer.
2. Semantic facts vs correlation metadata :: the "same words, same user, same conversation" test; frame_id/turn/conversation/principal/trace live in the envelope only.
3. Typed slots without serializing arbitrary objects :: closed tagged value set (text/number/duration/datetime/ref/boolean); ref for aliases; never raw compound dumps across the boundary (fixes _compound_parts fragility by construction).
4. Ambiguity/invalid/missing/correction/cancellation composition :: status algebra + clarification session contract (contract section 4); correction = new frame with origin(correction) + envelope supersedes; cancellation emits conversation.end/cancelled and never executes.
5. Where pending-dialogue state lives :: conversation-scoped clarification session owned by the runtime host (TurnCoordinator side), keyed by conversation_id; Prolog resolves purely with Context; prompts generated from missing lists. Nothing global, nothing prompt-managed, nothing in a Prolog dynamic DB.
6. Portable across runtimes :: compounds+lists core (Trealla-verified), Unicode-safe normalization required (current ASCII tokenizer is a verified defect), single term<->JSON serializer, same fixture corpus both runtimes (#172 gate).
7. Resolver evidence without hidden model reasoning :: evidence.steps from deterministic resolver rules (verb head, unit normalization, object-word refinement, capability explain/4 from #119 prior art); LLM internals excluded by contract.
8. #122 feeding without authority :: rewritten text is resolver *input*; frames record evidence only; no rewrite dict survives into slots.
9. What disappears :: prompt verb list (generated from KB), raw query_prolog tool (typed resolve_frames only), Prolog-internal LLM rewrite + ask HTTP calls, Prolog process_create for apps (adapters/platform providers own execution), duplicate reply phrase tables vs Python strings (single reply path per surface).

** Adversarial review (counterexamples the contract must survive)
- Stale follow-up :: a late "2 minutes" after the clarification session closed must not silently attach - context(partial_frame) is minted per open session; the host rejects frames referencing closed/superseded sessions (turn-state gate mirrors actors.py stale-event rejection).
- Concurrent turns in one conversation :: TurnCoordinator already serializes turns per conversation; clarification sessions are per-conversation singletons - two concurrent submits cannot both hold the open frame; second one either queues or is rejected as stale.
- Cross-principal leakage :: clarification sessions are principal-scoped like conversations; frame slots never carry principal data by contract.
- Prompt injection via slots :: slot text is inert text(A) by contract; adapters validate typed values; no adapter may eval/execute slot content (extends #194's "no arbitrary Intent plane").
- Replay/idempotency of side effects :: side-effectful frames execute at most once per request_id in the envelope; the frame itself is not an idempotency key.
- Portability divergence (parser drift) :: same corpus, same normalizer core, single serializer, comparator excludes evidence - divergence allowed only as explicit platform-provider difference (contract example 13), never as silent parse drift; #172 CI gates equivalence on SWI and Trealla.
- kb/config.kb zombie authority :: deletion is part of the migration (design artifact); keeping an unloaded "user override" file would be a second hidden authority.
- Prompt-injection through AgentManager :: the prompt verb list and raw query tool disappear; the agent consumes frames/events, not raw goals (migration).

* Decision record (Auto-RAGE decision gate, 2026-08-30)
- Freeze IntentFrame v1 exactly as docs/intentframe-contract.md; implement in #155 (host-owned clarification sessions + typed slots), #156 (Prolog adaptation + corpus on the portable subset), #157 (capability reasoning to ExecutionPlans), #172 (portable core + dual-runtime fixtures).
- Reject: raw positional args lists (no types, the proven source of pending/1 fragility); arbitrary JSON bodies on the wire (unbounded schema, no validation anchor); prompt-managed clarification (LLM-owned state - unverifiable, already contradicted by the daemon path having no prompt authority); a global pending command store (hidden mutable state, cross-conversation leakage); direct shell/provider strings in slots (breaks platform parity and the security invariants).
- No production implementation in this slice: docs + planning changes only, per the issue's acceptance rule.
