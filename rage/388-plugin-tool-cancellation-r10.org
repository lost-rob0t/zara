* Selected architecture
Core manually inserts a runtime-only cancellation value into the exact approved tool call immediately before invoking the existing canonical ToolNode. The plugin-facing annotation is LangChain's model-hidden InjectedToolArg marker; Core overwrites any model-supplied =cancellation= value with its own exact-invocation read-only ToolCancellation view. ToolNode remains the sole executor.

The injection helper only opts a tool in when its full input schema contains =cancellation= while its model-facing =tool_call_schema= does not. This keeps ordinary tool arguments untouched and makes the hidden/runtime boundary explicit and testable.

* Invariants
- Approval and current tool binding are verified before Core allocates the cancellation signal.
- One ToolNode; no direct BaseTool executor, no ContextVar, no InjectedState, no plugin-specific side channel.
- Runtime value is exact-invocation Core state and read-only to plugin code.
- Model cannot expose, suppress, or retarget the value; Core overwrites spoofed cancellation args.
- Signal is set before owned execution cancellation reaches async tool code.
- Terminal lifecycle remains one ToolCancelled(reason="turn cancelled") event.
- Concurrent invocations receive different signals.
- Unloaded/rejected tools never receive a signal or execute.
