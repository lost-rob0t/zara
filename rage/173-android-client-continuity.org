* Design boundary
- Android remains a client of the one Zara daemon/runtime; no local LLM, server, conversation database or memory authority is added.
- Enrollment material from #322 remains the sole CURVE identity/pin authority.
- One Android runtime reducer owns connection/session state rendered by future Compose surfaces.
- A successful TCP/CURVE socket alone is not =Connected=: only canonical =hello.ok= for the current generation may establish an application session.
- Reconnect creates a new transport/application generation. Old-session events/replies are rejected rather than applied to current state.
- Durable conversation identity is retained separately from ephemeral ZARA/1 session identity; no invented =session.resume= message.
- Endpoint configuration is public metadata and must never contain embedded user-info credentials or client private material.

* Invariants / adversarial cases
- wrong/missing pin, missing/corrupt credential and socket auth failure never downgrade to plaintext;
- malformed/oversized/wrong-magic/unknown message input fails closed;
- duplicate reply cannot complete two requests;
- stale generation/session response/event cannot mutate current conversation/runtime state;
- reconnect attempts and pending requests are bounded;
- no transcript, private key, token or raw credential enters diagnostics;
- process recreation may restore public server profile + durable conversation id, never fabricate a live session.
