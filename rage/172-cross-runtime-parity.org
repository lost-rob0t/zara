* Research
- The Android app now packages the canonical resolver sources and exposes =resolve_frames/4= through the Trealla entrypoint, but =SemanticFixtureRunner= still accepts abstract =SemanticRuntime= implementations and therefore cannot by itself prove SWI-versus-Trealla execution.
- Initial research treated =android/app/src/main/assets/prolog/portable/semantic_fixtures.json= as the executable corpus. Source audit corrected that assumption: the JSON declares =scope: portable-packaging-seed= and contains only seven seed cases. The authoritative realistic corpus is =kb/semantic_corpus.pl= from #156.
- =kb/semantic_corpus.pl= already covers complete/pending timers, numeric boundaries, dialogue follow-up/correction/ambiguity, open/text/search/device/media intents, cancellation/state precedence, empty/unknown input, injection-like text, and the currently pinned Unicode behavior. Final parity must execute that corpus, not relabel the packaging seed as acceptance coverage.
- Android pins Trealla source revision =b25ccfb8e485a697bb47f1947d6fb8e0ad4e6aaf= in =android/flake.nix=. The parity gate executes that exact source, not an unrelated host Trealla version.
- SWI remains the server reference runtime. Both runtimes consult the same canonical resolver dependency set and serialize ground portable frame terms canonically.
- Host execution of the exact pinned Trealla engine is the deterministic CI semantic-engine surface; JNI/ABI/APK packaging is proven separately by the Android native gate. Hardware/lifecycle claims remain #178/#179.
- Trealla's pinned CLI supports ordered file consultation and =-g/--goal= evaluation; its GNUmakefile has a deterministic native =tpl= target. The gate builds a writable temporary copy of the immutable Nix-pinned source.

* Architecture / design
- =scripts/test-android-semantic-parity.sh= is invoked by =scripts/test-android.sh=.
- Build host =tpl= from exact =ZARA_TREALLA_SOURCE_DIR= with SSL/FFI/thread/network/TTY extras disabled because they are irrelevant to the portable semantic core; no network fetch.
- Stage =semantic_core.pl= plus canonical =modules/intent_frames.pl=, =modules/normalizer.pl=, =kb/intents.pl=, and =kb/semantic_corpus.pl= in the same relative layout consumed by Android Trealla.
- A small temporary Prolog driver enumerates every =corpus_case/6=, rejects duplicate/empty case sets, calls =resolve_frames/4= with each case's real State and Context, normalizes actual and expected frames, and hard-fails any corpus mismatch.
- Run that same driver under SWI and pinned Trealla. Each engine must independently satisfy the expected corpus, then their canonical output files must be byte-equivalent.
- Missing runtime/source, consult/parse/runtime failure, corpus mismatch, duplicate ids, empty corpus, or cross-engine divergence fails closed.
- Keep this gate Android-only. No Python daemon/runtime, desktop, config, or protocol files are changed.

* Adversarial review
- Both runtimes must execute; fixture text alone is not evidence.
- Both runtimes must independently match expected frames so identical shared regressions cannot false-green.
- Pin Trealla through existing Nix input; no curl/wget/git clone/moving input.
- Temporary build/stage/output state is removed on exit.
- Output contains only synthetic checked-in corpus results; secrets/user state/provider data are never involved.
- Headless semantic execution must not pull in terminal edit/history libraries. =NOTTY= selects Trealla's =history_none.o= path; =NONETWORK= selects no-network objects. These are build-surface reductions only and do not alter resolver semantics under test.
- This proves shared Prolog semantic-engine parity. Android process/JNI lifecycle, concurrency/resource bounds, protocol security, and device behavior remain with their owning gates.
