** Research
- =AgentManager.process_async()= currently invokes =run_conversation_loop= directly through the already-landed =AgentLoopAdviceRegistry=.
- =[agent]= config has no backend selector in the shipped default config.
- The #260 contract explicitly requires a pluggable =[agent].backend= resolved from a loop registry while preserving one runtime, approval controller, cancellation chain, history persistence, latency trace, and max-step bound.
- The loop replacement boundary must sit underneath existing advice so before/after/around/override semantics remain stable regardless of selected backend.
- Backend lookup must be deterministic and fail closed for unknown names; silently falling back to LangGraph would hide configuration errors.

** Architecture / design
*** Selected boundary
- Add =AgentLoopRegistry= under =zara/agent/=.
- The registry owns named async loop callables and deterministic owner metadata.
- Seed exactly one built-in backend, =langgraph=, bound to the existing =run_conversation_loop=.
- =AgentManager= reads =[agent].backend= once per turn, resolves the named loop, then invokes that resolved loop through the existing advice registry.
- Add narrow registration/unregistration methods on =AgentManager= so later user-hook/service-plugin slices can register replacements without reaching into private state.
- Add =backend = "langgraph"= to the default configuration.

*** Rejected alternatives
- Conditional =if backend == ...= branches in =process_async=: not extensible and recreates command-specific hacks.
- A second AgentManager/runtime per backend: violates the one-runtime invariant and forks approvals/history/cancellation.
- Let unknown backends silently fall back to LangGraph: unsafe configuration ambiguity.
- Move backend selection into advice: advice wraps behavior; backend identity is a lower-level implementation choice and must remain independently diagnosable.

*** Invariants
- One AgentManager, one approval controller, one conversation manager, one tool registry.
- Existing advice wraps the selected backend rather than being bypassed.
- Backends receive the same state and keyword contract as =run_conversation_loop=.
- No Android files, no second agent framework, no new dependency.

*** Acceptance criteria -> tests
1. Registry resolves the built-in =langgraph= backend and exposes deterministic owner/name metadata.
2. Duplicate names are rejected unless replacing the same owner's registration explicitly.
3. Unregister is owner-safe and cannot remove another owner's backend.
4. Unknown backend resolution raises a bounded explicit error.
5. =AgentManager.process_async()= invokes the configured named backend through the existing advice seam.
6. Default config declares =backend = "langgraph"=.
