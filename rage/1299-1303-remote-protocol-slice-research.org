* Transport truth

The Android remote client is **JeroMQ (ZeroMQ) DEALER over tcp:// with CURVE**,
custom =ZARA/1= multipart framing. No WebSocket/HTTP/gRPC. Owner of connection
lifecycle: =ZaraTextClientActor= (single-thread executor, one dealer).
Connection state machine: =RuntimeState.ServerConnection= reduced by
=AndroidTextSessionController=. Generation fencing exists (generation bumps on
connect/reconnect/trust change; requests carry (generation, sessionId)).

* Root cause of the incident (code-proven)

1. *Legal server frames are rejected by the Android codecs.*
   =zara/protocol_runtime.py:199,207= emits =voice.speech.started=
   (=pre_speech_samples= body) and =voice.speech.ended= (=reason= body) for
   every server voice turn; =zara/protocol.py:69-81= also declares
   =runtime.error=, =runtime.stopped=, =turn.cancelled= as legal server types.
   Android =ZaraVoiceStreamCodec.kt:148= throws =unsupported voice stream
   event type= for the speech markers, and =ZaraTextCodec.kt:252= throws
   =unsupported server text message type= for the runtime/turn-cancel frames.
   → If a marker interleaves with a voice command reply, the voice command
   fails (=protocol_error= card); if it arrives in the post-commit pump, the
   pump dies.
2. *Pump death leaves fake-connected state.*
   =ZaraTextClientActor.pollVoiceEvents= (437-445) catches =Throwable=, sets
   =voicePumpActive=false=, notifies =voiceStreamFailureObserver=, returns.
   Controller state stays =Connected=; no =connectionLost=; no reconnect; no
   diagnostics event. The only production =connectionLost= trigger is a text
   request timeout (=AndroidTextSessionController.kt:120-127=).
3. *Failure detail is discarded.*
   =TextServerMessage.ProtocolError(code, message, retryable)= is decoded
   (ZaraTextCodec.kt:241-251) but =ZaraTextClientActor.kt:188,268= keep only
   the code inside a message string; =UiOperationFailure.kt:27= collapses every
   =ZaraWireException= to =protocol_error= and everything unmatched (e.g.
   Remote-mode fast-fail =IllegalStateException=, =AndroidAppSession.kt:464-467=)
   to =operation_failed=.
4. *UI duplicates the collapse.*
   =MainActivity.kt:326-333= writes both =operationError= banner
   (=ZaraApp.kt:911=) and =conversationStore.failTurn(...)= (error card) with
   the same umbrella token.
5. *Footer lies.*
   =ZaraApp.kt:843-846,927-939=: =remoteReady= ignores =runtimeMode= and every
   non-Connected transport state; failures are masked by the LOCAL fallback
   line while =REMOTE • AUTHENTICATED • SYMBOLIC= stays up whenever
   Connected+enrolled even if requests fail.
6. *No restore after process recreation.*
   =AndroidAppSession.init= restores the persisted profile but never
   reconnects; after =session.init= the client is disconnected with no typed
   event (=session.init → remote_connected=false= with nothing between).
7. *Telemetry gap.*
   =LocalRuntimeDiagnostics= records only startup/submission events; no
   connect/disconnect/reconnect/handshake/voice-stage/protocol events exist.
   =ZARA-LOCAL-DIAGNOSTICS/1= is a flat snapshot with no failure block.

* Alternatives considered and rejected

- *Proxy-based failure injection (client ↔ fault proxy ↔ real server).* More
  moving parts, cannot inject application-level ZARA/1 semantic faults
  (version mismatch, out-of-order) without reimplementing the codec anyway.
  → a dedicated scriptable ZARA/1 CURVE fixture server wins.
- *Treat every decode error as fatal connection loss.* Over-broad: a rejected
  frame for an unrelated stale request should fail that request, not tear the
  session. → typed classification: frame-class errors fatal to session
  desync (malformed/unsupported/out-of-order/stale), request-class errors
  fail the request; transport-class errors always collapse the connection.
- *New instrumented androidTest stack (Espresso/Compose-test).* Repo has zero
  androidTest and no deps; established real-app-path pattern is installed APK
  + adb/uiautomator python. → extend the python device acceptance.

* Voice turn on device feasibility

Manual voice = press-and-hold mic (onStartVoice → pressToTalk) → release
(onStopVoice → commit). =adb shell input swipe x y x y <ms= is a deterministic
long-press. Emulator mic yields silence PCM; the fixture scripts transcript +
audio output regardless of audio content, so a real capture→STT→submit→
response→TTS→playback turn is exercisable through the real APK.
