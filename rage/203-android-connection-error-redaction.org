#+title: RAGE #203 — redact Android connection failures before reducer state
#+status: ACTIVE

* Consumption
- Issue :: #203
- Immutable/current canonical start :: 0a370079f2bf293b320ea72865239e6ee4c08a73
- Scope :: Android text-client runtime only. No Core/protocol/plugin changes.

* Failure analysis
- =AndroidTextSessionController.connectGeneration= copied =Throwable.message= into =RuntimeEvent.ConnectionFailed=.
- After bounded reconnect exhaustion, the reducer stores that string in =ServerConnection.OfflineDegraded.reason=.
- Compose renders the reason in the human-facing connection label, so transport/provider exceptions could expose private endpoints, paths, tokens, or implementation detail despite UI exception redaction.

* Design
- Sanitize connection exceptions before they enter canonical reducer state.
- Stable reasons are =permission_denied=, =network_error=, and =connection_failed=.
- Traverse causes at most eight levels with identity-based cycle detection and never inspect or return =Throwable.message=.
- Preserve application-authored lifecycle reasons such as =text request timed out= passed through =connectionLost=; only exception-derived connect failures are classified here.

* TDD
- RED tests require adversarial secret-bearing exception messages to disappear, stable categories, nested-network classification, and a source contract forbidding direct =error.message= reducer injection.
- GREEN adds =ConnectionFailureReason= and routes connect failures through it.
