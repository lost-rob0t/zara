* Iteration 1
** Regression discovery
- Current =modules/commands.pl:open_app/1= checks =app_mapping/2=, then =direct_app/1=, then falls through to =launch_process(AppName, [])= for every unknown atom.
- =launch_process/2= passes a bare atom through =path(Executable)=, so an unregistered speech/user-supplied app token is still executable authority.
- This is not shell interpolation, but it bypasses the reviewed app mapping/direct-app boundary and violates the current closed typed-capability invariant.
- Existing process-safety issue #13 is therefore reopened rather than creating a duplicate issue.
- Sibling Android PR #307 is draft and its exact-head CI is cancelled; this branch does not touch =android/**= or #159 protocol work.

** Design / adversarial decision
- Unknown app identifiers must fail closed and must never reach =process_create/3=.
- Preserve configured =app_mapping/2= and explicit =direct_app/1= as the legacy Linux allow-listed compatibility surface until RuntimeHost/device capability migration replaces it.
- Do not add guessed app names, PATH discovery, shell fallback, or a new execution registry in this regression repair.
- Keep literal argument boundaries and launch-status verification unchanged for allowed mappings.

** TDD target
- Add deterministic coverage proving an unknown app is rejected before process launch.
- Preserve positive coverage for an allow-listed direct app and a configured argv mapping.
