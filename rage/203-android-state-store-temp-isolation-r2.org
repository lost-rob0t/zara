* Recovery

* Failure analysis
- The app and VoiceInteraction service can run in separate Android processes while sharing noBackupFilesDir.
- ClientStateStore.save used one fixed sibling .client-state.bin.tmp for every writer.
- Concurrent writers or a killed process leaving that path unusable could make a later save fail before the existing atomic replace step.

* Design
- Create a unique sibling temp file for every save with Files.createTempFile.
- Keep fsync-before-replace and atomic-move-with-safe-fallback semantics unchanged.
- Delete only the temp file created by this save.
- This removes fixed-temp ownership collisions; it does not claim semantic multi-writer merge/last-writer conflict resolution.
