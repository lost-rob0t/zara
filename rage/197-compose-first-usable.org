* Design
- Use one =ComponentActivity= and one Material 3 Compose tree.
- Preserve =ClientStateStore= restoration and =AndroidEnrollmentRepository= projection before composition.
- Navigation is local presentation state only; runtime/auth/session data stays in =RuntimeState=.
- First milestone surfaces are Chat, Connection, Settings and Diagnostics. Voice/tasks/calendar/devices/integrations remain subsequent issue slices.
- Chat remains explicitly unavailable unless the canonical reducer says Connected and enrollment says Ready. No fake assistant response or fake connected state.
- Diagnostics always show exact =BuildConfig.SOURCE_SHA= and non-secret reducer metadata only.

* Adversarial review
- Rejected a UI-owned connection Boolean: would split authority from the reducer.
- Rejected placeholder chat replies: would violate the first-usable product gate.
- Rejected copying endpoint/session into Compose persistence: durable client state already has a single owner.
- Rejected displaying key material: diagnostics may expose source/session/correlation metadata, never credentials.

** Reducer-driven UI
- Adversarial review found a truth gap: reconnect side effects can advance the reducer after the initiating button future returns, so polling state only from UI callbacks could leave Compose displaying stale Connected state.
- =03f052af3797d30f7533fb470c6fc7ff1d488409= adds one controller state observer and publishes immutable reducer snapshots after connection, reconnect, enrollment and conversation mutations, outside the controller lock.
- =92c8b2d3dd19787278a0f1c6d7944c121c11d9ec= exposes that observer through =AndroidAppSession=.
- =212defc49e5adbbacb672fa11f3daa256280d39d= drives Compose directly from that reducer observation on the UI thread.
- Observer tests through exact branch head =ef356d75cba664c6375513c2710a2a72b208bfbf= require Connecting -> Connected -> Reconnecting -> fresh Connected publication and durable conversation projection after a real turn result.

** Parallel-connect RED/GREEN and enrollment honesty
- RED =f755d2b711fd5fc9aa72ccc6fce6ee9f6532e2f2= requires the Connect control to be available only from Disconnected or OfflineDegraded and rejects UI attempts to start a parallel lifecycle while Connecting, Connected or Reconnecting.
- GREEN =41edb3eecada2161b88410d4e3d7d83c115b84b2= centralizes that projection in =canRequestConnect= and disables endpoint mutation during an active lifecycle.
- The Settings surface now explicitly distinguishes the two-sided enrollment contract: the Android public key must be enrolled by the Zara server owner; pinning the server CURVE public key locally does not perform server enrollment. Private key material remains in Keystore-backed storage and is never rendered.
