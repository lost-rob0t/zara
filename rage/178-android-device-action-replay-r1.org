* RAGE #178 r1 — Android stale/replayed device actions

- Consumed issue :: #178
- Exact immutable start :: =e1b86f17debe88f6d7190379b0ae3f1522d70b29=
- Scope :: Android ZARA/1 device-action adversarial proof only. No Core/protocol/plugin implementation.

** Research
- =ZaraTextClientActor= binds every inbound device action to the current authenticated session before handing it to the device-action handler.
- Completed/terminal action ids are retained in a bounded 256-entry set and a duplicate terminal action id is rejected before another acknowledgement or execution.
- Existing actor tests prove successful execution and expired deadlines, but not wrong-session targeting or terminal replay.

** Design / acceptance
- A device action carrying a stale session id must fail with =StaleTextSessionException= before handler execution or action acknowledgement.
- A second request with the same terminal action id must execute the adapter exactly once and fail before a second accepted/result acknowledgement.
- Keep the proof on the existing actor/dealer path; no parallel replay cache or action state machine.
- Fresh exact-head CI is required before promotion/merge.
