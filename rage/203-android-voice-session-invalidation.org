** Bug / source analysis
- =ManualVoiceSessionCoordinator.press= binds capture to the canonical connected session id, but the coordinator previously had no runtime-state callback after capture began.
- A network/daemon loss can move the reducer to reconnecting while the physical recorder remains active until another failure path happens to stop it.
- A replacement authenticated generation/session must never inherit audio capture started for the prior session.
- #203 explicitly requires daemon/network loss, bounded reconnect and stale-audio lifecycle hardening.

** Design
- Retain only the generation/session binding that authorized the active capture; this is not a second runtime state machine.
- On reducer state publication, cancel through the existing sole =PushToTalkController= owner if the runtime is no longer connected, generation changes, or session id changes.
- Cancellation remains idempotent at the coordinator boundary because repeated state publications observe Idle/no binding.
- Clear the binding on release, cancel, close and failed cleanup.
- AppSession wiring is deferred while #407 owns that file; after #407 is canonical, recover master and feed every canonical reducer publication into this coordinator before external UI observation.
