* Threat model decision
The current Python closure repair is not an authority boundary.  PR
=lost-rob0t/zara-plugins#1163@d17e4ca9df4baae2b5a2a17f900820fb2a0f7a43=
proves same-process code can recover the nested issuer and registry by closure
introspection.  Moving those objects into another underscore name, closure,
frozen dataclass, module secret or in-process broker is rejected.

The GREEN implementation for #663 must therefore own executable predicate
registration outside the generic plugin interpreter (isolated worker/process or
an equivalent boundary).  Trusted construction binds:

- authenticated principal/session (not request data),
- namespace,
- logical operation id,
- exact predicate + arity + argument schema,
- registration/runtime generation,
- cancellation/deadline correlation.

The plugin-facing request may carry only request id, logical operation,
expected generation, bounded inert arguments and timeout.  It may not carry
principal, namespace, predicate, arity, module, goal, query, capability token or
raw backend/process metadata.

Successful results must bind fresh observed execution provenance to exact
namespace + predicate + arity + generation + request id.  Process exit zero is
not domain success.  Missing/ambiguous/stale/cancelled/crashed execution remains
=unknown=/=cancelled=/=error= and must not become verified truth.
