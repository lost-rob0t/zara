** Research
- =zara/__main__.py= routes AMD/ROCm/HIP/Vulkan local STT to provider =whisper-cpp= and resolves a local GGML =.bin= model.
- Dictation intentionally converts =whisper-cpp + vulkan= back to the historical internal =cuda= compatibility token before entering =zara.dictate=.
- =zara/whisper_cpp.py= explicitly translates that historical =cuda= token back to Vulkan; its server command only adds =--no-gpu= for CPU.
- =zara/stt_backends.py= =backend_compat(provider)= temporarily exposes provider adapters through the historical =faster_whisper.WhisperModel= surface.
- PR #577 correctly targeted misleading/brittle dictation backend selection, but changed =amd|rocm|hip= normalization itself from the established =cuda= compatibility contract to =vulkan= and deterministically failed existing Core coverage.
- The safe seam is therefore model/backend selection inside =zara.dictate=: preserve the incoming compatibility token, recognize an already-resolved GGML =.bin= model, and instantiate =WhisperCppModel= on actual Vulkan explicitly.

** Design
- Preserve =_normalize_device(amd|rocm|hip) -> cuda=.
- Permit explicit =vulkan= without changing historical aliases.
- Add a small provider-neutral selection seam returning backend, actual model device, and compute marker.
- =GGML .bin + cuda/vulkan -> whisper_cpp, vulkan, vulkan=.
- Ordinary CUDA model -> existing faster-whisper =cuda/float16= path and existing int8/CPU fallback behavior.
- Do not require faster-whisper to import successfully when the selected backend is whisper.cpp/Vulkan.
- Log the actual model backend/device so a Vulkan run no longer prints a misleading =Loading ... on cuda= line.
- Do not change ZeroMQ, Android, voice transport, Prolog routing, or microphone ownership.
