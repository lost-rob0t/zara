* Slice C — collapse process ownership to one Copilot renderer
** Research / adversarial decision
- The duplication boundary is =DesktopController=, not =ConversationService= or the daemon/client protocol. Current normal construction owns two QWidget renderers and fans status/conversation/runtime updates into both.
- The bounded migration is one process-owned =CopilotWindow= with =quick_window= retained temporarily only as an object-identity compatibility alias to =window=. This preserves callers/tests while removing the duplicate renderer.
- Full-chat entrypoints must switch the same object to =EXPANDED= and show it; they must not hand off/copy state or hide another window.
- Any fan-out/close/status paths must identity-deduplicate the alias so one surface never receives an update or close twice.
- No daemon, protocol, provider, conversation-store, or Android path changes are required for this slice.
