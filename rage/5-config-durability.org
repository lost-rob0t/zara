* Iteration 1
** Research
- Current =modules/config_loader.pl= has exactly one user Prolog path, =$XDG_CONFIG_HOME/zarathushtra/config.pl= (fallback =~/.config/zarathushtra/config.pl=).
- =ensure_user_config/0= correctly avoids rewriting an existing file, but that does not preserve mutable runtime/operator state when an external declarative manager owns =config.pl= as an immutable Nix-store-backed file or symlink.
- Current reload tracks asserted clauses and removes them before loading a replacement, so the existing clause-reference mechanism can support a multi-layer load without adding a second configuration subsystem.
- Current server loader intentionally rejects device-only facts; that boundary must remain identical for every layer.
- =hooks.pl= derives its directory from =config.pl= but is a separate file; this slice changes Prolog configuration layering only.
- Existing =scripts/test-prolog-config.sh= already isolates =$XDG_CONFIG_HOME= and is the correct deterministic regression harness.

** Design
- Preserve =config.pl= as the backwards-compatible provisioned/base user configuration.
- Add =$XDG_CONFIG_HOME/zarathushtra/config.local.pl= as the mutable/private user-owned overlay.
- Never create =config.local.pl= automatically. Missing local overlay is valid and must stay absent, preventing Zara or Nix templates from manufacturing private state.
- Parse and validate base + local layers before mutating active facts. Concatenate base facts before local facts, then =asserta/2= in that order so later local clauses become the first visible overrides while retaining deterministic defaults behind them.
- Reload remains atomic with respect to validation: if either layer is invalid, active previously-loaded clauses remain unchanged because replacement occurs only after both reads succeed.
- Server scope reads the same two layers with =validate_server_user_fact/3= and rejects device-only facts in either layer.
- Export =user_local_config_path/1= so tooling/docs/tests can discover the mutable authority without hard-coding a path.
- No secrets or private content enter templates, Git, logs, or Nix-store-owned defaults.

** Acceptance-to-test map
- Provisioned base + mutable override coexist :: test base =search_engine= and local =search_engine=, assert local wins and base file content is unchanged.
- Mutable layer is not auto-created :: call =load_user_config= with no local file and assert the local path stays absent.
- Reload replaces old local state without duplicates :: rewrite only =config.local.pl=, reload, assert old local clause is absent and exactly one new local clause precedes base/default.
- Invalid local layer is atomic :: load valid state, write invalid local term, assert reload throws and prior loaded value remains active.
- Server boundary applies to local layer :: put device fact in local overlay and assert =load_server_config= rejects it.
- Existing supported-fact and unsafe-input tests remain green.
