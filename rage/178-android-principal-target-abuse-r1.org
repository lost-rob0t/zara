- Consumed issue :: #178

- Scope :: Android ZARA/1 device-action adversarial proof only. No Core/protocol/plugin implementation.

** Research
The canonical device-action codec already rejects unknown envelope/body fields and binds actions to the authenticated live session. The #178 matrix explicitly requires wrong target principal/device/session coverage, but Android only had explicit stale-session actor coverage. Payload-supplied =principal_id= or =device_id= targeting was an undocumented proof gap even though current closed-schema behavior should reject it.

Malformed/oversized text envelopes and URI/intent scheme abuse already have dedicated Android tests, so duplicating those would add little value.

** Design / adversarial cases
Add deterministic codec-level cases for =principal_id= and =device_id= injected both into the action body and top-level envelope. All must throw =ZaraWireException= before any actor/adapter execution can occur. Do not add new target fields or a second authorization path.

** TDD note
This is acceptance-coverage only: no production behavior is changed. The current closed schema is expected to satisfy the new proof immediately, so a RED production cycle is not applicable. Fresh exact-head CI remains mandatory.
