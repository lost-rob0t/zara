** Design (Auto-RAGE decision)
Transport-local ordering (option a); rejected host-side immediate-accept
(option b) because the host already accepts at start - execution is a
background task - and the defect is purely wire serialization:
1. Hold turn-scoped runtime events per (principal, turn_id) when the route
   is unknown or the accepted reply is awaiting flush (bounded 64x128,
   drop-oldest; replaces the silent drop of pre-registration events).
2. Flush buffered events through the same per-route FIFO strictly after
   turn.accepted; conversation-fallback and non-turn events unchanged.
3. Turn-scoped events enqueue via _enqueue_outbound (never direct _send)
   so they cannot overtake a queued accepted reply.

- Root cause 1 (crash): SecureZaraZmqGateway._enqueue_outbound overrode the
  base with a (route, message) signature while the base contract is
  (route, message, payloads=()); iteration 1's drain/flush calls pass
  payloads positionally, so the FIRST turn-scoped event drained on a

  iteration-1 calls made it reachable. Explains all four red jobs

  stock-server interop which drives the real Python secure gateway).
- Root cause 2 (race): the drain read _turns_awaiting_accept membership
  outside the lock and appended to _early_turn_events in a separate
  critical section; completed()'s flush could pop-empty + discard the key
  between them, stranding the event in the early buffer forever.
