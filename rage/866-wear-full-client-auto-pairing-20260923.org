** Design (slice for this iteration)
Auto pairing = the paired Android phone (the node already holding canonical truth) provisions the watch automatically over the Wear Data Layer. No server credentials ever leave the phone (fail-closed boundary from #866/#1358); the watch renders canonical truth pushed by the phone and states truthfully whether the phone link is live.

- New shared contract in =shared-ui= =ai.zara.ui.continuity=:
  - =WearCompanionContract=: capability name, message paths, request/response envelope codec (bounded, versioned) for /watch_hello request and /phone_provision response carrying phone name, principal/conversation/project scope, and the encoded =SymbolicConversationEdgeSnapshot=.
- Phone =app/watch/WearCompanionLink.kt=:
  - listens for =zara_watch= capability nodes, answers hello with the current scope + latest canonical snapshot from =PortableConversationStore=, republishes snapshot on conversation changes while a watch is reachable.
- Wear =wear-app=:
  - =WearCompanionClient.kt=: Data Layer client that auto-requests provisioning on connect (auto pairing; zero manual input), tracks link state machine =SEARCHING → REQUESTING → PAIRED / PHONE_UNREACHABLE / REJECTED=, accepts snapshots only through =SymbolicConversationContinuityGate=.
  - =WearMainActivity= becomes a real round UI: sigil header + status (link state, phone name, scope), conversation screen (dialogue act, entities, unresolved questions, outcomes, generation), Voice deep-link button.
- Invariants:
  - watch never renders unprovisioned state as connected; snapshot truth only through the gate;
  - secrets/credentials never enter Data Layer payloads (payload is pure-symbolic projection only);
  - no second auth/session/transport authority on Wear in this slice (server enrollment stays phone-owned per #1358);
  - payloads bounded by codec contract.
