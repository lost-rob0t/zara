#+title: RAGE 1254 Desktop Pure-Symbolic Runtime

* Research
- RuntimeHost already owns lifecycle, cancellation, stale-turn fencing, capability leases, plugin coordination, and canonical turn events.
- Desktop submits canonical SubmitTurn commands through QtRuntimeBridge and keeps history in ConversationService/ConversationStore.
- LangGraphRuntimeBackend constructs AgentManager, whose normal path owns provider/model setup; it cannot be the hard-zero provider-disabled boundary.
- modules/symbolic_dialogue_turn.pl composes canonical intent_frames + symbolic_dialogue and explicitly leaves persistence to the canonical conversation projection.
- Android already has a provider-free PureSymbolicConversationController and a conversation execution-policy boundary; Desktop needs equivalent runtime semantics without a second history store or planner.
- [agent].backend is already the canonical AgentLoopRegistry selector. Pure-symbolic conversation policy must stay orthogonal to it rather than hijacking that key.

* Design
- Add a thin PureSymbolicRuntimeBackend under the existing RuntimeBackend/RuntimeHost boundary.
- Select the Desktop boundary with conversation.execution_policy = pure_symbolic before AgentManager or daemon/provider startup; leave agent.backend untouched.
- The backend owns no conversation history, expert registry, planner, tool executor, or provider client.
- All language semantics/rendering stay in canonical Prolog through PrologEngine and symbolic_dialogue_turn.pl.
- Return hard-zero provider/model budget and usage metadata on every successful symbolic turn.
- Fail closed on attachment/task-prompt inputs that do not yet have canonical pure-symbolic projection semantics; never delegate them to LangGraph/provider code.
- Effects remain dispatch_required/verified response acts. This slice must not claim effect success or bypass RuntimeHost capability/approval/tool boundaries.

* Evaluate
- Provider-free unit/contract coverage and a real Prolog greeting/parse-miss path are implemented.
- Desktop now has an offscreen affected-flow application test using the real Qt bridge, RuntimeHost, canonical ConversationService/ConversationStore, and symbolic Prolog backend.
- Self-review caught an architectural error in the first draft: it reused [agent].backend. The branch now uses the separate conversation execution-policy key and pins agent.backend as unchanged in regression coverage.
- Exact-head CI remains required before this slice is considered green.

* Outcome
- Draft integration slice. Durable projected context, expert/effect composition, restart/replay, project switching, and Android parity remain owned by the active canonical #1264/#1254 integration path; this branch intentionally does not fork those stores/contracts.
