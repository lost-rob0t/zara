* Design / adversarial review
- Native JNI surface remains exactly the already-landed =JniTreallaNativeApi.initialize/evaluate/shutdown= API; no second parser or semantic serializer is added in Kotlin.
- One native engine instance is process-local and guarded by a mutex. Initialization creates exactly one Trealla engine and consults the supplied portable core path; failed consult destroys the engine and returns false.
- Evaluation requires a live engine and a non-empty query. Each answer must expose a =Result= binding; Zara copies its canonical =pl_term_text= representation into the returned Java string array. Missing =Result= or Trealla error fails the JNI call rather than inventing success.
- Query-owned terms are copied before =pl_redo/pl_done=. Owned Trealla strings are released with =pl_free=.
- Results are bounded to 256 answers to prevent an unbounded JNI allocation loop. Hitting the bound closes the still-active query deterministically.
- Shutdown destroys the engine and is idempotent.
- CMake accepts only explicit local =ZARA_TREALLA_SOURCE_DIR= and =ZARA_TREALLA_LIBRARY= inputs; it performs no network fetch and therefore cannot silently move to an unreviewed upstream revision.
- This slice does not wire Gradle/native packaging yet because the NDK and pinned Trealla artifact are not present in the current Android toolchain; enabling an externalNativeBuild that cannot pass the canonical Nix Android gate would be a false-green/false-shipped architecture.
