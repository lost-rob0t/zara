** Design

*** Decisions
- D1 :: Frame-keyed capability KB. kb/capabilities.pl facts key on
  (IntentNS, IntentName), not surface verbs (#119 mechanic rejected - verbs
  are frame-input concerns, resolved by #156; plans consume frames).
  Facts: capability_provider(NS, Name, ProviderId, Priority),
  capability_property(ProviderId, Property), capability_binding(ProviderId,
  ArgName, SlotName) (declared argument schema). No shell strings, no
  executable names, no package ids anywhere in the KB.
- D2 :: Availability is environment-explicit. Selection takes a closed
  environment term: environment(principal(P), auths(A), devices(D),
  providers(S), aliases(AL), policies(POL)). Server-side provider
  availability (S) and launchable aliases (AL) are server-policy authority;
  device advertisements (device(Id, Owner, Caps)) are only an availability
  source for location(device) providers. kb/config.pl (side-effectful
  initialization, user config) is NOT consulted by plan selection - purity.
- D3 :: Qualification pipeline per declared provider: availability (server:
  ProviderId in env.providers; device: an env device owned by the requesting
  principal advertises the provider's capability cap(Atom)) -> alias gate
  (ref(app_alias) argument on a server provider requires
  alias(Provider, Alias) in env) -> authorization (requires_auth(Auth \= none)
  requires Auth in principal auths, else auth-denied) -> policy preference
  (prefer(location(L)) / prefer(device(Id)) reorder) -> deterministic priority
  (desc) -> ties yield ambiguous (capped alternatives).
- D4 :: Typed outcomes only: ready / unavailable(Reason) / ambiguous /
  denied(insufficient_authorization). Reason atoms: no_provider (nothing
  declared for the intent), provider_unavailable (declared but not available),
  alias_unsupported (all eliminations alias-gated), provider_missing (stale
  re-check after a ready plan), insufficient_authorization (denied).
  Unavailable is plan-level; the frame is never rewritten with a fabricated
  semantic status (contract example 12).
- D5 :: Structural defenses, not filters: device advertisements can only
  qualify providers whose location is device AND whose declared capability
  matches; admin/server providers are location(server) so no advertisement can
  create them ("malicious device advertisement cannot acquire admin/server
  capability"); advertisements from other principals are invisible
  (cross-principal isolation); auth requirements are evaluated against
  server-granted auths only, never against advertised claims.
- D6 :: Portable plan term (compounds + lists only):
  execution_plan(intent(ns(NS), name(Name)),
    provider(id(Id), location(L), device(D), side_effect(C), requires_auth(A)),
    status(S), arguments([argument(name(N), value(V))]),
    evidence([atom]), alternatives([atom])). Decoded through flat
  plan_head_row/12 + plan_arg_row/8 projections (pyswip nested-compound
  constraint; 'none' sentinels as in #156).
- D7 :: Python mirror zara/runtime/plans.py: PlanStatus, PlanLocation,
  PlanSideEffect enums; PlanArgument(name, value: SlotValue) reusing
  frames.py typed values and validate_value; frozen ExecutionPlan dataclass
  with validator (ready requires provider+location; device plans name a
  device; text arguments bounded at 512 chars; unknown plan states rejected).
  PlanEnvironment + DeviceAdvertisement dataclasses encode the environment
  term (encode_environment_term) - no raw strings at call sites.
- D8 :: PlanExecutor seam (zara/runtime/plans.py): adapters registered per
  provider id; refuses non-ready plans, unregistered providers, oversized
  arguments; passes typed values only (never shells text); side-effecting
  plans execute at most once per envelope request_id (bounded replay set;
  replay returns typed replayed outcome). Cancellation/stale semantics:
  non-ready plans never execute; plan_stale/4 (Prolog, pure) re-derives the
  plan in a fresh environment and marks a formerly-ready now-unavailable
  selection as unavailable(provider_missing) - no unsafe fallback.
- D9 :: Scope boundary (deliberate): wake/daemon do NOT consume plans yet.
  The reasoning layer, typed mirror, boundary, and executor seam are proven by
  tests; wake cutover rides the migration rows in #160/#173 (events) and the
  Android slices (#196/#197). A7 work (agent prompt verb list + raw
  query_prolog retirement) stays in #160: retiring the raw tool before the
  plan layer is the only execution surface would leave the agent without a
  typed path. Coordinated, not half-done.
- D10 :: Ties and ambiguity: equal top priority after policy -> ambiguous with
  deterministic alternatives (provider ids, or provider@device atoms for
  device-level ties), capped at 8. Plan-level ambiguity surfaces typed
  evidence; consuming it (clarification) is a host concern (#155 machine /
  #173 emission), not this slice.

*** Rejected alternatives
- Reusing #119's capability_resolver verbatim: verb-keyed, kb_config-coupled,
  shell-command evidence, speculative executable fallback - all violate the
  frozen contract or explicit issue invariants.
- Putting availability inside Prolog (asserting dynamic provider facts):
  resolution must stay pure; dynamic DB state would make plans
  non-deterministic across calls and untestable.
- Letting the KB store alias->package/shell maps: provider-neutral plans;
  concrete launch strings are adapter/platform state (Android RUN_COMMAND,
  desktop xdg-open) and must never ride the plan.
- Silently picking a device on ties: violates "may not silently pick one";
  ambiguous is the typed contract answer.
- plan_for_frame accepting non-complete frames: clarification owns open
  frames; the plan layer fails them closed (Python raises ValueError before
  Prolog is consulted; Prolog clause also fails).

*** Threat / failure analysis
- Slot-text injection into adapters: executor passes typed SlotValue objects;
  adapters validate; text is data, never a command (tested with a recording
  adapter asserting the typed value object arrives).
- Malicious device advertisement: structural location(device) gating + owner
  filter + server-side auth evaluation (D5) - tested.
- Cross-principal targeting: owner filter - tested both directions.
- Stale provider between plan and execute: plan_stale/4 typed
  unavailable(provider_missing); executor refuses non-ready - tested.
- Replay/duplicate side effects: at-most-once per request_id with a bounded
  replay window - tested (bounded set eviction, replay rejection).
- Unbounded plans: 512-char text arguments, <= 8 alternatives, bounded
  environment sizes (devices <= 64, providers <= 64, aliases <= 256, caps
  per device <= 64) - tested.
- Non-finite/typed-value violations in plan arguments: frames.validate_value
  reused - tested.
- Prolog string injection via crafted aliases/principals: _prolog_atom
  escaping (quote/backslash) - tested with quote-bearing inputs.

** Adversarial review (recorded before implementation)

*** Attack 1: "The plan layer is dead code - nothing calls it"
Risk: D9 ships reasoning + executor seam with no production call site.
Response: the issue's acceptance is explicitly "becomes an authorized typed
plan or an explicit ambiguity/unavailable/denied result, WITHOUT performing
the action" - the deliverable is the deterministic decision layer. The
executor seam exists so the "typed adapters" migration row has a proven,
at-most-once entry point rather than a promise. Wake cutover without this
layer would execute intents exactly as today (raw execute_intent), i.e. no
progress on the row. Verdict: scope holds; call sites land in #160/#173/#196.

*** Attack 2: environment-as-term is a stringly escape hatch
Risk: encode_environment_term builds a Prolog string; callers could pass
garbage and the parser would accept unknown compounds, silently failing open.
Response: the environment is a closed dataclass; the encoder emits only the
six known fields with escaped atoms; bounds are validated at construction.
Malformed terms are impossible from the typed API; Prolog-side, unknown
environment shapes simply fail to qualify (fail-closed - no candidates ->
unavailable). Residual: a caller bypassing the dataclass with a raw term
string - same trust level as today's goal strings into query_once; the
wake/daemon wiring slices will go through the dataclass. Verdict: acceptable,
documented.

*** Attack 3: ambiguous alternatives encoding ('provider@device' atoms)
Risk: overloading atoms with provider@device is a mini-format that Android
must re-parse; contract prefers structured lists.
Response: alternatives are presentation for evidence/clarification; the
authoritative tie information is the candidate set re-derivable from
plan_explanation. Flat atoms survive pyswip (the #156 constraint); nested
compound lists do not. A structured wire form is #172's serializer concern,
where the same constraint applies. Verdict: keep flat atoms; document the
separator contract in the module header and wiki.

*** Attack 4: policy preference vs priority ordering interaction is ambiguous
Risk: "prefer(location(L))" reordering on top of priority could produce
non-obvious winners (low-priority preferred-location beats high-priority
non-preferred?). Response: defined semantics - preference is a FILTER
reordering: candidates of the preferred location/class are considered first;
only if none survive do others compete. Priority then ranks within the
effective set; ties -> ambiguous. Tested for: prefer(server) with device also
available; prefer(device) with only device available; prefer(device(D2)) with
two devices (targeting policy); preferred location unavailable -> fallback.
Verdict: pinned by tests.

*** Attack 5: at-most-once replay set in-process only
Risk: executor replay protection is per-process; a restart loses the window
and a redelivered request_id re-executes.
Response: true and accepted for this slice - persistence is the daemon
envelope store's job (#173+). The invariant enforced here is "at most once
per request_id per executor lifetime", bounded. Documented in the executor
docstring and wiki. Verdict: scoped.

*** Attack 6: requires_auth vocabulary drift with zara/security.Capability
Risk: two auth vocabularies (plan atoms vs Capability enum) drift apart.
Response: requires_auth atoms use the Capability VALUES ('session.basic',
'daemon.admin'); the pytest layer validates plan auth atoms against the
Capability enum where known, and admin providers in the KB use 'daemon.admin'.
Verdict: aligned by test.

*** Attack 7: pure-Prolog tests duplicate pytest boundary tests
Risk: plunit + pytest cover the same assertions twice, doubling maintenance.
Response: they test different boundaries: plunit proves the pure selection
logic under plain SWI (portable-subset discipline, #172 needs it), pytest
proves the pyswip decode + Python mirror + executor. Distinct failure modes
(term shape vs marshalling vs validation). Verdict: keep both, no overlap in
assertions.

*** Attack 8: bounded_atom duplication in capability_plans
Risk: copying bounded_atom/2 from intent_frames duplicates logic.
Response: 3-line helper; cross-module import would couple plan selection to
the resolver module's export surface (#160 will retire legacy exports).
Precedent: intent_frames already carries local copies of number_token/unit
helpers. Verdict: accepted, documented.

*** Attack 9: capability KB keys on (NS, Name) but ns values are open sets
Risk: unknown ns/name yields no_provider - is that distinguishable from a KB
typo? Response: no_provider is exactly the typed signal for "nothing
declared"; KB omissions surface as unavailable in tests. Corpus-style
fixtures pin the declared set. Verdict: acceptable; the KB is the authority.

*** Attack 10: tests need real SWI + pyswip (flake-only)
Risk: contributors without nix see failures. Response: repo convention
already (all Prolog tests are flake-gated). Verdict: no change.

Review outcome: design stands with Attack 2/3/5 caveats documented. Proceed
to TDD.
