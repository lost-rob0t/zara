* RAGE #203 / #178 — invalidate stale Android playback on authenticated-session loss

- Consumed issues :: #203, #178
- Exact immutable start :: =5f17f167850c87fe04ca30a525819b2d2a11ae98=
- Scope :: Android runtime/voice lifecycle only. No Core/server/plugin implementation.

** Analyze
=VoiceStreamSinkActor.reset()= already owns serialized playback teardown, but =AndroidAppSession.observeRuntimeState= only forwarded runtime changes to microphone capture. On daemon/network loss, =RuntimeState= clears =sessionId= while active speaker playback could remain owned by the old authenticated session.

** Threat / design
Stale TTS from a dead/replaced authenticated session must be invalidated through the existing single playback owner. Track only the currently Connected runtime session. When it disappears or changes, request =voiceStreamSink.reset()= before publishing the new runtime state to UI observers. Do not add a second audio owner or invent resume semantics.
