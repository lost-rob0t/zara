** Design decisions
- New shared UI library android/org-surfaces (namespace ai.zara.org.surfaces) owns the reusable focused surfaces + workspace scaffold + theme; no per-app surface forks. Flagship org-app consumes it (single canonical path), focused apps are thin launchers.
- Fleet (one APK each): org-app ai.zara.org.app "Org" (flagship, all surfaces); org-editor ai.zara.org.editor; org-todo ai.zara.org.todo; org-reminder ai.zara.org.reminder; org-timer ai.zara.org.timer; org-roam ai.zara.org.roam; org-graph ai.zara.org.graph; org-home ai.zara.org.home (today agenda + dailies + sibling-app chips via PackageManager; absence is fine).
- All apps: own applicationId, depend only on org-core/org-storage (+org-surfaces); no dependency on :app (Zara phone) or each other; ORG_HOME uses-permission + provider <queries> for optional shared workspace; SAF picker fallback always available.
- Editor: revision-fenced lossless text save (stale refusal when disk changed under the session). Graph: deterministic layout function. Timer: pure countdown model. Reminders: OrgReminders.fromProjection list (no fake AlarmManager claims).
- Release surface: release.yml builds every fleet module and publishes zara-org-<app>-<version>.apk + sha256 + per-app manifest, release created WITHOUT --prerelease so it becomes /releases/latest; android-latest.yml carries every fleet APK in the rolling payload; scripts/test-android.sh builds/tests every org module.
- Version: minor bump 0.2.2-alpha -> 0.3.0-alpha, android.versionCode 4 -> 5, release.target follows (new feature line).

** Rejected alternatives
- Separate parser/sync per app: violates #1000 source-of-truth rule (forbidden).
- Publishing only to android-latest: mutable channel is not release evidence; operator asked for the latest release page.
- Keeping flagship surfaces private and copying them into 7 apps: duplicative UI forks; single canonical surface library instead.
