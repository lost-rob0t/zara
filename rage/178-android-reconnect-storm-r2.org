* RAGE #178 r2 — Android reconnect-storm hardening

- Consumed issue :: #178
- Exact immutable start :: =9ac0e0c0b94f571d6cab69ec252bb69ac2db3420=
- Scope :: Android-only reconnect-storm behavior and deterministic JVM coverage. No Core/protocol/plugin files.

** Research
- =AndroidTextSessionController.connectionLost= feeds every loss callback into the canonical reducer.
- The reducer currently treats =ConnectionLost= while already =Reconnecting= as a failed retry, incrementing attempt/generation even when no reconnect attempt has actually run.
- Repeated platform/network callbacks can therefore consume the bounded retry budget and enter =OfflineDegraded= without any failed connect operation.
- Existing stale-connect protection already rejects late completions by generation; duplicate loss callbacks do not need to rotate generation to preserve isolation.

** Design
- Only an actual =Connected= session loss begins reconnect.
- While already =Reconnecting=, duplicate =ConnectionLost= is idempotent: preserve generation, attempt, scheduled retry, and disconnect count.
- Actual =ConnectionFailed= remains the sole path that advances a reconnect attempt after a scheduled connect has executed and failed.
- Keep canonical reducer/state ownership; no parallel reconnect state machine.

** Deterministic proof
- Test commit :: =b9f5f234078ae5ad38fe9a93bcb6f1cb234280b7=
- Regression :: eight duplicate =connectionLost= callbacks during one reconnect window must leave state at =Reconnecting(2,1)=, keep one 250ms retry, one disconnect, and generation 2; the first actual connect failure must then advance to attempt 2 / generation 3.
- First CI #1679 was superseded/cancelled by the GREEN push before completion and is not used as verification evidence.
- Fix commit :: =b3e10f9b4364d9a6b4c918cdf7d1980ef44c5a2e=
- Implementation :: =RuntimeEvent.ConnectionLost= is idempotent outside =Connected=; =ConnectionFailed= remains the retry-attempt advancement path.
- Exact-head CI :: #1680 on =b3e10f9b4364d9a6b4c918cdf7d1980ef44c5a2e= is authoritative and must complete green before promotion/merge.

** Acceptance
- Duplicate network callbacks cannot burn reconnect budget or rotate generation.
- Actual failed reconnects still advance bounded exponential backoff.
- Stale generation/session checks remain canonical.
- No Core/protocol/plugin changes.
