* Research / failure analysis
- =MainActivity= previously traversed to the root Throwable and copied its raw message into Compose =operationError=.
- The system =ZaraVoiceInteractionSession= independently repeated the same raw-root-message pattern for voice start/send/cancel failures.
- Network/auth/platform exceptions can contain endpoints, filesystem paths, tokens, provider internals, or other private implementation detail.
- Voice streaming already has a coarse diagnostic boundary; both human-facing Android surfaces need the same fail-closed property without creating a second runtime state machine.

* Design
- Classify by Throwable type only; never expose Throwable.message.
- Stable bounded categories are =permission_denied=, =invalid_input=, =network_error=, and =operation_failed=.
- Traverse causes at most eight levels with identity-based cycle detection.
- Compose and VoiceInteraction surfaces share the same =UiOperationFailure= boundary.
- Preserve explicit human-safe UI strings only where the application itself authors the text, such as microphone permission denial.

* TDD
- RED first: adversarial endpoint/token/path-bearing message must not escape and category matrix must remain stable.
- RED follow-up: VoiceInteraction source contract forbids =rootMessage= / =current.message= and requires the shared classifier.
- GREEN: =UiOperationFailure= implements bounded message-free classification; =MainActivity= and =ZaraVoiceInteractionSession= route all exceptional user-visible operation paths through it.
