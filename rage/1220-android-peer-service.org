* Design / adversarial review
Boundary: Android hosts a bounded authenticated ZARA/1 ROUTER peer listener as a real Android
foreground service, generation-fenced by the landed lifecycle, with a peer enrollment authority and
proven wire interop against the canonical Python client. NOT in this slice: turn execution on the
phone runtime, pairing ceremony/QR (#666/#1059 in flight), discovery/relay, sync (#1221 in flight),
UI toggle.

New components (=android/app/src/main/java/ai/zara/app/peer/=):
1. =PeerEnrollmentRegistry= — in-memory enrolled-peer authority, default-deny. =EnrolledPeer(deviceId,
   publicKeyZ85, generation, active)=; bounded to 256; duplicate active key/device rejected; =revoke=
   fences lookups immediately; =resolve(publicKeyZ85)= returns null for unknown/inactive. Identity for
   authorization comes only from here + ZAP, never from payload.
2. =PeerNodeWire= — server-side strict ZARA/1 codec: same envelope key set/grammar/64 KiB cap as
   Python =protocol.py=; decodes =hello= (versions must contain 1) and =ping=; validates the node
   document exactly like =ZaraNode.from_mapping= (9 fields, device-class enum, Z85 key, bounded
   tcp:// endpoints, capabilities ⊆ {open_app, open_uri}, =ZARA/\d+= versions, positive generation);
   encodes =hello.ok=/=pong=/=protocol.error= with the verbatim Python error codes
   (=authentication_required=, =invalid_message=, =unsupported_version=, =node_authority_mismatch=,
   =invalid_node=, =quota_exceeded=, =authorization_denied=).
3. =PeerNodeGateway= — the listener: single poll thread; =ZAuth= custom CURVE auth backed by the
   registry (deny => no ZMTP handshake, no application reply oracle), =zapDomain("zara")=, phone
   keypair as CURVE server keys, ROUTER with bounded options (linger 0, HWM 256, handshake ivl 5s);
   binds =tcp://= endpoints; per message: route frame + ZAP =User-Id= metadata -> registry resolve
   (revocation fences the *next* message) -> strict decode -> hello node binding compared against the
   *authenticated* enrollment (payload identity never wins) -> one-credential-one-route on hello ->
   bounded route table (32) and per-peer rate window -> replies; turn/runtime types fail closed with
   =authorization_denied= until the runtime-host slice. Lifecycle integration: =requestStart= ->
   bind -> =listenerStarted=; bind failure -> =listenerFailed= (truthful, generation-fenced, no
   leaked context); =requestStop= -> close -> =listenerStopped=; =networkChanged= re-advertises
   endpoints without changing identity. Stale callbacks cannot resurrect a listener (lifecycle
   already pins this; gateway must route every transition through it).
4. =PeerNodeIdentityStore= — durable node id + enrollment generation (atomic temp+replace,
   =noBackupFilesDir/zara/peer/peer-node.bin=, magic header, 64 KiB cap); rotation only through the
   explicit enrollment-authority replace API; combined with the Keystore-wrapped CURVE credential it
   produces =PeerNodeIdentity=; process recreation restores identity and starts truthfully STOPPED.
5. =PeerNodeListenerService= + =PeerNodeServiceController= — the repo's first foreground service:
   =:voice= process, =exported="false"=, =foregroundServiceType="connectedDevice"=,
   =startForeground= before any socket work, low-priority notification channel, no wake lock;
   controller is a pure JVM-testable seam binding service callbacks to gateway+lifecycle; the
   manifest/wiring is pinned by a source-contract test.
6. Interop evidence: =android/integration/zara_peer_client_fixture.py= — canonical Python CURVE DEALER
   client (reusing =zara.protocol= encode/decode) driven by env/argv, emitting machine-readable
   result lines; proven against the real Python =SecureZaraZmqGateway= by a new pytest
   (=t/test_zara_peer_client_fixture.py=) and against the Kotlin listener by an env-gated JVM test
   (=PythonPeerClientInteropTest=, wired in =scripts/test-android.sh= like =ZARA_STOCK_FIXTURE=).

Adversarial cases that must have tests before implementation is trusted:
- enrolled peer presenting another peer's node doc -> =node_authority_mismatch= (compare against
  ZAP-authenticated key, not payload);
- revoke mid-session -> next message =authentication_required=, no restart;
- unenrolled key -> silence at ZMTP level (client timeout, no oracle);
- malformed/oversized envelope -> =invalid_message= with bounded memory;
- stale =listenerStarted= after stop -> rejected by lifecycle, no resurrection;
- bind failure -> FAILED phase truthful, resources released, new generation retry works;
- second connection with same enrolled key -> prior route dropped (one-credential-one-route);
- route-table/rate bound -> =quota_exceeded=;
- process recreation -> identity restored, phase STOPPED, no fabricated session;
- payload node identity escalation -> never authoritative;
- no HTTP fallback, no second transport, no discovery trust.
