* Research
** Existing contract
- Shared ZARA/1 #159 already owns =capability.snapshot= and the session-bound =device.action.request -> device.action.accepted -> device.action.result|device.action.error= lifecycle.
- Android already had strict closed v1 capability encoding/ack decoding for =open_app= and =open_uri=, but #173 intentionally advertised an empty set until real Android adapters existed.
- Availability advertisement is not authorization and Android OS permission cannot be granted remotely.

** First implementation slice
Earliest useful/safest adapter is =open_uri= because it can be expressed through a closed URI schema and public Android ACTION_VIEW without package ids, arbitrary Intent extras, reflection, shell, or dynamic invocation.

Before execution, Android validates the request against the authenticated current session, closed capability id/version, bounded deadline/arguments, and URI policy. Only explicit reviewed schemes are accepted. Result/error is typed and correlated; no optimistic success is emitted before Android resolves/starts a handler.

=open_app= follows only after a bounded app-alias/visibility design. Package identifiers remain platform adapter state, not portable semantic arguments.

* Design
** Invariants
- One Android registry is the source of advertised device availability and executable adapters.
- Registry keys are the closed =DeviceCapability= enum; no dynamic class, method, raw Intent, shell or reflection registration.
- Snapshot derives from currently available registered adapters; no capability is advertised without an executable adapter.
- Every action is bound to the current authenticated session and is rejected when stale, cancelled or expired.
- =open_uri= accepts only bounded normalized HTTP(S) URIs and constructs a fresh ACTION_VIEW + CATEGORY_BROWSABLE intent locally.
- URI userinfo, fragments, backslashes, controls, unsupported schemes, missing hosts and values over 2048 bytes fail closed.
- No URI payload is written to routine diagnostics/logs.
- Android acknowledges accepted only after request validation/ownership; terminal success is emitted only after the platform launcher returns successfully.
- Device requests are consumed by the existing =ZaraTextClientActor= on its one authenticated DEALER, including while text or voice replies are interleaved. No second socket/pump/runtime is created.
- Route-local terminal action ids are remembered in a bounded set and cleared on reconnect/disconnect so duplicate terminal actions fail closed without becoming durable authority.

* Adversarial review
- Capability advertisement and execution share one source; a non-empty advertisement without a handler fails before session acceptance.
- Server acknowledgement must exactly equal the advertised set; server-added authority fails the connect.
- Device request session must exactly equal current authenticated session.
- Expired request fails before =device.action.accepted= and before adapter invocation.
- Unadvertised capability, duplicate terminal action id and device action without a handler fail closed.
- Adapter exceptions are reduced to bounded typed errors; raw platform exceptions/URI payloads are not serialized.
- =device.action.cancel= is handed to the adapter boundary and made terminal. Current advertised adapter is synchronous; any future long-running adapter must add explicit cancellation ownership before advertisement.
