* Consumption
- Issue :: #203
- Immutable start :: c09a61bb772b406905ed267e5c227d4a84edb7c7

- Scope :: Android voice ownership wiring only. No Core/protocol/plugin changes.

* Failure analysis
- The pure role-loss guard can distinguish Manual vs Assistant ownership, but production Assistant invocation still called the same =pressToTalk= entry as in-app manual PTT.
- Without distinct production ownership, role loss cannot safely cancel Assistant capture without also threatening manual PTT.
- A role transition may race capture startup, so Assistant ownership is checked again against canonical runtime role immediately after capture starts.

* Design
- Manual UI calls =pressToTalk= and records =AssistantVoiceOwnership.Manual=.
- VoiceInteraction calls =pressAssistantToTalk= and records =AssistantVoiceOwnership.Assistant=.
- Canonical AssistantRole observation updates the runtime reducer and then the guard.
- Release/cancel/permission/host-stop/close clear ownership through the same existing voice owner.
- Role-loss cancellation is serialized through the existing Android voice-control executor and reports failure through the redacted voice diagnostic boundary.

* TDD
- RED source contract requires distinct Manual/Assistant entry paths and canonical role observations reaching the guard.
- GREEN production wiring adds no new capture or runtime state machine.
