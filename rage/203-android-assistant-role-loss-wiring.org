* Failure analysis
- The role-loss guard distinguishes Manual vs Assistant ownership, but production Assistant invocation previously called the same =pressToTalk= entry as in-app manual PTT.
- Without distinct production ownership, role loss cannot safely cancel Assistant capture without also threatening manual PTT.
- A role transition may race capture startup. The first implementation queued the right cancellation but could still report startup success before the queued cancel executed; adversarial review caught this and the start path now fails if canonical role is no longer Held.

* Design
- Manual UI calls =pressToTalk= and records =AssistantVoiceOwnership.Manual=.
- VoiceInteraction calls =pressAssistantToTalk= and records =AssistantVoiceOwnership.Assistant=.
- Canonical AssistantRole observation updates the runtime reducer and then the guard.
- After Assistant capture begins, canonical role is checked again; role loss queues cancellation on the same voice-control owner and fails the start future.
- Release/cancel/permission/host-stop/close clear ownership through the same existing voice owner.
- Role-loss cancellation is serialized through the existing Android voice-control executor and reports failure through the redacted voice diagnostic boundary.
