* Audit
#175 remains open after B1 manual PTT, B2 streamed transcript/audio and B3 local barge-in landed. The B3 RAGE plan named Android audio-focus ownership, but its production diff contains playback interrupt/cancel behavior and no =AudioManager= focus adapter. Current =AndroidPcmOutput= uses =USAGE_ASSISTANT= but directly starts/stops =AudioTrack= without requesting/releasing audio focus or reacting to system focus loss. Therefore audio-focus loss remains a real acceptance gap, not backlog bookkeeping.

The separate residuals for wake mode, Bluetooth/headset route changes and background/foreground service behavior remain outside this first lifecycle slice until their platform contracts are individually bounded.

* Invariants
- Audio focus is owned exclusively by the Android playback edge, never Core/server.
- Playback must not start unless assistant audio focus is granted.
- Permanent/transient focus loss stops local playback through the same single playback owner; it does not fabricate server cancellation or start a second runtime.
- Focus is released exactly once when playback stops/closes, including failed AudioTrack startup.
- Focus callbacks are serialized into a small typed adapter boundary; raw Android constants do not leak into reducer/protocol state.
- No activity/context leak: use application context / AudioManager service only.
- No #174 files are modified in this parallel slice.
