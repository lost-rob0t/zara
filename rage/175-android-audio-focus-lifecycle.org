* Audit
#175 remains open after B1 manual PTT, B2 streamed transcript/audio and B3 local barge-in landed. The B3 RAGE plan named Android audio-focus ownership, but its production diff contains playback interrupt/cancel behavior and no =AudioManager= focus adapter. Current canonical =AndroidPcmOutput= uses =USAGE_ASSISTANT= but directly starts/stops =AudioTrack= without requesting/releasing audio focus or reacting to system focus loss. Therefore audio-focus loss remains a real acceptance gap, not backlog bookkeeping.

The separate residuals for wake mode, Bluetooth/headset route changes and background/foreground service behavior remain outside this first lifecycle slice until their platform contracts are individually bounded.

* Invariants
- Audio focus is owned exclusively by the Android playback edge, never Core/server.
- Playback must not start unless assistant audio focus is granted.
- Permanent/transient focus loss stops local playback through the same single playback owner; it does not fabricate server cancellation or start a second runtime.
- Focus is released exactly once when playback stops/closes, including failed speaker startup.
- Focus callbacks are serialized into a small typed adapter boundary; raw Android constants do not leak into reducer/protocol state.
- Android uses application context + AudioManager and public =AudioFocusRequest= only.
- Delayed focus gain is rejected. On any loss Android abandons the framework request immediately; Zara does not auto-resume stale server audio on a later focus gain.
- No #174 files are modified in this parallel slice. Production =AndroidAppSession= wiring waits for #174 canonical/recovery rather than creating a merge conflict or duplicate audio owner.

* Adversarial review
- Focus denial happens before =PcmOutput.start=; no speaker state is fabricated.
- Speaker startup failure releases a previously granted focus request.
- Local focus loss clears playback state through the existing =interrupt= path, so late chunks remain stale/rejected.
- Focus release is idempotent in the pure owner and paired with output completion/interrupt/close.
- Framework loss callback abandons the request before notifying playback; no automatic resume path exists.
- Focus handling does not send an upstream turn cancel by itself: system focus loss is a local playback policy event, whereas user barge-in remains the explicit upstream cancellation path from B3.
