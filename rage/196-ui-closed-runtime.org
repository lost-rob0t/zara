* Analyze / research
- Accepted #195 architecture requires UI-closed invocation while preserving the same typed runtime and explicit lifecycle cleanup.
- Current Android manual voice path owns the canonical ZARA/1 audio-input lifecycle: =audio.input.start= + bounded PCM chunks + =audio.input.commit= / =audio.input.cancel=; the event pump starts only after commit.
- Initial UI-closed prototype automatically opened the mic in =VoiceInteractionSession.onShow=. Adversarial review rejected it: a system invocation has no manual button-release callback, so the stream could remain open and never send canonical commit.
- Current Android Developers reference confirms =VoiceInteractionSession.onCreateContentView()= is the public hook for session UI and =onShow()= follows content creation. It also defines =SHOW_SOURCE_PUSH_TO_TALK= for physical-button invocation. Therefore the bounded implementation uses an explicit session-overlay PTT control and reuses the existing manual voice/commit path instead of inventing local VAD.

* Design
- =ZaraApplication= owns exactly one lazy =AndroidAppSession= in the app's =:voice= process.
- MainActivity and both VoiceInteraction services run in that same process. Closing/recreating Compose removes observers only; it does not destroy or duplicate the canonical Android client.
- Process death still creates a new AndroidAppSession from durable enrollment/profile state; existing runtime reducers do not fabricate a live session.
- Session overlay PTT: ACTION_DOWN starts/reconnects through canonical =AndroidAppSession=; ACTION_UP commits; ACTION_CANCEL/onHide/onDestroy cancels.
- Start planning fails closed on missing microphone permission, missing Assistant role, bad enrollment, missing endpoint, transient connection state, or connected state without a real session id.
- Async reconnect/start is fenced: release-before-start becomes immediate commit after successful start; cancel/hide-before-start becomes immediate cancel after successful start; duplicate presses cannot start a second capture.
- VoiceInteractionService re-assesses role on ready/shutdown and cancels any active capture on shutdown.

* Adversarial review
- Rejected :: automatic mic start on session show. It can create an uncommitted stream and therefore no transcript/response/audio completion path.
- Rejected :: local Android VAD solely to close system-assistant capture. Server remains canonical VAD/STT owner; duplicating VAD would create a parallel semantic/audio lifecycle.
- Rejected :: separate assistant-process runtime or second DEALER. UI/services are co-located with one application-owned =AndroidAppSession=.
- Race :: UI closes during reconnect/start -> gate converts late success into typed cancel.
- Race :: finger releases before reconnect/start completes -> gate converts late success into typed commit.
- Race :: role/service shutdown while capturing -> shared service cancellation stops the one capture owner.
- Process death :: only durable profile/enrollment survives; no live session id is synthesized.
