- Scope :: Android test/evidence only. No Core/server/plugin implementation.

** Source analysis
Canonical =AndroidUriLauncher= already constructs a fresh local =ACTION_VIEW= intent from an =OpenUriPolicy=-normalized URI, adds =CATEGORY_BROWSABLE= and =FLAG_ACTIVITY_NEW_TASK=, and does not deserialize caller-controlled Intent objects.

** Adversarial boundary
The proof fails if production URI launching gains any direct arbitrary-intent escape surface such as =Intent.parseUri=, explicit component/class targeting, package forcing, or caller-controlled extras. These mechanisms would bypass the reviewed URI-only capability contract.

** Acceptance
- URI launcher remains fixed to =ACTION_VIEW= + normalized =Uri=;
- =CATEGORY_BROWSABLE= and new-task launch semantics remain explicit;
- arbitrary Intent deserialization/component/package/extra injection remains absent;
- fresh exact-head CI is required before promotion/merge.
