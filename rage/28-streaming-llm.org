* Research
** Current production behavior (at =dc51f12=)
- =zara/agent/graph.py:187= :: the agent node calls =llm_with_tools.ainvoke(msgs)=, which buffers the complete =AIMessage=. The latency trace records =llm_first_token= with =buffered_proxy=True= (graph.py:199-205) - an explicit proxy marker awaiting this issue. First visible text is impossible today; first audio waits for the full model response.
- Two LLM client stacks are in the voice path:
  1. Agent/conversation path :: LangChain chat models bound with tools inside the LangGraph agent node (the conversational core behind =run_conversation_loop=, used by wake, desktop and daemon surfaces).
  2. Direct query path :: =zara/llm.py= =LLMClient= (typed =LLMResult=, aiohttp, session reuse) used by =zara/wake.py= =query_llm_async= for non-agent queries.
- Cancellation infrastructure exists (ZARA-026): turn coordinator with bounded mailboxes, true barge-in, stale-work cancellation. The streaming path must plug into existing turn cancellation, not invent a second one.
- The pending user branch =wip/latency-trace-ctor= (preserved 2026-08-29, green) moves =latency_trace= from =AgentState= into node/graph constructor args. #28 rewrites the same node; realization must coordinate with that branch (rebase onto it or absorb its constructor-injection approach) rather than silently discarding user work.
- =zara/llm.py= has no streaming endpoint support today; LangChain chat models expose native =astream()= yielding =AIMessageChunk= increments, including tool-call argument fragments.
- TTS boundary today receives complete text (ZARA-026 ack aside); #29 (phrase-sized TTS player) is the downstream consumer of this issue's =sentence_ready= events and must not be blocked by this issue.
** Library/authority findings
- LangChain =astream()= is the provider-neutral mechanism for Anthropic/OpenAI/Ollama chat models; AIMessageChunk supports =+= accumulation. Tool calls surface as chunk fragments; user-facing speech must hold until a complete tool call plus result exists (issue requirement).
- The one provider-neutral interface required by the issue is therefore a typed event protocol emitted by the agent node (LangChain-backed) and, secondarily, by =LLMClient=; both producers map their provider stream into the same event shapes. Rejected: making the LangGraph node depend on =zara/llm.py= internals (would fork the tool-binding path); adding a custom provider SDK layer (violates repo LangChain policy and duplicates ZARA-016-tested clients).
** Failure modes to design against
- Malformed/partial provider chunks; chunk errors mid-stream (must emit =failed=, close stream, keep history exact).
- Cancellation mid-delta (must stop future deltas, close stream/session, emit =cancelled=; no orphan TTS chunks).
- Tool-call fragments accidentally spoken (must never emit tool-call syntax as text deltas).
- Abbreviations/URLs/code breaking naive punctuation chunking; unbounded clauses with no punctuation (max-length + max-wait thresholds force emission).
- Unicode grapheme splitting at chunk boundaries.
** Open questions for design
1. Event delivery shape: async generator of typed events vs callback/queue. Candidate: bounded =asyncio.Queue= aligned with the actor-style turn coordinator (ZARA-023), preserving backpressure and cancellation semantics.
2. Exact =sentence_ready= chunk policy: punctuation set, abbreviation guard list, max chars, max wait ms; how code/URLs suppress mid-URL breaks.
3. How delivered-chunk tracking integrates with conversation history (exact final text persisted regardless of what was spoken).
4. Whether =LLMClient= gains =stream_events_async= in this issue or the agent node alone satisfies the release chain (issue says implement for configured providers where supported; wake direct path is part of configured surface).

** Implementation decisions
- =stream_publisher= (typed =LLMStreamEvent= callback) is constructor-injected
  into =create_agent_node= / =create_tools_node= and threaded through
  =create_agent_graph=, =run_conversation_loop=, and
  =AgentManager.process_async=. Runtime/UI streaming uses the canonical bus:
  the node publishes =AssistantDelta= via =runtime_bridge.model_streaming= and
  populates =AssistantComplete.text= with the exact final text; no new
  runtime event types, no daemon codec change (codec already maps
  =assistant.delta= / =assistant.completed=).
- Streaming gate: =stream_publisher is not None and callable(astream)=. LLM
  fakes/implementations without =astream= keep the exact buffered path with
  =buffered_proxy=True= (honest fallback, A6); direct node constructions in
  existing tests are untouched.
- Provider stream consumption: =astream= is pumped by a dedicated task into an
  =asyncio.Queue=; the consumer awaits =queue.get()= with
  =chunker.wait_budget()= as timeout so the chunker's max-wait flush is
  genuinely time-driven. (A =wait_for= around the generator's =__anext__=
  would cancel the stream on every timeout - recorded as a design-relevant
  implementation constraint.)
- Tool-call handling: chunks carrying =tool_call_chunks= never emit text;
  first fragment per index emits =ToolCallStarted(name, id)=; the aggregated
  =AIMessageChunk= is rebuilt as an =AIMessage= (content, additional_kwargs,
  tool_calls, id, response_metadata) so LangGraph approval/tool-loop and
  history semantics are unchanged. =ToolResult(name, id)= is published by the
  tools node for executed, rejected, and unavailable tool results.
- =zara.llm.LLMClient= gains =serialize_stream_request= +
  =stream_events_async= (single attempt, no retry duplication): OpenAI/
  OpenRouter SSE =data:= frames, Anthropic SSE deltas (=content_block_delta=,
  =message_stop=, =error=), Ollama NDJSON. Terminals: Completed (non-empty),
  Cancelled (re-raised), Failed (http/rate_limit/malformed_response/
  provider_error/empty_response/timeout/connection). Session lifecycle
  (ZARA-016) unchanged; no wall-clock cap on streams, sock_read covers stalls.
- Chunker conservation invariant (concatenation of emissions + flush equals
  fed text exactly) is property-tested; guarded terminators hold back at
  buffer end until the next feed disambiguates.
- Deviation from design text: =sentence_ready= is NOT mirrored onto the
  runtime event bus (design point 4 ambiguity). Rationale: the daemon codec
  raises on unmapped event types and wire semantics are frozen for this
  issue; =sentence_ready= stays in the typed =stream_publisher= contract that
  #29 consumes. No contradiction with acceptance criteria.
