* Research
- #170 selected JeroMQ 0.6.x for Android ZMTP/3.0 + CURVE and delegated key storage to #173.
- JeroMQ 0.6.0 =ZMQ.Socket.setCurveSecretKey(byte[])= requires the client long-term CURVE secret as raw 32-byte or 40-character Z85 material; =setCurvePublicKey= and =setCurveServerKey= use the same representation family.
- Android Keystore keys are intended to remain inside the keystore boundary, while Android recommends KeyStore for long-term cryptographic key protection and AES/GCM for authenticated encryption.
- =Context.getNoBackupFilesDir()= is explicitly excluded from automatic backup, preventing device-bound wrapped credentials from being restored onto a device that cannot unwrap them.
- Production re-audit found an independent server regression: stock =zara-server= still rejected TCP and did not consume the completed #130 =SecureZaraZmqGateway=. That recovery is isolated in #329 / PR #331 and is not hidden inside the Android branch.

* Design
** Boundary
Implement authentication state and credential protection now; leave full reconnect/session/action protocol integration for the next #173 iteration after #159 stabilizes. Server production-listener recovery belongs to #329.

** Selected architecture
1. =CurveCredential= is the transport-facing value: client public key + client secret key bytes. It is never persisted in plaintext.
2. =CredentialCipher= abstracts authenticated wrapping so JVM tests can use a deterministic fake while production uses AndroidKeyStore AES-256-GCM.
3. =WrappedCredentialStore= persists only a versioned envelope containing public key, IV and ciphertext under =noBackupFilesDir= using fsync + atomic replace semantics.
4. =AndroidKeystoreCredentialCipher= owns a non-exportable AES wrapping key under a fixed application alias. It does not require per-use biometric authentication because background assistant reconnect must remain possible.
5. =ServerPin= is a separately persisted public value containing the expected 32-byte CURVE server public key. Missing pins fail closed. Re-pinning the same key is idempotent; silently replacing it with another key is forbidden.
6. =CurveAuthConfigurator= is the only component allowed to place client public/secret/server keys onto a JeroMQ socket. It validates/copies material and clears the temporary secret copy after socket configuration.
7. =EnrollmentRepository= exposes typed states =Unenrolled=, =AwaitingServerPin=, =Ready= and =Corrupt=. Corrupt/undecryptable credentials never silently rotate identity.
8. =JeroMqCurveKeyCodec= exposes only public-key Z85 enrollment exchange. =JeroMqCurveDealerFactory= constructs a bounded-handshake DEALER and applies CURVE before connection use.

** Invariants
- No plaintext CURVE secret in persisted app files, logs, diagnostics or resources.
- The actual CURVE secret is wrapped by a distinct non-exportable AndroidKeyStore AES-256-GCM key; it is not falsely modeled as an exportable AndroidKeyStore private key.
- Server pin is mandatory before CURVE socket configuration and cannot silently change.
- Key, IV and ciphertext sizes are bounded and validated before decrypt/configure.
- Credential and pin replacement writes are atomic.
- Lost/deleted Keystore wrapping key produces explicit corrupt/re-enrollment state, never implicit new identity.
- Loaded secret copies are explicitly cleared where the JVM/JeroMQ boundary permits.
- Android manifest includes =INTERNET= because JeroMQ TCP is the selected remote transport.
- No #159 capability/action message types are introduced on this branch.

** TDD map
1. Wrapped credential round trip through a fake authenticated cipher; persisted bytes must not contain the raw secret.
2. Corrupt envelope / wrong cipher key -> typed =Corrupt= state.
3. Missing credential -> explicit =Unenrolled=.
4. CURVE client/server keys require exactly 32 bytes; Z85 exchange round-trips exactly 40 characters.
5. Auth configurator sets pinned server/client public/client secret and fails closed if the socket rejects any option.
6. Enrollment is explicit: identity creation -> awaiting pin -> ready; configuration before pin fails.
7. Corrupt stored identity cannot be replaced silently.
8. Server pin is idempotent for the same key but a different pin is rejected while preserving the original.
9. Android Keystore implementation compiles under minSdk 29 using AES/GCM + AndroidKeyStore.
10. Android debug APK/secret inspection gate remains green with the new authentication code and JeroMQ dependency.
