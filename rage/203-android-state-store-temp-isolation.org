#+title: RAGE #203 — isolate Android state-store temp files across processes
#+status: ACTIVE

* Consumption
- Issue :: #203
- Immutable/current canonical start :: 0a370079f2bf293b320ea72865239e6ee4c08a73
- Scope :: Android durable client-state persistence only. No Core/protocol/plugin changes.

* Failure analysis
- The app and VoiceInteraction service can run in separate Android processes while sharing =noBackupFilesDir=.
- =ClientStateStore.save= used the single fixed sibling =.client-state.bin.tmp= for every writer.
- Concurrent writers or a killed process leaving that path unusable could make a later save fail before the existing atomic replace step.

* Design
- Create a unique sibling temp file for every save with =Files.createTempFile=.
- Keep fsync-before-replace and atomic-move-with-safe-fallback semantics unchanged.
- Delete only the temp file created by this save.
- This removes fixed-temp collisions; it does not claim multi-writer semantic merge/last-writer conflict resolution, which remains a separate persistence concern if needed.

- GREEN: per-save unique sibling temps, same bounded binary format and fail-closed load behavior.
